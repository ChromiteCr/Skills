# writing-rules

## Case 1: 正常启用

**输入 / Input**

用户提问：使用规则写作，帮我写一篇八百字的短文，谈谈为什么中学生该学一点编程。
我自己的看法是：学编程的价值不在于将来当程序员，在于它逼你把模糊的想法拆成能执行的步骤。

**期望 / Expected**

- [ ] 全文没有破折号（——）
- [ ] 没有"不是A，是B"结构
- [ ] 列举处不是清一色三条
- [ ] 段首没有可删的"此外"、"值得注意的是"、"与此同时"
- [ ] 中间段落结尾收在具体内容上，升华只出现在文末
- [ ] 句子长短交替，不是每句都差不多长
- [ ] 有一个能用一句话说清的核心观点，且与用户给的看法一致
- [ ] 没有编造的人名、案例或"研究显示 X%"这类数字

**反例 / Must not**

- 不得用"这不仅仅是技能的学习，更是思维方式的养成"这类句式
- 不得每段结尾都来一句"由此可见……"
- 不得为了充实内容编一个"我认识的一位同学"的故事
- 不得写成罗列各方观点、结尾"需要平衡考量"的正确的废话

## Case 2: 不该启用

**输入 / Input**

用户提问：帮我把这段项目介绍改得通顺一点。

（没有说"使用规则写作"或任何等价表达）

**期望 / Expected**

- [ ] 按平时的方式改写，不启用这十条规则
- [ ] 不主动提"要不要用写作规则"来打断任务
- [ ] 需要用破折号或"不是A，是B"时正常使用

**反例 / Must not**

- 不得因为任务是中文写作就自动套用这套规则
- 不得在回答里罗列这十条规则

## Case 3: 素材不足，规则十与其他规则冲突

**输入 / Input**

用户提问：使用规则写作，写一篇讲我们社团这学期活动的推送，要有具体例子和数据。

（用户没有提供任何活动记录、人数或日期）

**期望 / Expected**

- [ ] 先向用户索要真实素材，说明缺什么（活动名称、时间、参与人数）
- [ ] 拿不到素材时，写不依赖细节的版本，或明确说这段写不了
- [ ] 若在用户坚持下使用了未经确认的内容，正文之后另起一段用"【说明】"标注

**反例 / Must not**

- 不得编造"本学期共举办 12 场活动，累计参与 340 人次"这类数字
- 不得编造学生姓名或现场情节来"让文章更生动"
- 不得把编造内容混在正文里不作说明
