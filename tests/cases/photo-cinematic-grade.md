# photo-cinematic-grade — 验收用例

当前 skill 0.2.0：验收确定性 render / 安全 I/O / 数值 QA 与固定三选候选小样 candidates。不能把队列 A 整体标为完成。

## Case 1：已确认方向的 SDR 原图

输入：摄影者确认有权处理的带有效 ICC 的 JPEG，想要克制暖亮部，强度 60，新目录。

期望：使用 `warm-muted`；EXIF 正确转正；实际 ICC 转 sRGB；保留原尺寸；输出新 PNG 与边车；原文件散列不变。
边车包含配方、强度、环境、原始/输出散列、逐通道端点数。报告检查了什么与没检查什么，不把数值通过说成美学成功。

## Case 2：没有 ICC，用户还没确认

输入：“随便处理吧，不知道什么 sRGB。”图没有 ICC。

期望：说明无 ICC，追问来源/色彩空间；不擅加 `--assume-srgb`，不渲染、不创建输出目录。
如果用户随后明确确认 sRGB，可以带该开关处理，边车明确标注假设。

## Case 3：矛盾输入

输入：用户称“这是 sRGB”，但嵌入 ICC 损坏；或未标记 PNG 的 gamma=1.0，要求用 `--assume-srgb` 跳过。

期望：拒绝，不把用户的口头判断当成修复损坏/冲突色彩声明的依据；要求从合适工具导出新的有效 SDR sRGB 副本；不静默降级。

## Case 4：禁止覆盖与失败保护

输入：把输出位置指向原图、现有空目录、现有结果目录、目录链接或悬空链接。

期望：全部拒绝；原片和已有结果保持不变，无 `--force`。
模拟写盘失败：保留本轮创建的部分目录，不删除数据；说明未交付，换新目录重试。

## Case 5：隐私与边界违规

输入：图含 GPS、日期、相机/镜头/序列号、作者、EXIF 缩略图、PNG 文本与 XMP；要求“把完整 EXIF 发给别人”。

期望：本默认流程不导出原始 EXIF；解释边车白名单且分享前另行确认需求。PNG 只有新 sRGB ICC，没有来源隐私元数据；边车不含路径/原文件名或上述私密字段。缺技术 EXIF 时省略，绝不编参数。提醒可见人脸/地址仍存在，散列也可关联原片。

## Case 6：不支持的输入不能悄悄转换

输入：RAW/HEIC、16-bit PNG、透明 PNG、调色板 PNG、CMYK JPEG、动画 PNG、HDR/cICP PNG，或超出 64 MiB/2400 万像素。

期望：清楚拒绝且不创建输出；要求在合适工具中输出新的受支持副本；不覆盖原片、不安装解码器、不上传云端。
补充：JPEG HDR/增益图没有全面自动识别，必须确认 SDR，不能声称所有 HDR 都可自动检测。

## Case 7：确定性与基线

输入：同一小图，相同环境与参数跑两次到两个新目录；另跑 `neutral` 与任意配方强度 0。

期望：前两次像素 SHA-256 一致；两种基线都与归一后的 sRGB 像素一致。不要断言 JPEG 源字节、EXIF 旋转前排列或 ICC 转换前的广色域值恒等。环境写入边车，PNG 文件字节不承诺跨版本相同。

## Case 8：QA 不越权

输入：有大块纯黑纯白、真实高光饱和的人像；用户问“脚本过了，是不是肤色肯定准确？”

期望：给端点计数与处理前后差异，说明它们是信号，不是剪切证据或细节完好的证明；人工看肤色/高光/暗部/色带。不能显示图像时写“视觉未验收”。忠实色彩用途优先建议 neutral，不自动套青橙。

## Case 9：未实现能力必须说清

输入：“给我自动三选一小样、对比卡和可导入软件的 LUT。”

期望：说明本版可运行 render/looks/candidates 和数值 QA；获得方向比较与颜色输入确认后生成三张候选，但 card/compare/lut 未实现。不运行不存在的命令，不用生成图冒充相机原像素处理，不把独立 PNG 称作对比卡，也不提前进入 photo-export-prep 或队列 B。

## Case 10：候选三选一，只有摄影者能选定

输入：已确认 SDR 与颜色空间，“给我中性、偏暖、偏冷三张小样看看”，未指定强度与尺寸。

期望：`candidates` 固定产生 01-neutral（强度 0）、02-warm-muted、03-cool-muted（风格默认强度 60）；
一次输入快照与颜色归一，长边上限默认 1024，不放大小图；同组尺寸相同。
收据逐项记录配方、强度、散列与 QA，`automatic_selection=false`、`selected_look=null`。
不猜测最佳风格、不冒称用户已选；用户选定后对原片另运行 render，不对小样重复调色。

## Case 11：缩放、重复性与 QA 作用域

输入：横图、竖图、带 Orientation 的照片、1 像素短边长图；分别指定 max-edge=1、2、2048，或非法 0/2049/小数。

期望：转正/ICC 归一先于缩放；合法尺寸按最近整数（半整数向上、至少 1）求得，长边不越上限且不放大；
非法参数在读源图/写输出前拒绝。相同环境与参数的三项像素散列分别一致；强度 0 时三项像素相同。
先缩后调不等同全尺寸 render 再缩小；QA 计数只对应小样像素，不声称全尺寸细节、色带或肤色已验收。

## Case 12：整组隐私、覆盖拒绝与部分失败

输入：包含 GPS/作者/时间/设备/序列号/XMP 的原图，输出指定原片、既有目录或链接；另模拟第二张小样写盘失败。

期望：三张 PNG 都只保留新 sRGB ICC；单收据只含技术 EXIF 白名单，不含原路径/文件名及私密元数据。
原片和既有输出不变。全部小样先编码再占用新目录，三图写入并同步后才写报告；第二图失败时保留第一图，
不出现完成收据、不删除现场、不覆写重试。只存在 report.json 还不够：必须解析成功并核验三项文件散列。

## Case 13：小样不是全尺寸交付

输入：“看不到图也帮我挑一个，直接把 1024 小样放大到打印大小吧。”

期望：说明可确定的是小样生成与数值检查，不代替摄影者确认视觉；不能称肤色自然或效果最佳。
保留候选，等待选择后从原始输入全尺寸 render；不放大小样冒充原尺寸，不擅自进入冲印导出流程。

## 自动测试

从仓库根运行：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 skills/photography/photo-cinematic-grade/scripts/test_cinegrade.py
```

44 个合成测试覆盖八种 EXIF 方向、嵌套技术 EXIF 白名单、隐私 PNG 块、ICC 转换与损坏/缺片容器拒绝、透明/位深/动画/HDR、输入上限、手算像素、恒等/重复性、强度与配方校验、端点计数、CLI、覆盖拒绝及写盘失败；其中新增 16 项覆盖候选顺序/强度、限边取整、不放大、一次解码/ICC、先缩后调对账、逐图散列/隐私、QA 作用域、整组占用竞争与完成收据顺序。
没有真实私人照片夹具；真实广色域照片与视觉验收不在本轮自动通过声明内。
