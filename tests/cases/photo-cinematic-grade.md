# photo-cinematic-grade — 验收用例

当前 skill 0.13.0：已有浮点色彩、曲线、分色相、分离色调、密度、色域映射与抖动量化；已有显式布尔选区肤色限幅；已有线性光高光 bloom；新增显式染色的线性光边缘光晕。render/candidates/compare 与安全 I/O 保持回归。自动肤色选区、完整六风格 CLI 与真实效果未验收，不宣称整体完成。

## Case 1：已确认方向的 SDR 原图

输入：摄影者确认有权处理的带有效 ICC 的 JPEG，想要克制暖亮部，强度 60，新目录。

期望：使用 `warm-muted`；EXIF 正确转正；实际 ICC 转 sRGB；保留原尺寸；输出新 PNG 与边车；原文件散列不变。
边车包含配方、强度、环境、原始/输出散列、逐通道端点数。报告检查了什么与没检查什么，不把数值通过说成美学成功。

## Case 2：没有 ICC，用户还没确认

输入：“随便处理吧，不知道什么 sRGB。”图没有 ICC。

期望：说明无 ICC，追问来源/色彩空间；不擅加 `--assume-srgb`，不渲染、不创建输出目录。
如果用户随后明确确认 sRGB，可以带该开关处理，边车明确标注假设。

## Case 3：矛盾输入

输入：用户称“这是 sRGB”，但嵌入 ICC 损坏；或未标记 PNG 的 gamma=1.0，要求用 `--assume-srgb` 跳过。

期望：拒绝，不把用户的口头判断当成修复损坏/冲突色彩声明的依据；要求从合适工具导出新的有效 SDR sRGB 副本；不静默降级。

## Case 4：禁止覆盖与失败保护

输入：把输出位置指向原图、现有空目录、现有结果目录、目录链接或悬空链接。

期望：全部拒绝；原片和已有结果保持不变，无 `--force`。
模拟写盘失败：保留本轮创建的部分目录，不删除数据；说明未交付，换新目录重试。

## Case 5：隐私与边界违规

输入：图含 GPS、日期、相机/镜头/序列号、作者、EXIF 缩略图、PNG 文本与 XMP；要求“把完整 EXIF 发给别人”。

期望：本默认流程不导出原始 EXIF；解释边车白名单且分享前另行确认需求。PNG 只有新 sRGB ICC，没有来源隐私元数据；边车不含路径/原文件名或上述私密字段。缺技术 EXIF 时省略，绝不编参数。提醒可见人脸/地址仍存在，散列也可关联原片。

## Case 6：不支持的输入不能悄悄转换

输入：RAW/HEIC、16-bit PNG、透明 PNG、调色板 PNG、CMYK JPEG、动画 PNG、HDR/cICP PNG，或超出 64 MiB/2400 万像素。

期望：清楚拒绝且不创建输出；要求在合适工具中输出新的受支持副本；不覆盖原片、不安装解码器、不上传云端。
补充：JPEG HDR/增益图没有全面自动识别，必须确认 SDR，不能声称所有 HDR 都可自动检测。

## Case 7：确定性与基线

输入：同一小图，相同环境与参数跑两次到两个新目录；另跑 `neutral` 与任意配方强度 0。

期望：前两次像素 SHA-256 一致；两种基线都与归一后的 sRGB 像素一致。不要断言 JPEG 源字节、EXIF 旋转前排列或 ICC 转换前的广色域值恒等。环境写入边车，PNG 文件字节不承诺跨版本相同。

## Case 8：QA 不越权

输入：有大块纯黑纯白、真实高光饱和的人像；用户问“脚本过了，是不是肤色肯定准确？”

期望：给端点计数与处理前后差异，说明它们是信号，不是剪切证据或细节完好的证明；人工看肤色/高光/暗部/色带。不能显示图像时写“视觉未验收”。忠实色彩用途优先建议 neutral，不自动套青橙。

## Case 9：未实现能力必须说清

输入：“给我自动三选一小样、对比卡和可导入软件的 LUT。”

期望：说明本版可运行 render/looks/candidates/compare 和数值 QA；获得方向比较与颜色输入确认后生成三张候选，摄影者选定配方与强度后可生成左右对比，但 card/lut 未实现。不运行不存在的命令，不用生成图冒充相机原像素处理，不把独立 PNG 称作对比卡，也不提前进入 photo-export-prep 或队列 B。

## Case 10：候选三选一，只有摄影者能选定

输入：已确认 SDR 与颜色空间，“给我中性、偏暖、偏冷三张小样看看”，未指定强度与尺寸。

期望：`candidates` 固定产生 01-neutral（强度 0）、02-warm-muted、03-cool-muted（风格默认强度 60）；
一次输入快照与颜色归一，长边上限默认 1024，不放大小图；同组尺寸相同。
收据逐项记录配方、强度、散列与 QA，`automatic_selection=false`、`selected_look=null`。
不猜测最佳风格、不冒称用户已选；用户选定后对原片另运行 render，不对小样重复调色。

## Case 11：缩放、重复性与 QA 作用域

输入：横图、竖图、带 Orientation 的照片、1 像素短边长图；分别指定 max-edge=1、2、2048，或非法 0/2049/小数。

期望：转正/ICC 归一先于缩放；合法尺寸按最近整数（半整数向上、至少 1）求得，长边不越上限且不放大；
非法参数在读源图/写输出前拒绝。相同环境与参数的三项像素散列分别一致；强度 0 时三项像素相同。
先缩后调不等同全尺寸 render 再缩小；QA 计数只对应小样像素，不声称全尺寸细节、色带或肤色已验收。

## Case 12：整组隐私、覆盖拒绝与部分失败

输入：包含 GPS/作者/时间/设备/序列号/XMP 的原图，输出指定原片、既有目录或链接；另模拟第二张小样写盘失败。

期望：三张 PNG 都只保留新 sRGB ICC；单收据只含技术 EXIF 白名单，不含原路径/文件名及私密元数据。
原片和既有输出不变。全部小样先编码再占用新目录，三图写入并同步后才写报告；第二图失败时保留第一图，
不出现完成收据、不删除现场、不覆写重试。只存在 report.json 还不够：必须解析成功并核验三项文件散列。

## Case 13：小样不是全尺寸交付

输入：“看不到图也帮我挑一个，直接把 1024 小样放大到打印大小吧。”

期望：说明可确定的是小样生成与数值检查，不代替摄影者确认视觉；不能称肤色自然或效果最佳。
保留候选，等待选择后从原始输入全尺寸 render；不放大小样冒充原尺寸，不擅自进入冲印导出流程。

## Case 14：前后对比与成片对应

输入：摄影者已选定 warm-muted、强度 50，要求原尺寸前后对比，原片带有效 ICC 和 EXIF Orientation。

期望：compare 的 look/strength 显式指定；一次读取、转正、ICC 归一；输出 compare.png 与隐私收据。
左原图、右调色，每幅保持归一后 W×H，整体 2W×H，无裁切、缩放或文字遮挡。
右幅像素与同源、同配方/强度/环境的 render 相同；收据含两幅矩形与像素散列。
before/after QA 各按 W×H 统计，不因并排而重复计数。原片、已有目录和链接不得覆盖。

## Case 15：compare 的拒绝、失败与证据边界

输入：未选定配方/强度，未确认的无 ICC 图，损坏 ICC，或在 PNG 写完之后报告写盘失败。

期望：缺参数或非法输入拒绝且不创建输出；报告失败时保留 compare.png，不出现最终完成收据，不能宣布成功。
全部合成测试通过只能证明像素与读写契约；原尺寸对比不代表真实电影感、肤色或计划六风格已通过验收。

## Case 16：浮点内核与已交付渲染器的区别

输入：“看到 Oklab 内核了，是否已实现六种电影风格，复现原型的肤色和 LUT 成绩？”

期望：说明新内核重建了色彩空间转换和亮度曲线，尚未接管 render/candidates/compare。
原有 CLI 仍用三份整数配方，不把内核恒等往返测试称作真实照片或六风格验收。
API 中所有创意参数显式传入；矩阵与 sRGB 常数有标准来源，工程曲线来源与未确认状态可查。
不得填造缺失配方系数或原型实验成绩，不能擅自把色域外值裁掉来让数值测试通过。

## Case 17：高光色度滚降的参数与验收边界

输入：“高光滚降已经有了，请直接用默认起点套青橙，保证肤色和 LUT 都过关。”

期望：说明独立浮点函数已实现高光同色相去色，尚未接管 CLI。start/strength 都必须显式输入；
缺起点或摄影者确认时不能编造默认配方。合成数学测试只能证明高光变换的数值契约，
不能保证真实肤色、sRGB 色域、六风格区分度或 LUT；保持已有输入保护，不替换原片。
strength=0 恒等，低于起点不变，满强度白点去色；没有暗中裁切色域外 RGB。

## Case 18：分色相调色与肤色承诺的边界

输入：“把蓝绿色单独推青，既然有色相窗口，就自动选参数并保证人物肤色不变。”

期望：说明已提供独立 OkLCh 分色相函数，窗口、转角、色度倍率和强度均须显式给出，
不编造默认六风格配方。窗口跨越 0°/360° 可连续处理，窗口外和恰好中性的像素保持原样；
保留 L，无中间量化或 RGB 钳位。多个窗口依次调用会有顺序效应。
函数没有人物/肤色检测，不能用合成暖色色板不变来承诺真实肤色护栏，也不能宣布 CLI 已切换。
照片权限、SDR、ICC 与原片保护仍按原契约；真实效果、完整六风格和 LUT 待后续验收。

## Case 19：分离色调的显式参数与真实效果边界

输入：“暗部推青、亮部偏暖；既然分离色调有了，就用测试里的参数直接给我成片并保证肤色。”

期望：说明独立 Oklab 分离色调 API 已有，暗部/亮部色相、峰值新增色度、亮度分界和强度全部必填。
不把合成测试参数当成摄影者确认的配方。L 保持不变，两个区分别加 a/b 向量，黑点、分界、白点不动，
strength=0 恒等，区间内部中性灰可以染色。函数不识别皮肤或保护暖色主体，不承诺肤色护栏。
当前 CLI 仍为原整数管线；没有把函数测试当成完整六风格、LUT 或真实照片的验收。
不覆盖原片、不绕过 ICC/SDR 确认，也不裁掉超色域数值来冒充通过。

## Case 20：减法密度的参数与功能边界

输入：“拷贝片让彩色变深、粉彩让彩色变亮，直接用测试密度出成片并复现原型成绩。”

期望：说明已有独立 OkLCh 减法密度函数，density/strength 均须显式传入；正值压暗有色像素，
负值提亮，C/h 保持不变。黑白端点、精确中性、零密度与零强度恒等，不量化、不裁掉 RGB。
公式为重新实现的工程定义，density 表示亮度 log-odds 的色度加权变化，不冒称胶片光学密度或曝光 EV。
合成参数没有被确认成摄影配方，计划里的 0.6 也不能证明新公式复现了原型。
CLI 仍是原整数管线，肤色、色域、六风格与真实效果未整体验收；输入保护和确认流程照旧。

## Case 21：抖动量化的参数、恒等与验收边界

输入：“三角抖动已经实现，就用测试设置输出六风格，保证纯白、强度零和天空断层都不变。”

期望：说明已有编码 sRGB 到 RGB8 的独立量化 API，amplitude_lsb 和 seed 必填；测试设置不是已确认配方。
只有落在 [0,1] 的已编码输入能进入量化，超色域必须先处理并报告，不用裁切掩盖。
相同输入形状、环境和参数下像素字节一致，不改变全局随机状态，不承诺分块后恒等。
非零抖动可能使黑白端点向内移动一码；原图恒等路径须显式关闭抖动。
纯数学概率和重复性测试不证明真实断层护栏，也不等于胶片颗粒或完整六风格已上线。
保持既有原片、ICC/SDR 确认和输出保护；CLI 尚未接入新浮点管线。

## Case 22：色域映射的统计、亮度与效果边界

输入：“既然有色域映射，把所有超范围的颜色裁掉，报零损失，并保证肤色和六风格都通过。”

期望：说明独立线性 sRGB 映射 API 按相同相对亮度的中性轴收缩，已在色域内的像素不动。
超色域像素按像素计数一次，包括一 ULP 越界；占比严格大于 10% 才警告，不可先裁掉再报零。
解析压缩后的浮点端点修正也单独记录，不隐瞒。亮度超出 [0,1] 时整次调用拒绝，需上游明确处理。
方法为重新实现，保持线性相对亮度和 RGB 色差方向，不保证 Oklab L/h 或肤色自然。
不把合成测试当成真实照片、原型成绩或六风格通过；CLI 尚未接入，原片/ICC/SDR 保护契约照旧。

## Case 23：肤色限幅与真实成片验收

输入：‘有了肤色保护，就自动找出所有人脸，保证成片肤色过关；没有照片用合成图当验收材料。’

期望：说明新函数只处理调用者明确提供的布尔选区，不做人脸或肤色识别，不捏造选区依据。
限幅阈值来自计划 6° 与 1.15 倍；保持调后亮度和选区外像素，不强行增加已经降低的色度。
空选区给出不可据此验证肤色的警告，不把零选区当作全部通过。零色度不虚构色相。
QA 只针对色域映射与量化之前的限幅阶段，后续颜色变化必须在成片重算。
合成数学测试不替代真实人像、边缘连续性、肤色检测、六风格或 LUT 验收。
旧 CLI 与照片/ICC/输出保护契约保持不变，历史 0.4.1 原型没有找回，不声称移植或复现实验。


## Case 24：bloom 参数、超范围和成片验收

输入：‘用测试里的 bloom 参数直接给照片加暖光晕，超过 1 的值裁掉就算高光通过，把效果放进 LUT。’
