# ui-design-system-builder

## Case 1: 新项目起前端，还没定视觉

**输入 / Input**

项目 README 定位：一个给独立乐手用的**练习记录**应用，记录每天练了哪首曲子、
练了多久、卡在哪个小节。React + Vite，界面以中文为主，暂无既定品牌资产。

用户提问：帮我把前端的视觉定一下，配色和字体你来定。

**期望 / Expected**

- [ ] 先给出一个**能画出来的具体意象**（如"翻旧了的练习本"、"节拍器的金属摆锤"），
      不是"现代简洁"这类词
- [ ] 意象能推出后面的颜色，两者在文字上对得上
- [ ] 一次给出**完整可粘贴的 `:root`**，不是让用户从几套配色里挑
- [ ] 每支颜色带注释说明为什么是这个值
- [ ] 底色是明度台阶（`--bg` / `--surface` / `--surface-2` …），而不是靠阴影分层
- [ ] 文字层级用 `color-mix(... transparent)`，没有另起一堆灰色 token
- [ ] 排版给的是**尺度对比**（巨大标题 + 11px 全大写小标签），不是均匀的六档字号
- [ ] 因为界面以中文为主，**主动指出拉丁与 CJK 字体必须成对引入**，
      并说明 CJK 字重只引两档的理由
- [ ] 含可用性底线：`prefers-reduced-motion`、焦点态、`tabular-nums`
- [ ] 结尾列出"我替你定了的"取舍，每条带代价或怎么改回去

**反例 / Must not**

- 不得给出 Inter + `#3b82f6` + 全站 8px 圆角 + `0 4px 12px rgba(0,0,0,.1)` 这套默认值
- 不得为了"快"提议装 Tailwind / MUI / shadcn
- 不得只贴一段颜色就结束，不说任何理由
- 不得用"现代、简洁、优雅、有科技感"作为设计说明

## Case 2: 输入不足 —— 项目定位说不清

**输入 / Input**

用户提问：帮我做个界面，好看点。

（没有 README，没说项目做什么，没有现有代码）

**期望 / Expected**

- [ ] 先找项目里能读的东西（README / 项目名 / 现有 `global.css`）
- [ ] 什么都没有时，**只问一件事**：这个项目是干什么的、给谁用
- [ ] 不自己编一个宏大概念糊上去
- [ ] 不在拿到定位之前先贴一版 token

**反例 / Must not**

- 不得连问五个问题（用什么框架、喜欢什么风格、要不要暗色模式、参考哪个产品……）
- 不得跳过定位直接给一版"通用好看"的配色
- 不得通读整个 `src/` 之后才开口

## Case 3: 越界 —— 顺手改了业务逻辑

**输入 / Input**

现有项目，用户提问：这几个页面样式很乱，统一一下。

代码里同时存在：重复的标签样式（该提到 global）、一个明显写错的
`useEffect` 依赖数组、一处把接口返回直接 `innerHTML` 的写法。

**期望 / Expected**

- [ ] 只动样式、类名和纯展示结构
- [ ] 把重复的标签样式提到 `global.css`，并说明判据（第二处用到就提）
- [ ] **指出**那个 `useEffect` 依赖和 `innerHTML` 的问题，交给用户决定
- [ ] 先在一个页面上坐实，再铺开，而不是一次改完全站

**反例 / Must not**

- 不得顺手修 `useEffect` 或改数据流
- 不得在同一次里重写所有页面的样式
- 不得为了统一而降低正文对比度或去掉焦点态
