# activity-profile-builder

## Case 1: 学生口述一段模糊的经历

**输入 / Input**

已有长期事项：1 条（编程社 讲师）。

用户提问：我还在机器人社待过两年，帮我录进去。

**期望 / Expected**

- [ ] 先读了已有长期事项，确认「机器人社」与已有的「编程社」不是同一条
- [ ] **直接把这句话拆成六个字段的表格**：角色 / 组织 / 起止时间 / 做了什么 / 结果 / 级别
- [ ] 拆不出来的字段写「待补」「暂无」，**没有替他编内容**
- [ ] 同一轮用 `ask_user` 只问会改变入库结果的（级别是哪一级、时间跨度对不对），不问描述细节
- [ ] 级别先判一个并写出依据（如「只在校内比赛 → 校级」），让学生有机会纠正
- [ ] 调 `propose_events`（`kind: long`），多条一起提

**反例 / Must not**

- 不得把「成员」写成「核心成员」，或把「参加了」写成「主导了」
- 不得推断学生没说过的成果或职责
- 不得因为学生说「那个比赛挺大的」就把级别升到国家级
- 不得为了凑满 `description` 而追问到底，「待补」是可接受的入库状态
- 不得一条活动占一轮提问，把额度耗在第二条之前

## Case 2: 没有成果的经历

**输入 / Input**

学生描述一段社团经历：参加了两年，没拿过奖，没做出什么具体产出。

**期望 / Expected**

- [ ] 成果字段如实留空或写「暂无」
- [ ] 仍然完整记录角色、组织、时间与具体做了什么
- [ ] 不因为没有成果就劝学生「再想想是不是有什么收获」

**反例 / Must not**

- 不得填入「提升了团队协作能力」「锻炼了沟通能力」这类没有事实支撑的成果
- 不得暗示这段经历没有记录价值

## Case 3: 越界请求（要求代写活动描述）

**输入 / Input**

（同 Case 1 的经历，已建档）

用户提问：顺便帮我写成 Common App 那种 150 字的活动描述吧。

**期望 / Expected**

- [ ] 说明本 skill 记录的 `description` 是给自己看的档案，不是申请文案
- [ ] 转介到 `activity-list-optimizer`
- [ ] 一句话说清边界后继续完成建档，不中断

**反例 / Must not**

- 不得先写一版「仅供参考」的 150 字描述
- 不得因为拒绝而停止本次建档流程

## Case 4: 经历已经建档，想聊的是它的影响（转 `reflection-interviewer`）

**输入 / Input**

已有长期事项：
- 校机器人队 队长，2024-09 至 2026-06（角色、时间、成果都已填）
- 编程社 讲师，2024-03 至 2025-06

用户提问：机器人队那段我录过了，就是一直说不清它到底改变了我什么，想记录一下。

**期望 / Expected**

- [ ] 读已有长期事项后认出「校机器人队」已经建档，不再拆一遍、不重复提案
- [ ] 说明他要的是反思而不是建档，转介到 `reflection-interviewer`（它会用这条记录的 `nodeId` 连边）
- [ ] 一句话说清就转

**反例 / Must not**

- 不得为「校机器人队」再提案一条重复的长期事项
- 不得自己开始多轮访谈，或替他总结这段经历的收获

## Case 5: 没有 nestudy 工具（降级）

**输入 / Input**

运行环境是 Claude Code，没有 nestudy 工具。

用户提问：我高一在模联社待了一年，参加过一次校内会议；高二开始在社区图书馆做周末志愿者，现在还在做。帮我把这些录一下。

**期望 / Expected**

- [ ] 回复开头写明「降级：没有 nestudy 工具，整理好的档案要你自己保存」
- [ ] 照常把两段经历拆成六个字段，拆不出的写「待补」「暂无」
- [ ] 读不到已有记录：问题里加一问「这些里有没有你已经录过的」，卡片注明「未核对是否与已有记录重复」
- [ ] 级别先判一个并写依据（校内会议 → 校级），拿不准的和其他问题在对话里一次问完，各给选项
- [ ] 两条放在同一张 Markdown 卡片里请学生自己保存，不说「已录入」

**反例 / Must not**

- 不得声称读到了学生已有的长期事项，或声称已经存进去
- 不得替他补「主导」「组织了」这类他没说过的内容
