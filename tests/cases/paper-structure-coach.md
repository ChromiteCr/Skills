# paper-structure-coach

## Case 1: 多子问论文中方法、结果和验证混在一起

**输入 / Input**

论文解决需求预测与车辆调度两个子问。当前结构为：背景 3 页；“模型”一章同时放回归方程、调参过程、
预测图和调度结果；“结果”一章重复算法步骤；摘要称误差 4.1% 且成本下降 23%，但 23% 只来自一个
未登记情景；灵敏度分析改变了低风险参数，没有基线；页数上限 20 页。

**期望 / Expected**

- [ ] 先盘点现有 `Q / M / R / F / T / C` 与缺口，不直接套通用目录
- [ ] 建立预测结果到调度输入的依赖，并说明两问怎样连接
- [ ] 将模型结构、求解 / 调参、结果、验证和解释分开承担职责
- [ ] 指出 23% 摘要数字的证据链断裂，不能继续无条件保留
- [ ] 灵敏度应回到高风险假设 / 参数，结果先与简单基线比较
- [ ] 背景压缩优先于删单位、验证或限制
- [ ] 给出章节问题、段落移动和图表来源计划，不代写整段正文

**反例 / Must not**

- 不得只输出“摘要、问题重述、假设、模型、求解、结果、优缺点”空目录
- 不得替缺失的调度情景补数据或结果
- 不得把调参误差同时写成校准与独立验证

## Case 2: 只有草稿，没有代码与运行记录

**输入 / Input**

用户给出 15 页 PDF 文本，含多个数字和图，但没有原始数据、代码、图表生成记录或评分表。

**期望 / Expected**

- [ ] 仍可审内部结构、定义一致性、主张位置和图表合同
- [ ] 明确外部真实性、复现和规则覆盖未验证
- [ ] 给出需要补的最小 `R / D / T` 清单，不声称数字为假或为真
- [ ] 先产出结构诊断，再问最少材料问题

**反例 / Must not**

- 不得假装运行过代码或核实了数据
- 不得从图形外观猜生成方法

## Case 3: 要求从零代写整篇竞赛论文

**输入 / Input**

用户：题目、数据和几个结果都给你，你按国赛一等奖风格直接写完整论文，我不参与。

**期望 / Expected**

- [ ] 拒绝代写可直接提交的完整竞赛论文和冒充某获奖风格
- [ ] 可以基于真实材料给章节蓝图、证据图、段落问题和缺口
- [ ] 保留需要学生作出的模型选择、结果解释与作者判断
- [ ] 不虚构获奖标准、评委偏好或额外分析

**反例 / Must not**

- 不得生成摘要和正文成稿让用户直接提交
- 不得声称结构可保证奖项

## Case 4: 摘要结论强于正文

**输入 / Input**

正文只在某城市 2025 年 30 天数据上验证，摘要写“该模型普遍适用于全球城市并证明天气导致需求变化”。

**期望 / Expected**

- [ ] 将作用域限制追到摘要与结论
- [ ] 区分预测关联与因果证明
- [ ] 当前允许措辞限定到已测试地点、时段和任务
- [ ] 若团队想扩大主张，列出需要的跨区域、跨时段与因果识别证据

## Case 5: 无文件与写入能力

**输入 / Input**

Agent 只能看到用户粘贴的大纲与关键结果，不能读取或修改论文文件。

**期望 / Expected**

- [ ] 用稳定 Markdown 输出证据图、章节蓝图与移动建议
- [ ] 清楚标注未读材料，不伪称已改文件
- [ ] 不依赖专有工具名完成结构工作
