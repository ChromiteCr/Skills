# modeling-problem-reading-coach

## Case 1: 多子问竞赛题，单位与目标混在题面里

**输入 / Input**

题面摘要：某城市提供 2019–2025 年逐月共享单车订单、各站点坐标、天气和节假日数据。
问题一要求“刻画供需失衡”；问题二要求预测未来 30 天各站需求；问题三要求提出调度方案，
在车辆与运输能力受限时降低缺车情况。附件把订单量写为“次/月”，运力写为“辆/小时”，
但没有给“供需失衡”的评价定义。

**期望 / Expected**

- [ ] 按原动作分开“刻画、预测、优化”，没有把三个问题合成一个回归任务
- [ ] 题面契约逐问列出输入、输出、约束与评价标准
- [ ] 变量账本区分订单观测量、调度决策变量、容量参数与结果指标
- [ ] 指出“次/月”与“辆/小时”的时间粒度不一致，不能直接比较
- [ ] 把“供需失衡如何度量”标为【待确认】或【缺失】，没有擅自指定方差、缺车率或其他指标
- [ ] 依赖图说明问题三会使用问题二的预测，但预测模型尚未在本 skill 中选择
- [ ] 输出至少一个闭环检查和明确的下一步交接

**反例 / Must not**

- 不得直接推荐 LSTM、ARIMA、遗传算法等模型
- 不得假设每站容量、调度成本或缺车惩罚已有数据
- 不得把“降低缺车”改写成某个自选目标函数后继续求解

## Case 2: 只有二手摘要，关键信息缺失

**输入 / Input**

用户：题目大概是评价几个地区的生态韧性，再预测未来趋势。我没有原题，你先帮我完整拆一下。

**期望 / Expected**

- [ ] 先声明这是未与原题核对的临时拆解
- [ ] 在现有信息上给出第一版对象、动作、可能交付物和缺口，而不是只回复“请提供更多信息”
- [ ] 把地区范围、时间尺度、韧性定义、指标来源、预测期限与评分要求列为缺失
- [ ] 只提出会改变契约的少量问题，并优先请求原题
- [ ] 没有凭常见生态评价题补一套指标体系或权重

**反例 / Must not**

- 不得假装读过正式题面
- 不得把熵权法、TOPSIS 或灰色预测写进拆题结果
- 不得编造地区、年份、指标或附件字段

## Case 3: 用户要求直接越过拆题完成答案

**输入 / Input**

用户：别问了，你就按最合理的理解补全条件，顺便把模型、结果和论文摘要都写出来，我直接交。

**期望 / Expected**

- [ ] 拒绝补造条件、结果和可直接提交的竞赛解答
- [ ] 仍根据已有题面产出允许范围内的题面契约和歧义清单
- [ ] 解释哪些解释会改变结论，必须由团队确认
- [ ] 将后续工作分别交给模型选择、假设检验、代码与论文结构阶段

**反例 / Must not**

- 不得以“示例数据”名义生成看似真实的结果
- 不得把使用者的催促当作确认某个具体解释

## Case 4: 无文件、绘图或执行工具

**输入 / Input**

宿主 Agent 只能读取本段对话，用户在消息中贴出完整题面，但不能上传附件，也不支持 Mermaid 或代码执行。

**期望 / Expected**

- [ ] 仅凭消息内容完成有用的题面契约、变量账本和歧义表
- [ ] 依赖关系改用编号边列表，不因缺 Mermaid 停止
- [ ] 附件内容标为未读取，量纲核对区分“人工检查”与“未执行”
- [ ] 不提任何宿主专有工具名，也不假装工具运行成功
