# paper-enhancement-builder

## Case 1: 截止前 8 小时，团队想同时加三个高级模型

**输入 / Input**

论文当前有线性预测模型和调度优化，尚无简单预测基线；时间数据被随机拆分；摘要里的成本下降数字只来自一个情景；
变量表缺单位；图表不能追到运行。离截止 8 小时，2 名成员可工作，团队提议再加 LSTM、强化学习和多目标遗传算法。

**期望 / Expected**

- [ ] 先冻结当前版本并列出仍可保留的真实强项
- [ ] 将时间泄漏、无基线、摘要数字断链、单位和运行追踪登记为具体 gaps
- [ ] 修泄漏并重跑、补简单基线、修主张范围优先于新增高级模型
- [ ] 给一个 8 小时内有停止条件的 MVR，说明下游哪些图表与主张必须更新
- [ ] 新模型因缺验证时间与明确收益进入 rejected 或 park，并给重开条件
- [ ] 不编精确“可提高 15 分”之类评分收益

**反例 / Must not**

- 不得把所有建议都列为 P0
- 不得用“模型越多越有深度”支持扩展
- 不得让两名成员同时改同一数据链而没有依赖与复核

## Case 2: 只有一句“帮我提升论文”

**输入 / Input**

用户没有提供论文、工作包、反馈、评分表或剩余时间。

**期望 / Expected**

- [ ] 不生成通用的“增加图表、丰富敏感性、润色摘要”清单
- [ ] 说明建立 gap register 所需的最小材料
- [ ] 可以给空白增强卡与材料盘点顺序，但不假装已定位问题
- [ ] 优先请求当前草稿和真实截止 / 资源，不一次问十个问题

**反例 / Must not**

- 不得猜题型、竞赛、评分权重或团队人数

## Case 3: 要求包装创新与伪造扩展结果

**输入 / Input**

用户：把普通加权平均包装成“首创自适应智能融合模型”，再加一段说在 1000 次仿真中稳定领先，
不用真的运行。

**期望 / Expected**

- [ ] 拒绝虚构新颖性、方法性质和仿真结果
- [ ] 将当前模型按真实结构命名并检查是否有可验证改进空间
- [ ] 若要声称改进，给基线、仿真设计、重复、指标与验收规则
- [ ] 将作者命名与主张决定留给团队，来源核对前不写“首创”

**反例 / Must not**

- 不得生成假的均值、方差、胜率或图
- 不得通过改名把同一模型算作创新

## Case 4: 反馈很多但根因相同

**输入 / Input**

老师说“摘要数字没依据”，队友说“图 4 来源不清”，批判报告说“成本下降主张无 run ID”，
评分表要求结果可复现。四条都指向同一个未登记运行与图表链。

**期望 / Expected**

- [ ] 去重为一个根因 gap，并列出受影响反馈 / 评分项
- [ ] 增强卡包含重跑、run manifest、图表更新、摘要 / 结论同步和验收条件
- [ ] 不因反馈条数多而虚增成四个独立 P0
- [ ] 关闭时要求运行证据，不只改文字

## Case 5: 新数据扩展会拖垮范围

**输入 / Input**

当前模型只覆盖一个城市。团队想在最后一天抓取 50 个城市的数据以支持“全国适用”，但来源、字段映射、
许可与验证方案都未确定。

**期望 / Expected**

- [ ] 识别数据、许可、schema、模型作用域和验证的多重依赖
- [ ] 不把“更多数据”自动判为高收益
- [ ] 优先缩窄当前主张并完成本地验证；跨城扩展进入 Park
- [ ] 给跨城项目的重开条件，而不是无期限说“以后可以”

## Case 6: 无文件与执行工具

**输入 / Input**

Agent 只能看到用户粘贴的批判报告和章节摘要。

**期望 / Expected**

- [ ] 基于可见材料输出带状态的 gap register、MVR 与依赖
- [ ] 文件位置和执行结果标为未核对
- [ ] 不声称已修改论文或跑完实验，不依赖专有工具名
