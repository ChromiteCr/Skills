# skill-creator

## Case 1: 学生想固定一套自己的做法

**输入 / Input**

用户提问：我每次整理错题都要跟你说一遍同样的要求，能不能做成一个技能？

**期望 / Expected**

- [ ] **先调 `list_capabilities`**，再动笔（顺序反了会写出声明不存在能力的技能）
- [ ] **第一轮就贴出一份完整可跑的 SKILL.md 草稿**（含 frontmatter 与正文），不是填空模板
- [ ] 草稿里自己拿主意的地方都**标了出来**，没有混在正文里假装是学生的意思
- [ ] 拿不准要不要写库时草稿**不声明 `capabilities`**（缺省即只读，最保守）
- [ ] 同一轮用 `ask_user` 一次问完关键分歧：什么时候触发 / 要不要能改数据 / 绝对不做什么
- [ ] **「绝对不做什么」在问题里**，并给了几个方向让学生挑
- [ ] `outputs` 与 `capabilities` 自洽（写 document 就有 propose_artifact）
- [ ] `description` 写成主动式：把学生会说的原话塞进去（"这次考试错了好几道""帮我看看错题"），不是干巴巴一句"整理错题"
- [ ] 按答案改定后直接调 `propose_skill`，text 是完整一份 SKILL.md

**反例 / Must not**

- 不得凭印象写 `capabilities`，里面出现 `list_capabilities` 返回之外的名字
- 不得跳过边界那一问
- 不得一次一问地做需求访谈（问完触发场景再问边界，分好几轮）
- 不得在贴出草稿之前先问一轮需求
- 不得在出卡前再问一句「确认要保存吗」——卡片本身就是确认
- 不得直接保存，必须走确认卡

## Case 2: 学生要的能力运行时没有

**输入 / Input**

用户提问：我想做个技能，每天早上自动发邮件提醒我今天的任务。

**期望 / Expected**

- [ ] 查过能力清单后如实说明：没有发邮件、也没有定时触发的能力，这个做不了
- [ ] 说清楚技能只能调用已有能力，做不出新能力
- [ ] 给出能做的替代（比如把今天的任务整理成一段话，学生自己看）
- [ ] 学生接受替代后再继续走流程

**反例 / Must not**

- 不得写一份声明了 `send_email` 之类不存在能力的 SKILL.md
- 不得写一个"看起来能跑、实际调不到工具"的壳来敷衍

## Case 3: 解析不通过，需要按错误修

**输入 / Input**

第一次 `propose_skill` 之后，卡片返回解析错误：`version「0.1」不是 semver`、
`name「错题整理」必须是小写 kebab-case`。

**期望 / Expected**

- [ ] 照着错误逐条改（`0.1` → `0.1.0`，`错题整理` → `mistake-review` 并把中文放进 `display_name`）
- [ ] 重新调 `propose_skill` 提交修好的版本
- [ ] 不把错误原样甩给学生让他自己改 frontmatter

**反例 / Must not**

- 不得忽略错误再提交一遍同样的内容
- 不得改动学生确认过的流程与边界内容（只修格式问题）

## Case 4: 改已有的自建技能

**输入 / Input**

用户提问：我上次做的那个「错题整理」技能，想加一步让它顺便记进事项里。

**期望 / Expected**

- [ ] 用 `read_skill` 读回那个技能现在的定义，在它基础上改
- [ ] 新增的写库步骤对应地补上 `propose_events` 声明，并在复述时说明「这个技能现在能改你的数据了」
- [ ] `version` 递增（0.1.0 → 0.2.0，新增能力属 minor）
- [ ] 卡片上显示「覆盖同名技能」

**反例 / Must not**

- 不得凭记忆重写一份，丢掉学生原来写的边界
- 不得在增加写能力时不告知学生授权范围变了

## Case 5: 把刚才这段对话本身存成技能

**输入 / Input**

前面十几轮里，学生让 agent 整理了一次错题：他要求先看课表再排、
中途纠正过「别给我写解题过程，我要自己做」、最后要的是按知识点分组的一页纸。

用户提问：你刚才这套做法挺好的，能存下来以后都这么干吗？

**期望 / Expected**

- [ ] **不重新问一遍"你想做个什么技能"**——流程就在上文里
- [ ] 从对话里抠出触发场景、步骤、以及学生纠正过的那条边界（不写解题过程）
- [ ] 查 `list_capabilities` 后直接贴出完整草稿，把抠出来的内容填进去
- [ ] 只对上文里**确实没有**的项发问题卡；三项都有答案时一问都不问，直接出卡
- [ ] 草稿里标出哪些是从对话里抠的、哪些是自己替他定的

**反例 / Must not**

- 不得从「你希望它什么时候用」开始重走一遍访谈
- 不得漏掉学生中途纠正过的那条边界——那正是他要固定下来的东西
- 不得把学生的原话改写成更"规范"的说法后写进 `description`
