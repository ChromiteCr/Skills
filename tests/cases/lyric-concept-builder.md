# lyric-concept-builder

## Case 1: 只有一个主题词

**输入 / Input**

用户提问：我想写一首疗愈主题的歌，帮我想想写什么。

**期望 / Expected**

- [ ] 指出"疗愈"是效果不是主题，需要落到具体处境（谁 / 什么状况 / 什么变化）
- [ ] 只问两个问题：唱给谁、有没有真实的画面可用
- [ ] 派**三个 sonnet 子代理**并行，切入位置分别是近景 / 时间对照 / 未说出口的话
- [ ] 子代理只返回概念卡四项，**不写完整段落**
- [ ] 主 Agent 收敛成一份概念卡：处境、意象系统、情绪弧线、hook 候选五条、素材清单
- [ ] 意象系统里的三到五个子意象来自同一个世界，能拍进同一个镜头
- [ ] 明确列出"不用"的高危意象
- [ ] hook 候选不含黑名单词，五条说法真的不同

**反例 / Must not**

- 不得产出"这首歌想表达温暖与治愈"这类效果词描述
- 不得把星空、海洋、翅膀、灯火堆在同一个意象系统里
- 不得在这一步写出完整的主歌或副歌
- 不得追问风格、调性、BPM 这类此刻无关的问题

## Case 2: 用户给了真实素材

**输入 / Input**

用户提问：想写给我外婆。她去年走的。我记得她总把电视音量开到最大，
还有她房间里那个走得慢五分钟的挂钟。

**期望 / Expected**

- [ ] 直接用他给的两个真实物件（电视音量、慢五分钟的挂钟）当意象核心
- [ ] 素材清单逐条列出这两样，并说明填词时只能用这些
- [ ] 情绪终点不强行圆满
- [ ] 只在确有必要时追问（比如还有没有别的具体物件），不重问已经答过的

**反例 / Must not**

- 不得另外编造"院子里的柿子树""她织的毛衣"这类没提过的细节
- 不得把真实物件换成"老屋""炊烟"这类通用符号
- 不得把终点写成"她一直都在我心里陪着我"

## Case 3: 已经知道写什么

**输入 / Input**

用户提问：处境、意象、hook 我都定好了，直接帮我填词。

**期望 / Expected**

- [ ] 不重走概念流程
- [ ] 指向 `adversarial-lyric-writer`
- [ ] 若他给的概念卡缺了骨架，提醒补，但不重问已经定好的部分

**反例 / Must not**

- 不得把他定好的处境再问一遍
- 不得因为"流程要求"而重新派子代理提切入角
