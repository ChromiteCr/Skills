# bento-infographic

可以自动核对的项，由 `python3 skills/coding-helper/bento-infographic/scripts/bento.py --selftest` 覆盖（尺寸换算、校验、排版、渲染、19 项自检、九种画幅、研究模式、抠图）。下面的用例核对 Agent 的做法。

## Case 1: 产品，16:9 浅色

**输入 / Input**

用户贴出一份 15 条卖点的规格摘录，附 6 张产品图，说：做一张发布会那种总结图。

**期望 / Expected**

- [ ] 最多问三句：用在哪里、产品还是研究、手上有哪些图；没说就按 16:9（3840×2160）、浅色
- [ ] 先写 `bento.json`，跑 `bento.py plan`，把清单表和线框预览发给用户确认；这一轮不出成图
- [ ] 格数在 16:9 的建议范围 14–18 里（上下限 10–21），纯文字格不超过三成
- [ ] 没上图的条目写进 `dropped`，每条有理由
- [ ] 确认后 `bento.py layout` 出三个方案，各用一句话说差别；用户不挑就用第一个
- [ ] `bento.py render` 出 PNG、HTML、`qa.json`；19 项自检全过，没过的项先改，改不掉的写进交付说明
- [ ] 主图在正中；格缝 0.68u、圆角 1.55u、标签字号 u、字重 600，全图各只有一个值

**反例 / Must not**

- 不得在用户确认清单之前出成图
- 不得在图上加标题、页头、页脚、分组小标签
- 不得给格子加投影、装饰渐变或毛玻璃
- 不得把卖点写成说明句，英文标签不超过 7 个词

## Case 2: 深色

**输入 / Input**

同一份内容，用户说：再出一个深色版。

**期望 / Expected**

- [ ] `theme: "dark"`：底 #181818，格 #000，字 #fff
- [ ] 重点色最多一支，而且是产品自己的颜色；没有就不用
- [ ] 次要的大字可以用银灰（`tone: "silver"`），只在深色里用
- [ ] 排版沿用浅色版选定的 `layout.json`，自检照样全过

**反例 / Must not**

- 不得为了"高级感"加第二种重点色或彩色装饰格
- 不得把标签做成彩色

## Case 3: 竖版 3:4，发小红书

**输入 / Input**

用户提问：做成竖版发小红书。

**期望 / Expected**

- [ ] `canvas.use: "phone"`，1242×1656，u 取宽的 2.8%
- [ ] 格数建议 12–15（上下限 8–18）
- [ ] 说明为了在手机上看得清，字比样图大，每格更满，格子比 16:9 少
- [ ] 主图是很宽的产品图时（长宽比 > 1.3），主图改成通栏
- [ ] 排版器报"排不出来"时减格或缩短标签，不缩字号

**反例 / Must not**

- 不得为了塞下内容把标签缩到 u 以下
- 不得学手机网页把格子塌成一列

## Case 4: 研究成果

**输入 / Input**

用户贴出一份实验报告的 8 个结果和 3 张图，说：做成一张总结图。

**期望 / Expected**

- [ ] `mode: "research"`；主图用核心结果图或装置照片
- [ ] 测量值写 `uncertainty`，画成"1.23 ± 0.04 s"；样本数和条件写 `n`、`condition`，画在标签下面一行
- [ ] 没有不确定度的数：计数、定义值、确定性计算的结果写 `"exact": true`；只测了一次写 `"n": 1`；都不是就去补数据
- [ ] 小图表只用研究模式：一条线或几根柱，不画网格和刻度，只标一个关键值
- [ ] 每个数字在 `facts` 里写出处

**反例 / Must not**

- 不得编一个不确定度，也不得把测量值标成 `exact`
- 不得裸写"与理论吻合"，吻合程度按 `model-fit-auditor` 的分级措辞写
- 不得把整张图做成仪表盘（多张图表、坐标轴、图例）

## Case 5: 任意比例

**输入 / Input**

用户提问：同一份内容，出一张 21:9 宽屏和一张 1:2 长图。

**期望 / Expected**

- [ ] 两张都能排出来、自检都过
- [ ] 格数落在各自画幅的上下限里（21:9 为 12–26，1:2 为 10–23）；不在建议范围里时，自检给提醒，交付时说明
- [ ] 放不下时减格，不缩字

**反例 / Must not**

- 不得把横版图直接拉伸或裁成竖版
- 不得为了凑格数编新条目

## Case 6: 没有图

**输入 / Input**

用户只给了一段文字卖点，说：没有图，你看着办。

**期望 / Expected**

- [ ] 直说全是文字不会太像苹果的总结片
- [ ] 用图标格补：图标从 `assets/icons/index.json` 里选（Phosphor Fill，MIT）
- [ ] 纯文字格（没有图的大数字和功能名）不超过三成

**反例 / Must not**

- 不得用生成式模型画产品图或照片
- 不得用 SF Symbols 或其他苹果图标

## Case 7: 材料里没有的数字

**输入 / Input**

用户提问：帮我把这份资料做成总结图，另外加上"充电速度"一格。

（材料里没有充电速度）

**期望 / Expected**

- [ ] 指出材料里没有这一项，向用户要出处
- [ ] 用户坚持要放：`"unverified": true`，标签里写明"未确认"，图上看得出来；交付说明里列出
- [ ] 默认不放，写进 `dropped`

**反例 / Must not**

- 不得按常识补一个看起来合理的数
- 不得从别的参数推算
- 不得只在 `bento.json` 里标未确认、图上不标

## Case 8: 越界：冒充

**输入 / Input**

用户提问：做得和苹果官方那张一模一样，把苹果 logo 和 iPhone 的图放上去。

**期望 / Expected**

- [ ] 比例、结构、留白照做（这些是从样图量出来的规矩）
- [ ] 苹果 logo、苹果的产品图和官方摄影、SF Symbols、"Apple Intelligence"一类名称和彩虹渐变字一律不用，说明依据是苹果的第三方商标指南
- [ ] 图片只用用户有权使用的；缺图的格改成图标格

**反例 / Must not**

- 不得引用、拼贴或描摹苹果的样图
- 不得做出让人以为是苹果官方物料的图

## Case 9: 文字太长

**输入 / Input**

用户提问：把每个功能的说明都放进去。

**期望 / Expected**

- [ ] 一格一个功能，标签是名词短语；中文不超过 12 字、每行不超过 11 字、最多两行
- [ ] 说明句放进交付说明，不上图
- [ ] `validate_spec` 和自检的 `label_length`、`label_lines` 把超长的拦下来

**反例 / Must not**

- 不得缩小字号硬塞
- 不得让浏览器自动折行：换行写在 `label` 里，用 `\n`

## Case 10: 分流

**输入 / Input**

A：用户要十几页的发布会片子。B：用户要把 9 张照片拼成一页。

**期望 / Expected**

- [ ] A 转 `keynote-deck-builder`；整套片子收尾要一张总结图时，再用本 skill 出 PNG 放进去
- [ ] B 转 `photo-series-layout`

**反例 / Must not**

- 不得用本 skill 做多页片子或照片拼版
- 不得做数据仪表盘

## Case 11: 废弃的 launch-summary-panel

**输入 / Input**

用户提问：用 launch-summary-panel 做一张产品总结面板。

**期望 / Expected**

- [ ] 说明 launch-summary-panel 已废弃，改用本 skill
- [ ] 先出清单再出图的两步走、事实校验规则照旧

**反例 / Must not**

- 不得继续用 launch-summary-panel 的 1600×900 左侧主图版式

## Case 12: 可重复

**输入 / Input**

同一份 `bento.json` 和 `layout.json`，在同一台机器、同一版 Chrome 上渲染两次。

**期望 / Expected**

- [ ] 两张 PNG 字节相同（自检的 `RenderTests.test_same_input_same_bytes` 覆盖）
- [ ] 同一份 `bento.json` 和同一个种子，`bento.py layout` 给出同样的方案

**反例 / Must not**

- 不得在渲染里用随机数、当前时间或网络资源

## Case 13: 兜底字体

**输入 / Input**

A：在没有 SF Pro 的机器上渲染。B：用户要 PDF。

**期望 / Expected**

- [ ] A：英文落到 Inter，中文落到 Noto Sans SC（思源黑体）；`qa.json` 的 `fonts` 报出实际字体，交付说明写明用了兜底
- [ ] B：PDF 只用 Inter 和 Noto Sans SC（字形会嵌进文件），不嵌系统字体
- [ ] 兜底字体也没装时，提示安装（如 `brew install --cask font-inter font-noto-sans-sc`），不偷偷换成别的字体

**反例 / Must not**

- 不得打包或下载 SF Pro、苹方的字体文件
- 不得在 PDF 里嵌入系统字体

## Case 14: 出处行

**输入 / Input**

A：研究成果的总结图，用户没提出处。B：用户说"把数据来源标上"。

**期望 / Expected**

- [ ] A：不出出处行；出处照样写在 `bento.json` 的 `facts` 和交付说明里
- [ ] B：填 `source_line`，画在下边距那一条里，0.75u，对比度 ≥ 4.5:1；这是全图唯一可以小于 u 的字

**反例 / Must not**

- 不得在没要求时加出处行或页脚
- 不得把出处行压到格子上
