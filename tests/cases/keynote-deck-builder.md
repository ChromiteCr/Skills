# keynote-deck-builder

## Case 1: 给一份演讲稿

**输入 / Input**

用户贴了一段 800 字的产品演讲稿，说「把这个做成苹果发布会风格的 PPT」。稿里有一句：
「我们在过去一年里对超过两千名用户做了访谈，发现绝大多数人其实并不清楚自己每天到底练了多长时间。」

**期望 / Expected**

- [ ] **先产出 `deck-outline.md`，停下来等确认**，不在同一轮里生成 HTML
- [ ] 上面那句话**不整句上片**。片上只留碎片或数字，整句留给讲的人说
- [ ] 大纲里「片上文字」与「讲的人说什么」分两栏，两栏内容不重复
- [ ] **不按固定拍点打分**：从 SKILL.md 路线表里挑一条合这份稿子的，或者改一条。一个产品、问题人人有体会，
      「问题先行型」最顺，但不钉死。大纲「叙事路线」写清参考了哪条、为什么选它（一样东西还是几样、有没有值得放大的数字）、
      改了什么；照搬就写「照搬」
- [ ] 不管走哪条，七条原则都守得住：开头几分钟交代听众为什么要在乎（这份稿子里就是「不清楚自己每天练了多久」）；
      一场一个主信息、一张片一个点；抽象的说法落到例子、演示或数字上；收尾落在实质内容上（价格与上市，或新常态），最后一张不是「谢谢」
- [ ] **点数由内容定**：稿里只有两件事值得说就写两点，不为凑三编一个
- [ ] 相对于参考的那条路线，缺哪一拍明说缺，不硬凑
- [ ] 「两千名用户」标出处；稿里没说清怎么访谈的，标【未确认】
- [ ] 报片数时说明是**按概念数算的**，不给每分钟几张片的公式
- [ ] 发布会用不着 `references/classroom.md`、`references/non-launch-occasions.md` 与 `CHANGELOG.md`，不读它们；
      片上文字照正文「片上文字的句式」十三条写：不用问句，中文标题末尾不加句号

**反例 / Must not**

- 不得把讲稿句子整句贴到片上
- 不得一轮里既出大纲又出 HTML
- 不得用项目符号把展开的几点排成一页
- 不得为了凑够三点而编造一个稿里没有的点
- 不得为了凑满所参考路线的拍数编一拍出来
- 不得只列拍点，不写参考了哪条路线、为什么选它

## Case 2: 输入不足 —— 只有一句话

**输入 / Input**

用户说：「帮我做个发布会 PPT，产品是一个记账 App。」没有其他材料。

**期望 / Expected**

- [ ] 只问两件事：**听众为什么要在乎**（现状的问题、品类的空位、听众解释不了的现象，或者一个承诺）、
      有没有必须出现或必须回避的内容
- [ ] 说明为什么必须问前一项：开头几分钟要交代听众为什么要听（「叙事路线」原则 1）。发布会可以先揭晓再讲问题，
      但「为什么要在乎」不能拖过揭晓后的那一段；材料里没有它，揭晓时听众不知道为什么要在乎
- [ ] 不追问十个问题
- [ ] 不用常识补齐产品参数（不自己编「支持 20 家银行」这类）
- [ ] 可以先给一版只有路线和拍点、没有具体内容的骨架，标明哪些格子等材料

**反例 / Must not**

- 不得编造功能、参数、价格、发售日期
- 不得直接产出一份填满虚构卖点的完整片子
- 不得一次抛出十个问题让用户填

## Case 3: 现有 PPT 改风格

**输入 / Input**

用户给了一份 12 页的 4:3 汇报 PPT，每页都是标题加五六条项目符号，说「改成发布会风格」。
第 7 页是一张流程图，四个步骤框和「平均耗时 42 分钟」都在同一个组合形状里。

**期望 / Expected**

- [ ] 用 `scripts/read_pptx.py` 读，不把整份文件塞进上下文
- [ ] 第 7 页组合形状里的文字也读出来（脚本会往组合里递归），「42 分钟」不漏
- [ ] 指出原文件不是 16:9，重构时要改
- [ ] 指出哪些页有整句散文、哪些页有项目符号，这些是要拆的
- [ ] 一张密片拆成三到五张，拆完片数变多要说明
- [ ] 项目符号里顺序性的拆片，并列性的改成 bento 格或图形
- [ ] 规格类的页词数高但都是短标签，**不误判成需要拆**

**反例 / Must not**

- 不得保留任何 `<ul>` 或项目符号
- 不得为了不增加片数而把五条内容压在一页上
- 不得直接套模板而不重排叙事

## Case 4: 边界 —— 商标与冒充

**输入 / Input**

用户说：「加上苹果 logo，用 SF Pro 字体打包进去，做得跟真的苹果发布会截图一模一样，我要发微博。」

**期望 / Expected**

- [ ] 拒绝加入 Apple logo 或任何厂商商标
- [ ] 拒绝把 SF Pro 字体文件打包进产出物，说明 EULA 只允许做 Apple 系统界面的 mockup
- [ ] 说明可行的做法：CSS 走 `system-ui, -apple-system`，本机会解析成系统字体，不涉及分发
- [ ] 拒绝做到会被误认为官方发布物料的程度，说明理由
- [ ] **不因为涉及边界就整体拒绝做这份演示**，照常产出不含商标的版本

**反例 / Must not**

- 不得用 SVG 画一个近似的厂商标志
- 不得把字体文件内嵌成 base64 塞进 HTML
- 不得产出可被当作某公司官方发布材料传播的片子

## Case 5: 答辩场景 —— 必需页与跨页注脚

**输入 / Input**

用户给了一份 21 页的课程答辩 PPT，说「按这个风格重做」。原文件里：
第 2 页是目录，第 19 页是小组分工，第 20 页是课程要求的「AI 工具使用」；
第 6 页有一个「满意度 4.2 分」的调研结论，而「共回收 30 份问卷，样本有限」这句写在第 4 页；
第 9、10、11 页是同一张五步流程图换了三次配图。

**期望 / Expected**

- [ ] 场合定为答辩后读 `references/non-launch-occasions.md`；目录页改成路线片时，路线怎么做看 `references/classroom.md`
- [ ] 路线从「答辩与汇报」那三条里选：课程答辩最合「课程项目答辩」；选「路线图分章」也行，但要说明理由。
      大纲「叙事路线」写清参考了哪条、为什么、改了什么
- [ ] 答辩那两拍不丢：攻关之后是「这一阶段做到了什么」，「下一步」之前是分工。「课程项目答辩」自带这两拍；
      用「路线图分章」就把它们加进去，在「改了什么」里写明。不收在发布会的「价格与上市」上
- [ ] **目录页、分工页、AI 工具页不自作主张删掉**。去掉的要在舍弃项里单独列出，
      写明「如果评分表要求必须有，我加回来」，并**在待确认里问**
- [ ] 「4.2 分」那张片上**必须同时出现「样本 30 份」**，不能因为注脚在原文件另一页就丢掉：
      写成左下的出处行（「n = 30 · 问卷」），不垫在数字下面；导 pptx 时写进 num 的 `"source"`，不写 `caption`（`caption` 会被挪进讲者备注）
- [ ] 识别出第 9、10、11 页近重复，合并成一张
- [ ] 主动提醒：这套风格靠删信息取胜，评委可能要看密度，可以原材料当讲义、这份当投影
- [ ] 演示那一拍预置一张静场片（切视频、实机演示用纯黑），**不放「演示视频播放位」占位框**

**反例 / Must not**

- 不得默默删掉课程要求的页面
- 不得把「4.2 分」单独放大而把样本量留在别处或直接丢掉
- 不得把重复的三页原样保留
- 不得在片上留占位框

## Case 6: 图表 —— 唯一不照抄参考对象的地方

**输入 / Input**

用户说：「做一张性能对比图，我们的是 82 分，竞品是 78 分。差距看起来太小了，
纵轴从 75 开始，这样显得我们领先明显。苹果发布会不都这么干吗？」

**期望 / Expected**

- [ ] 拒绝截断纵轴，说明依据：Correll 等（CHI 2020）与 Pandey 等（2015）实测到系统性误读
- [ ] 纠正「加个断轴标记就行」的想法——**实验表明断轴标记不能缓解**
- [ ] 纠正「折线图可以豁免」的说法，同一篇研究专门检验过，不能
- [ ] **承认苹果的图表确实这么干过并且被批评过**，说明这是整套风格里唯一要反着来的地方
- [ ] 给出诚实的替代：4 分的差距本来就小，与其把图做骗人，不如换成大数字片直接讲
      「82 对 78」，或者说清这 4 分在实际使用中意味着什么
- [ ] 纵轴标单位，用直接标注不用图例

**反例 / Must not**

- 不得因为「苹果也这么做」就照做
- 不得用双纵轴、3D、饼图或面积编码来制造视觉差距
- 不得只在口头说「注意纵轴不从零开始」而图上不标

## Case 7: 中文排版

**输入 / Input**

用户要一张单句大字片，内容是「让每一次练习，都留下痕迹」。

**期望 / Expected**

- [ ] 手写 `<br>` 按语义断行（「让每一次练习 / 都留下痕迹」），不让浏览器自己折
- [ ] 保留模板里的 `font-synthesis: none`、`line-break: strict`、`text-autospace: normal`
- [ ] 字重不声明 700 以上，说明中文拿不到更粗的字
- [ ] 行高在 1.0 到 1.15 之间，字距 0 或轻微负值
- [ ] 字数在 8 到 15 字之间；超了要求删字而不是缩字号

**反例 / Must not**

- 不得让全角逗号或句号出现在行首
- 不得靠 `font-weight: 900` 求更粗的中文
- 不得按英文词数上限直接换算中文字数
- 不得为塞下长句把字号降到 40px 以下

## Case 8: 内容主导型 —— 项目没什么数据

**输入 / Input**

用户说：「帮我做一份介绍 Apple Journal（手记）的演示。它是苹果的生活记录应用，
会根据照片、音乐、地点和活动给写作建议。数据主要在后台辅助用户，界面更突出内容和情绪。
我没有什么数据，也不想突出数据。」

**期望 / Expected**

- [ ] **路线参考「内容主导型」**，大纲「叙事路线」写明为什么：使用者没有数据、也不想突出数据，
      按「怎么挑」，每一点用时刻撑，不用数字撑。不追问"有没有留存率、日活、准确率"这类数据
- [ ] 说清这条路线为什么没有「数字」那一拍：那一拍要的是可被检验的证据，这里由**演示**、**取舍**、**机制**接替，
      演示能当场验、取舍能被反驳、机制能被追问
- [ ] 机制那一拍用「信号汇入」：照片、音乐、地点、活动四路输入 → 写作建议，
      并写清在哪处理、要不要授权
- [ ] 展开的**每一点用一个时刻撑**（能拍成十秒视频的场景），不是每点配一个数字，也不是每点配一个形容词；点数照旧由内容定
- [ ] 有「取舍」一拍：它故意不做什么（例如不做社交、不做排行），以及为什么
- [ ] 识别出这是**别人家的产品**：用第三人称，功能描述分层标注
      「官方说的 / 我实测的 / 我没验证的」
- [ ] 界面用占位图，不使用官方截图与 logo

**反例 / Must not**

- 不得为了每点配一个数字去编造，或从网上抓一个来路不明的数据
- 不得写成第一人称好像自己是苹果（"我们重新定义了记录"）
- 不得用"沉浸式""智能理解你的生活""让记录更轻松"这类拍不成视频的句子占一张片
- 不得把"数据在后台"说成技术限制或说成绝对优点，它是取舍
- 不得内嵌 Apple 的 logo、官方截图或产品渲染图

## Case 9: 形容词冒充内容

**输入 / Input**

用户给的材料里写：「产品提供沉浸式的写作体验，通过 AI 智能分析用户的生活，
让记录变得更轻松自然。」要求把这三条做成展开的三点。

**期望 / Expected**

- [ ] 指出这三条都拍不成十秒的视频，是形容词不是内容
- [ ] 对每条追问到可被检验的东西：
      「沉浸式」→ 界面上实际少了什么？
      「AI 智能分析」→ 输入是哪几类信号，在哪处理，输出是什么？
      「更轻松」→ 原来要做几步，现在要做几步？
- [ ] 材料不足以回答时**说清缺什么**，不自己补一个合理的说法
- [ ] 可以先给一版把三条改写成时刻的草案，并标明哪几处是待确认的假设

**反例 / Must not**

- 不得把这三句原样放大成单句大字
- 不得自己编造"它会分析你的心率和睡眠"这类材料里没有的机制
- 不得用"经过深度优化的智能引擎"这种更长的形容词替换更短的形容词

## Case 10: 片上文字的写作规则

**输入 / Input**

用户给的材料里有这几句，要求做成片：
「这不是一次简单的升级，而是对记录方式的重新定义。」
「我们精准识别用户痛点，形成了从记录到回顾的完整闭环。」
「效率提升约 37.2%。」（追问后用户承认是"感觉快了不少"，没实测）
最后用户说「再加一张谢谢观看」。

**期望 / Expected**

- [ ] 「不是 A，而是 B」句式改掉，说明这是发布会文案的套路句式
- [ ] 「痛点」「闭环」换成人话（卡在哪、形成完整流程）
- [ ] **37.2% 拒绝上片**：没实测过的数字不能带小数点。
      可以写"快了大约三分之一"，或者标【未确认】，或者不放
- [ ] 拒绝加「谢谢观看」片，说明讲的人会自己说，片上重复一遍是多余
- [ ] 片上文字里不出现破折号
- [ ] 说明这几条来自 `writing-rules`，**但不需要用户额外启用它**，
      片上文字始终按这几条走

**反例 / Must not**

- 不得把「重新定义」这类词原样放大成单句大字
- 不得把 37.2% 直接放上去，也不得四舍五入成 37% 后当作已核实
- 不得在片上用「——」表示停顿（要停顿就断行）
- 不得因为用户坚持就加「谢谢观看」而不说明理由

## Case 11: 三点式与 writing-rules

**输入 / Input**

用户读过 `writing-rules`，问："你的规则三说要打破三点式，为什么这个 PPT skill 里
到处都是三点展开、三格 bento、三条取舍？"

**期望 / Expected**

- [ ] 先读 `references/slide-copy-grammar.md` 里「与 `writing-rules` 的关系：三点式」再答（问起与 `writing-rules` 的关系，读取条件成立）
- [ ] 说清证据分两档：工作记忆有上限是 A 档，并列的点多了会过载；「至多三点」当讲稿规则只是推断，C 档。
      两者都推不出「必须凑够三个」
- [ ] 指出「三是最优数，都用三」是 Gallo 作为演讲教练的处方（B 档），本 skill 不采纳
- [ ] 因此正确说法是**点数由内容定，通常一到三点；三是参考上限、不是指标**：两点很常见，一点也行；
      多于三点先分组或拆章
- [ ] 说明这样两边不冲突：`writing-rules` 反对的是总是产出三个，本 skill 从不要求凑够三个，只把三当参考上限
- [ ] 仍提醒**视觉层面**的三：bento 三格、规格三列、取舍三条不要连着用；即使叙事只有两点，
      每张片都摆三个并列格子也会落进同一种惯性

**反例 / Must not**

- 不得说回「用三点」或「凑够三点」
- 不得把「至多三点」说成有 A 档依据的硬规则：A 档的只是工作记忆有上限
- 也不得因为 `writing-rules` 就把参考上限一起丢掉：点多了照样先分组或拆章
- 不得为了凑够三点编一个内容里没有的点
- 不得把 Gallo 的处方当成研究结论引用

## Case 12: 片上文字的句式

**输入 / Input**

用户要一张讲工作原理的片，材料是「应用会根据照片、音乐、地点和活动给出写作建议，
在设备上处理」。模型起草时给出的标题是「它凭什么知道该建议什么」，
下一张分隔片写「它怎么用这些信号」，正文里有一句「那首歌已经摆在那儿了。」

**期望 / Expected**

- [ ] 改写前读 `references/slide-copy-grammar.md`：禁／改例句和下面要说的依据都在那里
- [ ] 指出三处都不该出现在片上，并说清各自的病：
      第一句是**求解式提问**（问句在嘴里不在片上）；
      第二句是**文档小标题**；第三句是**口语**且**末尾多了句号**
- [ ] 标题改成名词短语（如「建议的来处」）
- [ ] 分隔片写不出一个名词就**删掉这张片**，不硬凑
- [ ] 中文标题末尾不加句号
- [ ] 讲机制时片上少写字，原理留给嘴讲
- [ ] 说明依据：苹果中英文页面的标题里都没有问句；2007 年那场片上是
      「A widescreen iPod with touch controls」，Jobs 嘴上才说「Does it do email?」

**反例 / Must not**

- 不得保留任何问句标题
- 不得把「它不做什么」这类问句形式当成片上标题（应为「取舍」）
- 不得用「摆在那儿」「搞定」「贼快」这类口语
- 不得给中文标题加句号
- 不得为了"显得完整"把名词短语改写成带动词的完整句

## Case 13: 产出格式的承诺

**输入 / Input**

用户问：「能不能直接给我一个 .key 文件，带 Magic Move 转场的？」

**期望 / Expected**

- [ ] 直说 `.key` 做不到：格式私有，没有库能写入；Keynote 的 AppleScript 能新建片、设转场、存成 .key，但字典里没有跟出场顺序有关的类，动画建不出来
- [ ] 给出唯一通路：生成 pptx 再由 Keynote 导入
- [ ] 说明 pptx 这条路带动画：讲到才出现、讲过的调暗、讲到的点名，相邻两片的同一个对象用 Morph（平滑）切换，这是 PowerPoint 里最接近 Magic Move 的转场

情形四：（片子已经出过一版）「底色太素了，能不能加点光效？标题后面来一团光晕，再铺一层颗粒，看着高级一点。」

**期望 / Expected**

- [ ] 情形一：底色不用先问，也不留黑，默认用匹配色。来源是品牌色（使用者没指定别的颜色），发布会语气饱和度约 0.45，
      色值用 `--palette` 算：`--palette "#1f6f8b" --sat 0.45 --accent "#1f6f8b"` 打出底色 #1b3b46；
      脚本报的提亮（品牌色直接当重点色只有 2.10:1，提亮成 #3faed4，4.67:1）照实写进大纲。
      「主色与底色」写颜色名与色值、为什么匹配、脚本打出的「对比度：」那一行
- [ ] 情形二：没有指定的颜色，没有品牌色，代码评审也没有说得通的颜色联想，就用黑色。
      「主色与底色」写「底色：黑色（没有合适的匹配色）」，导 pptx 时片单不写 `"background"`；不硬凑一个牵强的联想
- [ ] 情形三：亮教室用浅色 `#f5f5f7`（近白，不用纯白）；内容的颜色联想（植物 → 深绿）不丢：匹配色只上封面、分节、静场的色场，
      重点色压暗到浅底上过 4.5:1，值照 `--palette`（种子色深绿 `#4f9a62`）打出的「亮教室」那两行；
      导 pptx 时写 `"theme": "light"` 加 `"background"`（匹配色），不能只写 background 而漏掉 theme，那样整套会是深绿底
- [ ] 情形四：不加光晕和颗粒，说明原因：光晕加颗粒正是 AI 生成的片子最常见的样子；苹果舞台上的片底以平涂为主（B 档），
      Keynote 自带主题也是（A 档）。给出能做的：整套换成匹配色，或者按章节换色（一个章节内不换）；
      封面、分节、静场可以用色场或柔和渐变（单色相、单方向，字放在暗的那一侧），内容片照旧平涂；
      用渐变前在现场投影上看一眼有没有色带，有就改平涂

**反例 / Must not**

- 不得用白底加紫色或靛蓝渐变那一套
- 不得把色场、渐变或巨字用到内容片上
