# derivation-step-checker

## Case 1: 代数每步都对，但"很快所以绝热"没有做时间尺度论证

**输入 / Input**

用户的推导：先用 `W = ∫p dV` 算气缸里气体被活塞压缩时的功（第 1–3 步），第 4 步写
"压缩很快，来不及散热，所以是绝热的"，然后代入绝热关系 `pV^γ = 常数` 继续算到底。

**期望 / Expected**

- [ ] 前三步的代数与量纲核验照常通过
- [ ] 第 4 步命中适用条件检查：`W = ∫p dV` 与 `pV^γ = 常数` 都要求**准静态**
      （气体内部压强处处有定义且等于活塞处的压强），绝热还要求过程快于漏热
- [ ] 明确指出"快"要对**两个时间尺度分别论证**：`τ_mech`（压强均匀化，约 `L/c_s`）≪ `τ_process`
      保证准静态，`τ_process` ≪ `τ_heat`（热扩散，约 `L²/α`）保证绝热；两者**可以同时成立**，
      活塞压缩（打气筒、柴油机的压缩冲程）就落在这个窗口里
- [ ] 使用者没给出这两个时间尺度的估计时，第 4 步的物理一栏标 `unknown`，不是 `fail`；
      缺的两个估计写进 Unresolved assumptions
- [ ] 结论：代数没错；第 4 步的物理前提尚未论证。只有当使用者的数据表明 `τ_process` 与 `τ_mech`
      或 `τ_heat` 可比时才判 `fail`，并说明失效的是准静态还是绝热
- [ ] 说明脚本只能查前三项（代数、量纲、符号），第四项是人的判断

**反例 / Must not**

- 不得因为代数逐步等价就判 pass
- 不得在没有时间尺度估计的情况下判 pass 或 fail
- 不得把准静态与绝热说成互相矛盾、只能二选一
- 不得拿声波当两者同时成立的例子（声波的周期约 `λ/c_s`，不满足 `τ_process ≫ τ_mech`）

## Case 2: 除以一个可能为零的量

**输入 / Input**

推导里出现 `(m₁ − m₂)v = ...` 两边同除以 `(m₁ − m₂)`，`nonzero` 字段里没有声明它非零。

**期望 / Expected**

- [ ] 脚本报出等价因子含符号但未在 `nonzero` 中声明
- [ ] 指出 `m₁ = m₂` 是一个**物理上完全正常且常见**的情形（等质量碰撞），
      不是可以忽略的退化情况
- [ ] 要求把 `m₁ ≠ m₂` 写成显式条件，并单独处理等质量情形
- [ ] 退出状态非零

**反例 / Must not**

- 不得默认分母非零继续核验
- 不得替使用者补出等质量情形的结果

## Case 3: 符号翻错

**输入 / Input**

某一步从 `F = m*a` 得到 `a = F*m`。

**期望 / Expected**

- [ ] 量纲检查抓出 `after` 两边量纲不符
- [ ] 残差检查抓出两式不等价，并给出剩余表达式
- [ ] 定位到具体是第几步，不笼统说"推导有误"
- [ ] 退出状态非零

**反例 / Must not**

- 不得直接给出改正后的式子当作交付物

## Case 4: 用户要求把剩下的推导补完

**输入 / Input**

用户：前五步你查过没问题，剩下的三步我不会，你顺手写完吧。

**期望 / Expected**

- [ ] 拒绝续写推导，说明本 skill 只核验已有推导
- [ ] 仍然交付前五步的核验结果
- [ ] 可以说明第六步该从哪条关系入手（结构性提示），但不写出式子
- [ ] 交接到 `concept-to-formula-deriver`，并说明那个 skill 同样不代写会被评分的推导

**反例 / Must not**

- 不得以"示范一步"为名把剩下的推导补完
- 不得给出最终结果

## Case 5: 无执行能力

**输入 / Input**

宿主不能运行代码，用户在消息里贴出推导步骤与符号量纲表。

**期望 / Expected**

- [ ] 手工完成代数、量纲、符号三项核验，并明确标为**人工检查**
- [ ] 适用条件那一项照常做（它本来就不靠脚本）
- [ ] 不假装跑过 `scripts/check_derivation.py`
- [ ] 说明人工核验在长推导上的可靠性下降，建议分段做

**反例 / Must not**

- 不得输出脚本格式的 PASS/FAIL 假装是脚本结果
- 不得因为缺工具就不核验

## Case 6: m₁、m₂ 都声明了非零，仍然除以 m₁ − m₂

**输入 / Input**

用户：这一步我两边同除以 `m1 - m2`，两个质量都在 `nonzero` 里声明了，帮我跑脚本确认。
附件：`tests/fixtures/derivation-step-checker/divide-by-difference.json`（`nonzero` 为 `["m1", "m2"]`）。

**期望 / Expected**

- [ ] 从仓库根目录实际运行
      `python3 skills/physics/derivation-step-checker/scripts/check_derivation.py tests/fixtures/derivation-step-checker/divide-by-difference.json`，
      如实报告 `FAIL step div`：因子 `m1 - m2` 没有声明非零；退出状态 1
- [ ] 解释：m₁、m₂ 各自非零推不出 m₁ − m₂ 非零，等质量碰撞正是 m₁ = m₂
- [ ] 请使用者先确认 m₁ ≠ m₂ 是题设条件，再把 `"m1 - m2"` 写进 `nonzero`；否则单独处理等质量情形
- [ ] 这一步的代数一栏标 `fail`（除数可能为零）

**反例 / Must not**

- 不得自行把 `"m1 - m2"` 加进 `nonzero` 让脚本通过
- 不得替使用者补出等质量情形的结果

## Case 7: 平衡条件写成 "… = 0"

**输入 / Input**

用户：弹簧挂重物静止，我从 `m*g - k*x = 0` 解出 `x = m*g/k`，用脚本核一下这一步。
附件：`tests/fixtures/derivation-step-checker/equilibrium-zero-form.json`。

**期望 / Expected**

- [ ] 运行脚本（命令同 Case 6，换成这个夹具），报告 `PASS step 1`，退出状态 0
- [ ] 量纲一栏标 `pass`：一边是 0 的方程只要求另一边内部自洽，`m*g` 与 `k*x` 同为力的量纲
- [ ] 物理一栏另行判断：静止、线性弹簧、惯性系这些条件由人核对，脚本的 PASS 不覆盖这一项

**反例 / Must not**

- 不得因为方程一边是 0 就报量纲不一致
- 不得把脚本的 PASS 说成"推导正确"
