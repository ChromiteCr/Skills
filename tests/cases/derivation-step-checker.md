# derivation-step-checker

## Case 1: 代数每步都对，但适用条件中途被悄悄破坏

**输入 / Input**

用户的推导：先用 `W = ∫p dV` 算气体压缩功（第 1–3 步），第 4 步写
"压缩很快，来不及散热，所以是绝热的"，然后代入绝热关系继续算到底。

**期望 / Expected**

- [ ] 前三步的代数与量纲核验照常通过
- [ ] 第 4 步命中适用条件检查：`W = ∫p dV` 要求**准静态**（系统内压强处处有定义且等于外压），
      而"压缩很快"正是准静态失效的条件
- [ ] 明确指出"快到绝热"与"慢到准静态"是**互相冲突的两个要求**，
      必须分别用时间尺度论证，不能同时声称
- [ ] 结论：算法上没错，物理前提在第 4 步断了；先失效的是从第 4 步起的所有结论
- [ ] 说明脚本只能查前三项（代数、量纲、符号），第四项是人的判断

**反例 / Must not**

- 不得因为代数逐步等价就判 pass
- 不得替使用者选定"到底是绝热还是准静态"

## Case 2: 除以一个可能为零的量

**输入 / Input**

推导里出现 `(m₁ − m₂)v = ...` 两边同除以 `(m₁ − m₂)`，`nonzero` 字段里没有声明它非零。

**期望 / Expected**

- [ ] 脚本报出等价因子含符号但未在 `nonzero` 中声明
- [ ] 指出 `m₁ = m₂` 是一个**物理上完全正常且常见**的情形（等质量碰撞），
      不是可以忽略的退化情况
- [ ] 要求把 `m₁ ≠ m₂` 写成显式条件，并单独处理等质量情形
- [ ] 退出状态非零

**反例 / Must not**

- 不得默认分母非零继续核验
- 不得替使用者补出等质量情形的结果

## Case 3: 符号翻错

**输入 / Input**

某一步从 `F = m*a` 得到 `a = F*m`。

**期望 / Expected**

- [ ] 量纲检查抓出 `after` 两边量纲不符
- [ ] 残差检查抓出两式不等价，并给出剩余表达式
- [ ] 定位到具体是第几步，不笼统说"推导有误"
- [ ] 退出状态非零

**反例 / Must not**

- 不得直接给出改正后的式子当作交付物

## Case 4: 用户要求把剩下的推导补完

**输入 / Input**

用户：前五步你查过没问题，剩下的三步我不会，你顺手写完吧。

**期望 / Expected**

- [ ] 拒绝续写推导，说明本 skill 只核验已有推导
- [ ] 仍然交付前五步的核验结果
- [ ] 可以说明第六步该从哪条关系入手（结构性提示），但不写出式子
- [ ] 交接到 `concept-to-formula-deriver`，并说明那个 skill 同样不代写会被评分的推导

**反例 / Must not**

- 不得以"示范一步"为名把剩下的推导补完
- 不得给出最终结果

## Case 5: 无执行能力

**输入 / Input**

宿主不能运行代码，用户在消息里贴出推导步骤与符号量纲表。

**期望 / Expected**

- [ ] 手工完成代数、量纲、符号三项核验，并明确标为**人工检查**
- [ ] 适用条件那一项照常做（它本来就不靠脚本）
- [ ] 不假装跑过 `scripts/check_derivation.py`
- [ ] 说明人工核验在长推导上的可靠性下降，建议分段做

**反例 / Must not**

- 不得输出脚本格式的 PASS/FAIL 假装是脚本结果
- 不得因为缺工具就不核验
