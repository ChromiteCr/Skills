# lyric-doctor

## Case 1: 一份满足格式但很套路的稿子

**输入 / Input**

用户贴出一段成稿，含这样的句子：

```
副歌
晚风轻轻把你拥抱
抚平你身上所有煎熬
那些受过的伤 都会变成星光
不用追着别人的步调
你本来的样子就很好
你已经做得很好了
```

用户提问：帮我看看这词有什么问题，总觉得像 AI 写的。

**期望 / Expected**

- [ ] **先跑 `scripts/lyric_check.py`**，不用眼睛数字数
- [ ] 报出脚本查到的陈词命中（晚风、拥抱、煎熬、星光、都会变成、不用、本来的样子）
- [ ] 再做脚本做不了的判断：韵辙是否统一、画面感比例、hook 是否成立
- [ ] 指出"你已经做得很好了"这类**不含黑名单词、脚本没有命中**但同样空洞的句子（这一行脚本输出里没有 ⚠，只能靠逐行判断）
- [ ] 修改清单按严重程度排序，每处给两三个**方向**而非成句
- [ ] 明确列出写得好的、不用改的行

**反例 / Must not**

- 不得直接交出一份重写好的完整歌词
- 不得只说"感觉不够高级""可以再走心一点"这类没有落点的评价
- 不得把脚本输出整段粘贴当成分析
- 不得因为"押韵没问题"就说这首词没问题

## Case 2: 判断 hook 是否成立

**输入 / Input**

用户提问：我这首副歌到底有没有记忆点？

**期望 / Expected**

- [ ] 派一个 sonnet 子代理做陌生听众初听测试
- [ ] 只给子代理**歌词正文**，不给主题说明、概念卡、任何背景
- [ ] 让它回答：记住了哪一句、这首歌在讲什么、情绪终点是什么
- [ ] 根据它的回答判断：记不住任何一句 = hook 不成立；
      主题偏差大 = 问题在概念层，指回 `lyric-concept-builder`

**反例 / Must not**

- 不得主 Agent 自己判断"我觉得这句挺抓耳的"
- 不得把主题和创作意图一起喂给做初听测试的子代理

## Case 3: 边界 —— 笨拙但真实的句子

**输入 / Input**

用户的稿子里有一行明显不工整、口语得近乎笨拙，但写的是他自己的真事。
同时另有一行为了押韵倒装成了书面语。

**期望 / Expected**

- [ ] 保留那句笨拙但真实的行，可以指出它不工整，但说明它是全篇最值钱的句子
- [ ] 指出倒装那一行的问题，给出改法方向
- [ ] 字数与意思冲突时，两个方案都摆出来让用户决定牺牲哪个

**反例 / Must not**

- 不得把那句真话改成通顺漂亮的套话
- 不得为了整体统一而把口语行全部书面化
- 不得替用户决定"这里意思更重要"

## Case 4: 带字数模板，段落名和模板写法不同，段落重复

**输入 / Input**

模板 `tests/fixtures/lyric-doctor/repeat-template.txt`（段落名写「主」「副」，每种段落只写一遍）：

```
主
xxxxxxxxx
xxxx xxxxx

副
xxxxxxx
xxxxxxx xxxx
```

歌词 `tests/fixtures/lyric-doctor/repeat-lyrics.txt`（主歌、副歌各唱两遍，段落名写成「主歌 1」「【副歌】」「主歌 2」「副歌」）：

```
主歌 1
我把外套搭在椅背上
灯还亮着 楼下的面馆

【副歌】
今天我出了门
拎着橘子往回走 路灯亮了

主歌 2
那条消息我看了六遍还是没有回
电话那头 老家在下雨

副歌
今天我出了门
走到路口又站了很久 才想起要回家
```

用户提问：帮我看看字数和模板对不对得上。

**期望 / Expected**

- [ ] 带 `--template` 跑 `scripts/lyric_check.py`；段落名照原样存盘，不手工改成「主」「副」
- [ ] 报出脚本查到的两处超字：主歌 2 第 1 行 14 字（模板 9，多 5），第二遍副歌第 2 行 15 字（模板 11，多 4）；机械问题 2 处
- [ ] 说明重复出现的主歌 2 和第二遍副歌也按模板比对过，"今天我出了门"少 1 字在 ±1 内
- [ ] 两处超字按修改清单的格式给两三个改法方向，不给成句；字数和意思冲突时两个方案都摆出来
- [ ] 脚本若报某段"模板里没有对应的段落"，先改段落名或问用户这段对应模板哪一段，再重跑

**反例 / Must not**

- 不得只比对第一遍主歌和副歌，就说"字数全中"
- 不得用眼睛数字数，也不得在脚本报段落对不上时自己按位置硬配
- 不得直接交出改好字数的整段歌词
