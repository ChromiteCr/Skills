# lyric-structure-mapper

## Case 1: 解析用户给的模板

**输入 / Input**

```
主
xxxxxxxxxx
xxxxxxxxxx
xxxxxx
xxxxxxxxx

预副
xxxxxxxx
xxxxx xxxxx
xxxxxxxx
xxxx xxxxx

副
xxxxxxx
xxxxxxx xxxx
xxxxxxx
xxxxxx
xxxxxxx xxxx
xxxxxxxx
xxxxxxxx
xxxxxxx xx
```

用户提问：按这个结构写，每句字数可以细微变动，每个板块尽量押韵。

**期望 / Expected**

- [ ] **逐行数 x**，给出每行的准确字数，不目测
- [ ] 把空格解析成停顿，标出分段字数（如 `5+5`）
- [ ] 把"细微变动"落实为 ±1 字，并说明同段对应行必须同长
- [ ] 每段标出功能（主歌=建立处境，预副=收窄抬升，副歌=hook 与顶点）
- [ ] 给出押韵方案，副歌指定开口辙
- [ ] 写明主歌二相对主歌一要变的是哪一项
- [ ] 给总字数与时长估算
- [ ] **不派子代理**，并说明这是确定性工作

**反例 / Must not**

- 不得在骨架表里写示例句子
- 不得擅自调整用户给的字数
- 不得为了"更合理"增删行数
- 不得派 sonnet 子代理来数 x

## Case 2: 没有模板

**输入 / Input**

用户提问：我想写一首三分钟左右的歌，不知道各段该写几句。

**期望 / Expected**

- [ ] 给出两到三个常用骨架，各自说明适合什么
- [ ] 每个骨架带具体行数与字数，不只给段落名
- [ ] 结合三分钟的时长给出总字数量级
- [ ] 提示还需要知道这首歌写什么，指向 `lyric-concept-builder`

**反例 / Must not**

- 不得只回答"主歌四句副歌四句"这种没有字数的结构
- 不得给出五个以上的骨架让人挑花眼
- 不得直接开始填词

## Case 3: 模板里段落名缺失

**输入 / Input**

用户只贴了几组 x，没有写段落名，行长明显分成两组。

**期望 / Expected**

- [ ] 按行数和行长推断段落功能
- [ ] **把推断说出来让用户确认**，不当作定论直接往下走
- [ ] 指出其中字数异常的行（比如某段第三行比同位置的行短很多），问是不是有意为之

**反例 / Must not**

- 不得默认第一段就是主歌、第二段就是副歌然后直接产出骨架表
- 不得为了补齐结构自行添加一个桥段
