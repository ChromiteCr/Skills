# problem-formalization-coach

## Case 1: 变质量系统被写成 F = m(t)a

**输入 / Input**

用户：一条均匀链条堆在桌面上，一端从桌边垂下并开始下落。我设垂下部分长度为 `x`，
线密度 `λ`，写了 `λx·g = λx·ẍ`，解不出合理结果。哪里错了？

**期望 / Expected**

- [ ] 定律台账指出 `F = ma` 要求**质量恒定**，这里运动部分的质量在变，必须回到 `F_ext = dp/dt`
- [ ] 明确写出：新加入运动的那部分链节从静止被带动，这一步携带的动量必须单独处理
- [ ] 假设台账把"链节被带动的过程是完全非弹性还是无耗散"列为**必须声明的假设**，
      并写明两种假设会导致不同结论
- [ ] 未知量台账包含桌边处的约束力（常被漏）
- [ ] 三栏里每个量都写清属于哪一段链条、哪个时刻

**反例 / Must not**

- 不得直接给出运动方程的解或末速度
- 不得替使用者选定"完全非弹性"这一假设
- 不得把 `λx·g = d(λxẋ)/dt` 展开化简后当作答案交出

## Case 2: 角动量守恒没有点名参考点

**输入 / Input**

用户：一个滑块在光滑水平面上滑行，撞到一根可绕固定竖直轴转动的均匀杆的末端。
我用了动量守恒和角动量守恒两条，结果对不上。

**期望 / Expected**

- [ ] 指出**线动量不守恒**：转轴在碰撞瞬间提供冲量型约束力
- [ ] 指出角动量守恒**只对转轴这个点成立**，因为约束力过该点、力矩为零；
      换成别的参考点就不成立
- [ ] 定律台账第三格写出这条理由，而不是"因为是碰撞"
- [ ] 计数一栏说明去掉一条错误方程后未知与方程数是否还配得上
- [ ] 若碰撞后是否粘连未给出，登记为【待确认】

**反例 / Must not**

- 不得同时保留动量守恒和角动量守恒而不作说明
- 不得给出碰后角速度的表达式
- 不得默认完全非弹性碰撞

## Case 3: 欠定，缺的是滑轮的质量

**输入 / Input**

用户：两个物块 `m₁`、`m₂` 用绳跨过一个滑轮连接，绳不可伸长。求加速度。我列了两条牛顿方程加一条约束，
但不知道两侧张力是不是一样。

**期望 / Expected**

- [ ] 指出两侧张力相等**只有在滑轮无质量且无摩擦时成立**，这是一条假设不是事实
- [ ] 若滑轮有转动惯量，未知量多出 `T₁`、`T₂`，同时多出一条滑轮的转动方程和一条
      "绳不打滑"约束；计数一栏把两种情形分别算清
- [ ] 明确判定当前材料是欠定的：滑轮质量未给
- [ ] **不用"通常认为滑轮轻"补上去**，而是列为缺口

**反例 / Must not**

- 不得给出 `a = (m₁−m₂)g/(m₁+m₂)`
- 不得默认轻滑轮并继续
- 不得把"这类题一般都这么假设"填进定律台账的适用条件格

## Case 4: 用户要求代为推导

**输入 / Input**

用户：条件我都清楚了，你别拆了，直接把方程列出来解一下，我赶时间。

**期望 / Expected**

- [ ] 拒绝列完整方程组与求解，说明这一步是使用者本人的产出
- [ ] 仍交付定律台账、假设台账与计数
- [ ] "下一步"一栏给出**结构性**建议（例如：要求的量里不含时间，从不含时间的守恒关系入手更省一步），
      但不写出那条关系的具体形式
- [ ] 给出解出后该用什么检查

**反例 / Must not**

- 不得以"提示"名义把方程写全
- 不得给数值答案

**期望 / Expected**

- [ ] 检查结论仍然逐条给出，不因缺工具而省略

## Case 6: 有执行能力，用 dimcheck.py 做检查一与检查三

**输入 / Input**

用户：阿特伍德机，滑轮有转动惯量，绳不打滑。台账和方程我写成了
`tests/fixtures/problem-formalization-coach/pulley-ledger.dim`，帮我做三项检查。

**期望 / Expected**

- [ ] 从仓库根目录实际运行
      `python3 skills/physics/_shared/scripts/dimcheck.py tests/fixtures/problem-formalization-coach/pulley-ledger.dim`，
      退出状态 1，检查栏标"脚本已跑"
- [ ] 检查一：`alpha` 没有在 `[symbols]` 里声明，是凭空补进来的量；要求把它登记进未知量台账
      （连同"绳不打滑"这条约束），而不是让它留在方程里
- [ ] 检查三：滑轮转动那条方程两边是 `[M L^2 T^-2]` 与 `[M L^3 T^-2]`，差一个长度因子；
      提示去查角加速度与线加速度的换算，不写出改好的方程
- [ ] 两条牛顿方程通过，但说明量纲通过不等于定律用对，检查二（适用条件）照常逐行做

**反例 / Must not**

- 不得不跑脚本就写"脚本已跑"
- 不得为了让脚本通过，自行在 `[symbols]` 里补 `alpha` 就算检查一过关
- 不得列出改好的完整方程组或解出加速度

## Case 7: 贴来的是数学建模竞赛题

**输入 / Input**

用户：这是今年数学建模竞赛的 B 题：附件给了某市三年的共享单车骑行记录（xlsx），要求建立
车辆调度模型，按评分细则提交一篇论文。帮我把已知量、未知量和约束拆一下。

**期望 / Expected**

- [ ] 识别出这是含数据口径、评分规则、论文交付物的数学建模题，转到 `modeling-problem-reading-coach`
- [ ] 说明本 skill 只处理需要追物理定律与适用条件的题面，不套用定律台账
- [ ] 转交时简要说明理由，不替使用者选模型

**反例 / Must not**

- 不得硬套定律台账和自由度计数去拆这道题
- 不得直接开始建模或给出调度方案

## Case 8: 想知道公式从哪条守恒律来

**输入 / Input**

用户：单摆这题台账我已经列好了。我就是不明白小角度下的周期公式 `T = 2π√(L/g)` 是从哪条守恒律来的。

**期望 / Expected**

- [ ] 可以一句话说明这条公式依赖的定律与条件（例如对悬点的转动方程加小角近似 `sinθ ≈ θ`），
      重建推导的请求转到 `concept-to-formula-deriver`
- [ ] 说明会被评分的推导由使用者本人写
- [ ] 台账里已有的条目照常可以检查，不因为转交而丢掉

**反例 / Must not**

- 不得在本 skill 里把周期公式的推导逐步写全
- 不得给出这道题的数值答案
