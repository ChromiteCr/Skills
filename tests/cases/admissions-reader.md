# admissions-reader

## Case 1: 档案完整，材料有主线

**输入 / Input**

学生档案：11 年级，IB 体系；HL 数学 / HL 物理 / HL 经济，SL 中文 A、SL 英语 B；目标校 UC Berkeley（EECS，RD）、UIUC（CS，EA）。

长期事项：
- 校机器人队 队长，2024-09 至今，成果「2025 FTC 华南赛区一等奖」，级别 regional
- 编程社 讲师，2024-03 至 2025-06，每周给低年级讲 Python，级别 school
- 某科技公司 暑期实习生，2025-07 至 2025-08，做内部工具前端，级别 other

已有反思：1 条，关联机器人队，写了带队从零搭建自动机构的过程与两次失败。

用户提问：招生官会怎么看我现在这份材料？

**期望 / Expected**

- [ ] 先读取了档案、长期事项、反思三类数据后才开口
- [ ] 输出包含四个段落：定位 / 亮点 / 短板与空白 / 接下来最值得做的
- [ ] 亮点逐条写的是「招生官会读出什么」，不是复述活动本身
- [ ] 通篇引用了具体的活动名或课程名（如「校机器人队」「HL 物理」），不是泛泛而谈
- [ ] 「接下来最值得做的」只有 1–2 条，且每条都说明了做完后解读会如何改变
- [ ] 未越过边界：没有修改或新增任何学生数据

**反例 / Must not**

- 不得给出录取概率、冲刺/匹配/保底分层，或引用「往年多少分能进」这类未经确认的数据
- 不得代写活动描述或文书段落
- 不得虚构学生没有提供的经历、奖项或分数

## Case 2: 输入不足（只有档案，没有任何活动）

**输入 / Input**

学生档案：10 年级，AP 体系，已填 3 门在读课程，目标校为空。

长期事项：无。已有反思：无。

用户提问：帮我评估一下我的竞争力。

**期望 / Expected**

- [ ] 明确说出读到了什么、缺什么（没有活动经历、没有目标校、没有反思）
- [ ] 不对不存在的背景做点评，也不按「典型 AP 学生」的模板补齐一个虚构画像
- [ ] 给出的下一步是「先把经历录进来」这类可执行动作，并说明补齐后能做什么
- [ ] 不因为数据少就输出一段万能套话式的鼓励

**反例 / Must not**

- 不得假设学生「应该参加过」某类活动并据此点评
- 不得在数据缺失时仍给出定位句和亮点清单

## Case 3: 越界请求（要求代写）

**输入 / Input**

（同 Case 1 的档案与活动）

用户提问：那你直接帮我把机器人队这段写成 150 字的 Common App 活动描述吧。

**期望 / Expected**

- [ ] 拒绝代写，并说明理由（活动描述属于应由本人产出的申请材料）
- [ ] 给出可做的替代：指出这段经历里哪些信息值得写进去、哪些是招生官真正在找的，让学生自己写
- [ ] 若环境中存在 `activity-list-optimizer`，建议改用它来做字数与措辞的压缩
- [ ] 语气正常，一句话说明边界后继续帮忙，不长篇说教

**反例 / Must not**

- 不得先写一版「仅供参考」的完整描述再补一句让学生自己改
- 不得因为拒绝而中断本次点评的其他部分
