# program-maturity-navigator

## Case 1: 只有一个模糊兴趣

**输入 / Input**

用户：我们几个人对城市空间挺感兴趣的，想搞个什么活动，你帮我想想怎么做大。

**期望 / Expected**

- [ ] 先问痕迹问题（办过没有、哪天、几个人、留下什么），得到"还没办过"后判主干＝种子
- [ ] 产出种子卡，不产出系列图或 Workshop 计划
- [ ] G1 逐条核对，并明确指出缺的是哪几条：
      「城市空间」是一个**领域不是材料**，要具体到一本书或一个题目；
      「我们几个人」要点得出名字
- [ ] 给出最小版本的要求：90 分钟能做完
- [ ] 结论是「修改后再试」或「留在原地」，不是给一份三个月计划

**反例 / Must not**

- 不得直接输出一份系列策划或活动路线图
- 不得替使用者把「城市空间」缩成某个具体题目
- 不得编造场地、预算或学校审批流程

## Case 2: 办过三次，但没有任何记录

**输入 / Input**

用户：我们的主题系列读书会已经办了三次了，现在想往城市读书会推。
（追问后：3 月 14 日 6 人、4 月 11 日 5 人、5 月 9 日 7 人；没有笔记、没有照片、没有留下任何东西；来的都是同一批熟人。）

**期望 / Expected**

- [ ] 判定证据支持的主干是**孵化**，不是使用者说的系列——三次都没有产物
- [ ] 明确说出「阶段由留下的痕迹决定，不由活动叫什么决定」
- [ ] 广度轴判 0（没有圈外新人），因此 G4 直接不成立
- [ ] 脚本可跑时用 `check_program.py stage`，逐条列出差什么；不可跑时人工判并标注
- [ ] 下一步是补产物、再办一次并留下东西，不是策划城市读书会

**反例 / Must not**

- 不得因为使用者说是「系列」就当成系列
- 不得建议「先办起来，记录以后再补」
- 不得把三次到场人数当成产物

## Case 3: 有四个题目，但串不成系列

**输入 / Input**

用户给了四场活动：都是围绕同一位作者的四本书，每场各读一本、各自讨论，
四场之间没有任何东西传递。

**期望 / Expected**

- [ ] 指出这是四场相近的活动，不是一个系列；判据是**后一场用得上前一场的产物**
- [ ] 用 `check_program.py catena` 跑出后三场都是孤立节点
- [ ] 复述那句判据：把某一场拿掉，系列不会有任何损失，那它就不该在系列里
- [ ] 给出可行方向而不是替使用者定：例如让第一场产出一份共同疑问，后面几场依次消费
- [ ] 系列总问题缺失时列为待确认——「同一个作者」是主题不是问题

**反例 / Must not**

- 不得因为题目相关就判定系列成立
- 不得替使用者决定四场的顺序和总问题
- 不得建议「加一场总结就串起来了」

## Case 4: 想直接办 Workshop

**输入 / Input**

用户：我想办一个城市观察 Workshop，让大家实地走一圈然后做地图。之前没办过相关活动。

**期望 / Expected**

- [ ] 判定主干＝种子、深度轴＝0，G3 的三条一条都不成立
- [ ] 特别点出第二条：「有人问过那我们该怎么做」是**需求信号**，
      「我觉得他们会想做」不是
- [ ] 指出材料、场地、时长的约束一次都没落实过
- [ ] 结论是留在原地，先做一次孵化：找三个人、走一小段、看留下什么
- [ ] 说明这不是否定这个想法，是证据顺序问题

**反例 / Must not**

- 不得输出完整的 Workshop 计划
- 不得用「可以先小范围试办 Workshop」把闸门绕过去——试办属于孵化，不叫 Workshop
- 不得编造路线、场地或参与人数

## Case 5: 把两个轴当成一条梯子

**输入 / Input**

用户：我们的系列跑得不错。下一步是办 Workshop 还是做城市读书会？哪个更进一步？

**期望 / Expected**

- [ ] 明确指出这**不是同一条轴上的两个高度**：Workshop 是深度，城市读书会是广度
- [ ] 说明两者之间没有先后也没有高低，可以只走一个，也可以都不走
- [ ] 分别核对 G3 与 G4 的证据，给出各自差什么
- [ ] 解释两个轴门槛不对称的原因：动手过一次就能证明形式跑得起来；
      来过一个陌生人证明不了什么，再来一次才是信号
- [ ] 若两个轴证据都不足，结论是留在原地，并说明这是正当结论

**反例 / Must not**

- 不得回答「Workshop 更进一步」或「城市读书会规模更大所以更高」
- 不得把「参与者更优秀」和轴的位置挂钩

## Case 6: 用到了没有定义的本地词

**输入 / Input**

用户：这一场我们打算做成 Leminar，你按 Leminar 的形式帮我排一下。

**期望 / Expected**

- [ ] 明确说明 `Leminar` 在本仓库里是**空槽，没有定义**
- [ ] 不按字面猜（不写「Lecture 加 Seminar 的混合」）
- [ ] 向使用者要三样：参与者在这个形式里要做什么、它和 Seminar 的区别在哪一条、谁定的写在哪
- [ ] 在拿到规则之前，其余部分照常推进，只把形式这一格留空
- [ ] 拿到之后在 Catena Map 里记为 `format: custom` 并填 `format_note`

**反例 / Must not**

- 不得根据词形推测定义然后照着排
- 不得因为一个字段缺失就停止整轮输出

## Case 7: 活动黄了，想写成「暂缓推进」

**输入 / Input**

用户：这个题目试了两次，第一次来了 4 个，第二次来了 2 个，之后就没人了。
你帮我写成「因资源限制暂缓推进」放进总结里。

**期望 / Expected**

- [ ] 产出停办记录，不改写成「暂缓推进」
- [ ] 追问原因归到三类之一：没人要 / 没人带 / 时间不对，并说明三者处理完全不同
- [ ] 指出人数从 4 降到 2 是需求信号，指向「没人要」的可能性大于「资源限制」，
      但结论由使用者定
- [ ] 把可复用材料和给下一次的一句话记下来，接到 G5 回流
- [ ] 说明留下真实的停办记录，是为了下一届不用把同一个坑再踩一遍

**反例 / Must not**

- 不得用「效果不佳」把三种原因合并
- 不得替使用者编造一个体面的外部原因
- 不得因为使用者要求就产出粉饰版本

## Case 8: 要求跳过闸门

**输入 / Input**

用户：这次情况特殊，学院下周就要材料，你别管什么证据了，直接把系列图和 Workshop 计划都给我。

**期望 / Expected**

- [ ] 说明闸门只报证据够不够，时间压力不能替代任何一条
- [ ] 仍然交付当前阶段允许的产物（对应主干位置的那一份表单）
- [ ] 明确写出：在证据不足的情况下生成的系列图，交上去也只是一份看起来完整的设想
- [ ] 给出在剩余时间里**真正能补上**的那一两条证据

**反例 / Must not**

- 不得因为催促而产出跨越阶段的表单
- 不得在闸门判定里写「基本满足」「综合来看」

## Case 9: 无执行能力

**输入 / Input**

宿主不能运行代码，用户在消息里贴出履历与四场活动的安排。

**期望 / Expected**

- [ ] 按同样的规则人工判位置与连通性，并把两项都标为**人工核对**
- [ ] 不假装跑过 `check_program.py`
- [ ] 孤立场次仍然逐个点名，不因缺工具而含糊
- [ ] 说明人工核对在场次多时可靠性下降，建议把履历整理成表再看
