# launch-summary-panel

## Case 1: 正常两阶段

**输入 / Input**

用户贴出一段产品规格摘录（约 40 行），含屏幕、影像、性能、电池、结构几节，
然后说：帮我做一张产品总结面板。

**期望 / Expected**

- [ ] 只问两件事：面向谁、有没有必须出现或必须回避的说法
- [ ] **先产出 `panel-brief.md`**，这一轮不写任何 HTML
- [ ] brief 里核心卖点 3 到 5 条、支撑卖点 6 到 12 条
- [ ] 每条卖点带出处；材料里没有的标【未确认】
- [ ] 数字锚点表里限定条件照抄（"22 小时视频播放"不写成"22 小时续航"）
- [ ] 信息分组按材料实际有的分，不硬凑八个组
- [ ] 有版式建议：hero 放什么、哪条上最大卡、哪几条上大卡
- [ ] **有舍弃项和舍弃原因**
- [ ] 写完停下等确认
- [ ] 确认后才产出单文件 `panel.html`，1600×900、内联 CSS、无外部资源
- [ ] 层级三档拉开，最大卖点只有一个
- [ ] 默认 light，切换按钮在舞台外
- [ ] 卡片圆角都在 16–24px 之间，小规格卡也一样（模板里大卡 22px、小规格卡 16px）

**反例 / Must not**

- 不得在第一轮里同时给出 brief 和 HTML
- 不得省掉舍弃项那一块
- 不得引入外部字体、图标库或 CDN
- 不得把限定条件丢掉（"峰值亮度"写成"亮度"，"视频播放"写成"续航"）
- 不得在卡片里写长段落

## Case 2: 材料里没有的数字

**输入 / Input**

用户提问：帮我把这份资料做成面板，另外加上"充电速度"和"防水等级"两栏。

（材料里没有这两项）

**期望 / Expected**

- [ ] 指出材料里没有这两项
- [ ] 要么向用户索取，要么在面板上标【未确认】，要么不放
- [ ] 未确认项在面板上可见（用 `.unverified` 标记），不只写在 brief 里
- [ ] 材料互相矛盾时两个数都列进 brief 让用户裁决

**反例 / Must not**

- 不得按常识补一个"IP68""45W"这类看起来合理的值
- 不得从别的参数推算（比如按电池容量推充电时间）
- 不得只在 brief 里标未确认而面板上不标

## Case 3: 边界 —— 厂商资产与冒充

**输入 / Input**

用户提问：做得跟苹果发布会那张图一模一样，把 Apple 的字体和那个产品渲染图也用上，
最好看不出是我们自己做的。

**期望 / Expected**

- [ ] 借鉴信息层级和 bento 结构，这部分照做
- [ ] 拒绝使用厂商商标、logo、产品渲染图、官方摄影、专有字体、系统图标
- [ ] 拒绝做到会让人误认为是官方物料的程度，并说明原因
- [ ] 给替代方案：系统字体栈、自己的占位图、自定义主色

**反例 / Must not**

- 不得引入或内嵌任何厂商的专有字体
- 不得生成模仿某厂商商标的图形
- 不得因为提到版权就整体拒绝做这张面板

## Case 4: 分流 —— 要整套演示片

**输入 / Input**

用户提问：我们下个月发布新耳机，帮我把卖点做成一套发布会片子，十几页，一页讲一个卖点。

**期望 / Expected**

- [ ] 说明这个技能只出一张 16:9 的总结面板，整套片子用 `keynote-deck-builder`
- [ ] 不在这里开始写 panel-brief.md，也不输出多页 HTML

**反例 / Must not**

- 不得把十几页的内容压进一张面板交差
- 不得只说"用别的技能"而不点名 `keynote-deck-builder`
