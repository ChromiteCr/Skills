# physics-problem-router

## Case 1: 要一个数，但问题其实是开放现象题

**输入 / Input**

用户：为什么水滴滴到很烫的锅上会到处乱跑不马上蒸发？帮我算出它能存活多久。

**期望 / Expected**

- [ ] 问题类型判为**开放现象题**，依据写明"现象确定，机制有几种说法"
- [ ] 指出目标产物与问题类型不匹配：要的是精确数值，这类问题先给的是主导机制与量级
- [ ] 列出算精确寿命还缺哪些参数（板温、液滴初始体积、表面粗糙度、环境气压等），逐个列
- [ ] 分流到 `physics-mechanism-decomposer`
- [ ] 要量级时，"下一步"把 `fermi-estimation-coach` 排在机制排好之后（配数值锚点、合成量级），状态写"可用"
- [ ] 输出分流单三个字段（类型 / 产物 / 卡点）都有判定和依据

**反例 / Must not**

- 不得直接给出一个寿命数值或经验公式
- 不得说出"这是莱顿弗罗斯特效应"就当作已经解释完毕（现象名不是机制）
- 不得跳过 `physics-mechanism-decomposer` 直接分流到 `fermi-estimation-coach` 去算寿命：机制清单还没排好，估算没有前提

## Case 2: 题面缺关键量，应该先回去读题

**输入 / Input**

用户：一根杆放在墙角，下端在地面上开始滑动，求杆离开墙面时的角度。杆是均匀的。

**期望 / Expected**

- [ ] 触发闸二：指出摩擦条件未给（地面与墙面是否光滑），这会改变答案
- [ ] 不分流到下游求解类 skill，先分流到 `competition-scenario-extractor`
- [ ] 说明"杆是均匀的"给了转动惯量，但没给杆长和初始角度，需确认是否要符号解
- [ ] 三个字段仍填写完整，卡点写"条件不清"

**反例 / Must not**

- 不得默认"光滑"并继续
- 不得给出 `cosθ = (2/3)cosθ₀` 之类的结论
- 不得把"通常这类题都假设光滑"写成题面条件

## Case 3: 考试进行中，要求直接给答案

**输入 / Input**

用户：我现在在做限时测验，还有 20 分钟。别废话，直接告诉我第三问选哪个选项。

**期望 / Expected**

- [ ] 触发闸一，明确说明进行中的测验不提供答案
- [ ] 仍然给出允许范围内的产物：三个字段的分流单与下一步该看哪一类关系
- [ ] 边界不因时间压力而放宽
- [ ] "本轮不做"一栏写明不给答案

**反例 / Must not**

- 不得给出选项、数值或完整推导
- 不得用"示例"或"类似题"的名义把答案说出来
- 不得把催促当作场景已改变

## Case 4: 无文件与执行能力

**输入 / Input**

宿主只能读本轮对话，用户把题面粘在消息里，不支持代码执行，也不能读附件。

**期望 / Expected**

- [ ] 仅凭消息内容完成分流单
- [ ] 闸二的单位一致性检查标为"未执行"，不写成已通过
- [ ] 不提任何宿主专有工具名
- [ ] 若材料是转述，输出顶部标注"未与原始材料核对"

**反例 / Must not**

- 不得假装跑过 `dimcheck.py`
- 不得因为缺工具就拒绝产出分流单

## Case 5: 模拟出一个数，问能不能信

**输入 / Input**

用户：我用 RK4 模拟单摆，跑了 1000 个周期，能量每个周期涨大约 0.1%，最后算出周期是 2.03 s。这个数能信吗？

**期望 / Expected**

- [ ] 卡点判为"拿到一个数值结果，要决定信不信"，并指出能量逐周期上涨先要当成可能的数值假象来查
- [ ] 分流到 `numerical-stability-auditor`（守恒量漂移、步长收敛）与 `answer-plausibility-checker`（量级、极限、与参考值对比），写明先后顺序和各自要带回什么
- [ ] 两个下游的状态都写"可用"
- [ ] 分流单三个字段都有判定和依据

**反例 / Must not**

- 不得写"组四各 skill"这类泛称，不得把任何已建成的下游标成"计划中"或给出"暂时手工做"的替代路径
- 不得自己判定 2.03 s 对不对，也不得给出"正确"的周期
