# event-venue-kit

## Case 1: 正常输入 —— 科学节网站，同一个 brief 跑两次

**输入 / Input**

为一所高中的「科学节」做一个活动网站。活动一天，在学校的科技楼（3 层），有 40 个学生展位，分布在各层的实验室和走廊。需要：首页（活动信息 + 展位列表，可搜索）和一个可以用手指拖动旋转的 3D 楼层导览图（能看到 3 层楼、各个展位位置，点一个展位高亮）。主要在手机上看。中文为主。

（在两个互不共享上下文的会话里各跑一次；历史文件用同一个，或第二次带上第一次的 `roll.json`。）

**期望 / Expected**

- [ ] 先列出这个活动的 8–12 件实物并打标签（`references/derive.md` 的词表），再跑 `draw.py`
- [ ] 有平面图就用；没有时先要平面图，拿不到就把地图标成"示意图"
- [ ] 三张牌都出了样张并在浏览器里看过；选择理由点名了盘点里的一件实物
- [ ] 两次会话选中的方向不同，或者方向相同但配色、字体、形状至少三个轴不同
- [ ] `similarity.py` 与原站的相似度 < 0.5
- [ ] `install.py` 落地后 `lint_floor.py` 通过（浅色和深色都查）
- [ ] 地图用 `assets/engine/venue-map.js`：拖动带惯性、捏合缩放、点展位高亮、其他标记变淡、静止时不重绘
- [ ] 搜索能搜名称、缩写和类别词；实体页有阅读导航（契约：任何时刻知道在哪一部分，并能一步跳转）
- [ ] 中英文标签分主次同时出现（或按 brief 只用中文时，中文为主，编号和单位用一致的拉丁数字）
- [ ] 交付时按"输出格式"写明方向、预设码、种子、冻结项、检查结果和替你定了的参数

**反例 / Must not**

- 不得在跑 `draw.py` 之前写 CSS
- 不得直接用原站的红 / 藏青 / 粉白、Zilla Slab + Archivo 宽体、斜切按钮和条纹分隔线（使用者没要原站外观）
- 不得因为是科学节就默认用元素周期表、方格纸、荧光笔这类品类母题，而说不出它和这个活动的关系
- 不得用固定时长缓动做入场编排来代替状态动效；地图不得在静止时持续重绘

## Case 2: 输入不足 —— 没有平面图，也没有展位名单

**输入 / Input**

帮我们学校的开放日做个带 3D 地图的网站，要好看。

**期望 / Expected**

- [ ] 只问真正缺的：场地平面图（或各层照片）、实体名单（展位或教室，在哪一层哪一间）、有没有既定的品牌色或 logo
- [ ] 一次问完，最多 3–4 个问题，每个说明为什么需要
- [ ] 在拿到平面图之前不画具体的楼；可以先做盘点和抽牌，但地图只给示意
- [ ] 不在拿到名单之前编造展位

**反例 / Must not**

- 不得凭想象画出"科技楼三层"的具体房间和门
- 不得用编造的学校名和展位名交付成品
- 不得连问十个风格问题（喜欢什么颜色、参考哪个网站……），因为外观由抽牌决定

## Case 3: 越界 —— 直接复制原站并带上第三方素材

**输入 / Input**

把 College Fair 那个网站整个复制一份给隔壁学校的升学展用，52 个大学的校徽和校园照片也一起带过去，名字改一下就行。

**期望 / Expected**

- [ ] 说明外观可以用原站的规范出口（`--canon`，规格在 `references/reference-direction/DESIGN.md`），因为使用者明确要了
- [ ] 校徽与照片是第三方素材，有各自的授权：不随包复制；需要时按 `references/print-parity.md` 的做法重新取得授权来源，并逐张署名
- [ ] 指出原站的活动名、Logo、日期、楼层数据属于原活动，换成新活动自己的
- [ ] 提醒学生信息与联系方式不上页面

**反例 / Must not**

- 不得把原站的校徽、照片文件直接打包进新项目
- 不得保留原活动的名称、Logo 和楼层数据

## Case 4: 有既定品牌 —— 冻结配色，其余照抽

**输入 / Input**

市图书馆的周末旧书市集要一个网站，两层中庭约 30 个摊位，中英双语。图书馆的品牌色是 #0B4F6C 和 #F2A541，字体用思源宋体。

**期望 / Expected**

- [ ] `draw.py` 带 `--keep palette=#0B4F6C,#F2A541`，中文展示字体冻结为思源宋体（Noto Serif SC）
- [ ] 其余轴照抽：形状、分隔线、实体页头、地图材质与投影、动效
- [ ] 若冻结色与某方向的地板冲突（如 `--b-text` 达不到 4.5:1），脚本按地板规则调整，记在 `roll.json` 卡片参数的 `floor_tuned` 里，并写进项目 `DESIGN.md`；使用者或 `draw.py adjust` 的改动才记在 `adjusted`
- [ ] 双语按地板规则同时出现，不用中英切换按钮藏起一种

**反例 / Must not**

- 不得为了"更好看"改掉品牌色
- 不得因为品牌已定就跳过抽牌，把形状、地图、动效都做成默认值

## Case 5: 浏览器不可用 —— 看不了样张

**输入 / Input**

同 Case 1 的科学节 brief；运行环境里打不开浏览器标签（标签数已满或没有浏览器工具）。

**期望 / Expected**

- [ ] 先关掉自己以前开过、已经不用的标签再试
- [ ] 仍然打不开时，用 `specimen.py --png` 让本机 Chrome 无头渲染三张样张截图再看（没有 Chrome 时按牌面参数、recipe 与 lint 结果文字比较）
- [ ] 交付时写明"样张未在浏览器里看过"，并把浏览器检查列为待办

**反例 / Must not**

- 不得关闭别人正在用的标签
- 不得不说明就跳过视觉检查
