# deadline-to-study-plan

## Case 1: 单个截止日，信息齐全

**输入 / Input**

学生档案：11 年级，IB 体系，HL 物理在读。

已有事项（短期）：
- 2026-08-12 数学小测（pending）
- 2026-08-20 至 08-22 校运会（三天，pending）

用户提问：9 月 5 日有一场 HL 物理的月考，帮我排一下复习。今天是 8 月 4 日。

**期望 / Expected**

- [ ] 先读取了已有事项与档案，再开口
- [ ] **第一轮就给出了完整的第一版节点**，没有停下来等信息
- [ ] 假设写在最前面且是显式的（「假设每天 2 小时、周末 3 小时」）
- [ ] 同一轮调 `ask_user` 问了可用时间与固定安排，选项具体（1 小时以内 / 1–2 小时 / …）
- [ ] 倒推出的节点是**有交付物的**（如「把电磁学近三年真题做完并订正」），不是「复习电磁学」
- [ ] 避开了 08-20 至 08-22 的校运会那三天
- [ ] 截止日前留了至少 1–2 天缓冲，最后一天是检查而不是新内容
- [ ] 节点数在 6 个以内
- [ ] 拿到答案后重排，并调用 `propose_events` 出卡，没有再问「要不要保存」

**反例 / Must not**

- 不得出现「每天学 2 小时」「多刷题」「保持状态」这类无法验收的任务
- 不得把任务排到校运会那三天
- 不得先问一轮可用时间、什么都不产出就结束这一回合
- 不得按某个时间假设排完却不把这个假设写出来
- 不得问「要不要我帮你排」「这样可以吗」这类不改变产出的问题

## Case 2: 截止日不明确

**输入 / Input**

用户提问：我下个月有个考试，帮我排下计划。

**期望 / Expected**

- [ ] 用 `ask_user` **一次问完**：哪门考试、大概哪一周、每天可用时间、有没有固定安排
- [ ] 不替学生假定一个日期——这是本 skill 唯一值得先停下来的一问
- [ ] 在拿到日期之前不产出任何提案

**反例 / Must not**

- 不得取「下个月中旬」之类的近似日期开始排
- 不得先排一版「假设是 9 月 15 日」的计划

## Case 3: 多个 DDL 冲突且时间不够

**输入 / Input**

学生给出三个截止日集中在同一周（IB 内部评估提交、托福考试、一场竞赛初赛），
自述每天只能拿出 1.5 小时。

**期望 / Expected**

- [ ] 明确指出按现有时间三件事无法都做到位，并给出量化依据（需要多少、只有多少）
- [ ] 用 `ask_user` 把取舍摆成选项（哪件降标准 / 哪件推迟），一张卡问完，由学生决定
- [ ] 学生做出选择后才提案

**反例 / Must not**

- 不得私自决定放弃其中某一项，也不得默默压缩某一项的时间而不说明
- 不得给出一份表面排得下、实际每天需要 4 小时的计划
