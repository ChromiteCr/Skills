# deadline-to-study-plan

## Case 1: 单个截止日，信息齐全

**输入 / Input**

学生档案：11 年级，IB 体系，HL 物理在读。

已有事项（短期）：
- 2026-08-12 数学小测（pending）
- 2026-08-20 至 08-22 校运会（三天，pending）

用户提问：9 月 5 日有一场 HL 物理的月考，帮我排一下复习。今天是 8 月 4 日。

**期望 / Expected**

- [ ] 先读取了已有事项与档案，再开口
- [ ] 主动问了每天可用时间，没有自己假定
- [ ] 倒推出的节点是**有交付物的**（如「把电磁学近三年真题做完并订正」），不是「复习电磁学」
- [ ] 避开了 08-20 至 08-22 的校运会那三天
- [ ] 截止日前留了至少 1–2 天缓冲，最后一天是检查而不是新内容
- [ ] 节点数在 6 个以内
- [ ] 调用 `propose_events` 出卡，没有先列一遍计划再问「要不要保存」
- [ ] 明确写出了这份计划的假设（每天几小时、避开了哪几天）

**反例 / Must not**

- 不得出现「每天学 2 小时」「多刷题」「保持状态」这类无法验收的任务
- 不得把任务排到校运会那三天
- 不得在没问可用时间的情况下直接给出满满当当的日程

## Case 2: 截止日不明确

**输入 / Input**

用户提问：我下个月有个考试，帮我排下计划。

**期望 / Expected**

- [ ] 追问具体日期，不替学生假定一个
- [ ] 同时把其他缺失项（哪门考试、每天可用时间、有没有固定安排）一次问完，不挤牙膏
- [ ] 在拿到日期之前不产出任何提案

**反例 / Must not**

- 不得取「下个月中旬」之类的近似日期开始排
- 不得先排一版「假设是 9 月 15 日」的计划

## Case 3: 多个 DDL 冲突且时间不够

**输入 / Input**

学生给出三个截止日集中在同一周（IB 内部评估提交、托福考试、一场竞赛初赛），
自述每天只能拿出 1.5 小时。

**期望 / Expected**

- [ ] 明确指出按现有时间三件事无法都做到位，并给出量化依据（需要多少、只有多少）
- [ ] 把取舍选项摆给学生（哪件可以降标准、哪件可以推迟），由学生决定
- [ ] 学生做出选择后才提案

**反例 / Must not**

- 不得私自决定放弃其中某一项，也不得默默压缩某一项的时间而不说明
- 不得给出一份表面排得下、实际每天需要 4 小时的计划
