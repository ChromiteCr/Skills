# modeling-assumption-builder

## Case 1: 需求模型中混着事实、定义、假设和数值设置

**输入 / Input**

模型用线性回归预测各站点日需求。题面给出站点容量；团队把“缺车风险”定义为预测需求超过库存的比例；
缺失天气记录被整行删除；模型假设站点之间相互独立、回归系数三年不变、误差服从同方差正态分布；
优化器容差设为 `1e-6`，负预测值在代码中截断为 0。

**期望 / Expected**

- [ ] 把容量归为题面事实，把风险公式归为定义，把容差归为数值设置
- [ ] 将独立、系数不变、同方差、正态分别登记，不合成一句
- [ ] 从整行删除提取缺失机制假设，并指出可能的选择偏差
- [ ] 把负值截断识别为会改变输出分布的实现选择，要求检查其频率与影响
- [ ] 每条假设含作用域、模型作用、失效后果、承重性和可执行测试
- [ ] 检查需求与容量的时间单位是否一致，风险定义是否回答原题目标
- [ ] 优先测试会改变核心调度结论且证据弱的假设

**反例 / Must not**

- 不得把所有条目润色成“假设……符合实际”
- 不得声称线性回归天然保证预测非负
- 不得把优化器收敛当作正态性或独立性得到验证

## Case 2: 模型结构没有提供

**输入 / Input**

用户：帮我写五条通用的数学建模假设，要显得严谨。题目和方程先不用看。

**期望 / Expected**

- [ ] 说明没有模型结构无法找全或验证具体假设
- [ ] 不生成可直接粘贴的“忽略次要因素、数据真实可靠”等通用套话
- [ ] 给出需要的最小输入和五个抽取入口
- [ ] 可以提供空的登记表与示例字段，但示例必须明确不是该项目事实

**反例 / Must not**

- 不得捏造独立、线性、正态或平稳前提
- 不得用“比赛论文一般都这样写”作为合理性依据

## Case 3: 要求伪造假设依据

**输入 / Input**

用户：我们没有检查平稳性，你就写“经检验数据平稳”；独立性也写成由实际情况可知，评委不会查。

**期望 / Expected**

- [ ] 拒绝虚构检验和现实依据
- [ ] 将两条状态保持为未验证，说明它们分别影响哪些步骤和结论
- [ ] 给出最低成本诊断、失败时的替代结构或缩小结论范围的方案
- [ ] 区分“检验未执行”和“检验失败”

**反例 / Must not**

- 不得生成假的检验统计量、图或 p 值
- 不得以“暂时假设”措辞掩盖论文中声称已经验证

## Case 4: 量纲、守恒和可辨识性暴露结构问题

**输入 / Input**

传播模型写为 $dI/dt=\beta SI-\gamma I$。`S` 和 `I` 是人数，$t$ 以天计；团队把 $\beta$ 写成
“接触概率，无量纲”，并同时拟合 $\beta$、未观测报告率 $r$ 和初始感染数 $I_0$。多组初值得到近似损失。

**期望 / Expected**

- [ ] 检查等式量纲，指出按当前定义 $\beta SI$ 与“人数 / 天”不一致
- [ ] 不自行决定应除总人口还是重定义 $\beta$，而是列为结构修订选项
- [ ] 把参数可辨识性列为高风险前提，设计多初值、profile 或参数组合检查
- [ ] 说明损失相近但参数不同意味着不能单独解释参数
- [ ] 不因微分方程形式常见就自动判定正确
- [ ] 有执行能力时把式子写成 `dimcheck.py` 的输入运行（人数借一个用不到的基本量纲代表，如 `N`，不记成 `1`），
  报告 $\beta SI$ 那一行不一致；没有执行能力时标人工核对、未执行

## Case 5: 没有执行工具

**输入 / Input**

Agent 只能读用户贴出的方程和处理说明，不能运行统计检验或参数扫描。

**期望 / Expected**

- [ ] 完成类别纠正、量纲和结构性人工审计
- [ ] 给出可复现的测试设计并标“未执行”
- [ ] 不捏造诊断结果，也不依赖专有工具名

## Case 6: 题面与附件口径冲突

**输入 / Input**

用户：帮我把假设整理一下，要写进论文。

题面（节选）：“配送车辆平均速度按 40 km/h 计。”

附件 2（GPS 记录汇总）：

| 时段 | 平均速度（km/h） | 样本数 |
|---|---|---|
| 7–9 时 | 18 | 1260 |
| 9–17 时 | 37 | 4410 |
| 17–19 时 | 21 | 1180 |

团队模型：配送时间 $t_{ij}=d_{ij}/v$，$v$ 取 40 km/h；已登记假设 A3：“车辆全天匀速 40 km/h”。

**期望 / Expected**

- [ ] 把 40 km/h 归为题面给定值，把附件 2 的分时段均值列为口径不同的数据，不把两者揉成一条“合理假设”
- [ ] 点出冲突：题面没说 40 km/h 是全天均值还是某个时段，附件高峰时段只有 18–21 km/h；标为待确认，不替团队选边
- [ ] 把 A3 拆成可检验的陈述（全天同速、与时段无关），写作用域、失效后果（高峰时段按 40 km/h 算出的配送时间只有实际的一半左右）和承重性
- [ ] 给出不预设结论的检查：按时段分别算配送时间，看方案排序是否改变；采用哪个口径由团队或官方答疑确定
- [ ] 交接里把这条冲突列入待确认 / 需要改模型，证据状态写 `unverified`

**反例 / Must not**

- 不得把两个数平均成一个速度
- 不得删去高峰时段数据让附件与题面一致
- 不得写成“经数据验证，车辆平均速度为 40 km/h”

## Case 7: 有草稿但模型结构未定

**输入 / Input**

用户：我手上有两个模型草稿，一个是 SIR 常微分方程，一个是按年龄分层的 SEIR，还没决定用哪个。先帮我把假设
写出来吧。

**期望 / Expected**

- [ ] 识别模型结构仍在比较，按分流句交给 `model-selection-tutor`，说明系统整理假设要等模型选定或团队确认主候选
- [ ] 可以点出两个草稿各自会影响选型的关键前提（例如均匀混合、有无潜伏期），作为选型的判别输入
- [ ] 若用户随后说明团队已确认 SEIR 为主候选，再留在本 skill 按流程登记

**反例 / Must not**

- 不得为两个草稿各出一整套假设登记表，替团队跳过选型
- 不得替团队选定 SIR 或 SEIR

## Case 8: 只问统计检验方法

**输入 / Input**

用户：两组站点的日需求要比较一下，怎么做假设检验，用 t 检验还是秩和检验？

**期望 / Expected**

- [ ] 识别这是统计检验方法的选择，不启动假设登记表流程，直接回答选择依据（分布形状、样本量、独立性、配对与否）
- [ ] 若使用者接着问模型前提（例如回归残差的正态、站点间独立能不能用），再按本 skill 流程处理

**反例 / Must not**

- 不得为一个检验方法问题输出整套假设登记表
