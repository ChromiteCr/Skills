# Modeling Paper Argument Checklist

建模论文不是按固定目录填字，而是把问题、选择、证据、结果与限制组成可追踪的论证。章节名可以随赛事模板改变，
下面的功能不能丢。

## 1. 主张—证据链

每条论文主张 `C` 至少回答：

| 字段 | 问题 |
|---|---|
| precise claim | 具体说了什么，作用域在哪里 |
| question | 回答哪个 `Q` |
| support | 由哪些 `F / R / T / D / M` 支持 |
| comparison | 与什么基线、替代模型或情景相比 |
| uncertainty | 数值或结构不确定性怎样表达 |
| limitation | 哪种条件下不能继续这样说 |
| location | 论文首次提出、论证和收束的位置 |

链条最低标准：

```text
题目 Q -> 方法选择 M + 假设 A -> 可复现运行 R -> 结果 / 图表 F
       -> 验证 T -> 论文主张 C -> 限制与适用范围
```

摘要只能使用正文已建立且状态允许的主张。摘要不是给未经验证的亮点另开一条通道。

## 2. 章节功能

按项目裁剪和合并，保留每个问题的明确归属：

- **摘要 / Executive summary**：问题、方法选择、关键结果、验证证据、限制与建议；数字带单位与口径
- **问题与交付**：原题动作、对象、目标、约束、输出；不把背景扩写成文献综述
- **符号、数据与假设**：变量定义、单位、来源、处理、假设作用域；表格不能代替关键理由
- **模型选择**：基线、候选、判别依据、拒绝方案；不是“我们采用先进的……”
- **模型建立**：从定义到方程 / 目标 / 约束，解释每项来源和边界
- **求解 / 估计**：算法、初值、容差、分割、参数估计与诊断；与理论模型分开
- **结果**：先基线，再主模型；报告数值、单位、不确定性和图表
- **验证**：手算 / 已知解、校准外验证、灵敏度、不确定性、稳健性各自回答什么
- **解释与决策**：结果如何回答题目，不超出证据谈因果或普遍性
- **局限与扩展**：具体到假设、数据、作用域与失败场景；不写“时间有限”作为唯一限制
- **结论**：逐问收束，强度不高于验证；不引入新数字或新方法
- **复现材料**：数据来源、代码 / 运行、图表生成、AI 辅助披露和规则要求

## 3. 段落功能

一个技术段落通常只承担一个主功能：定义、选择理由、推导、程序、结果、解释、限制或过渡。常见断裂：

- 方程出现前变量未定义，出现后也不解释每项
- 方法段提前宣布结果，结果段又复述算法
- 图表段只说趋势，不报量、单位、基线与不确定性
- 限制段列出问题，却不说它影响哪条结论
- 结论段把“在测试场景中”放大成“普遍适用”

每段首句应让读者知道它要完成哪一步，但不要求机械套句式。

## 4. 图表合同

每个 `F` 回答一个问题，并保留：

- 支持的 `C / T` 与生成它的 `R / D`
- 横纵轴、单位、样本 / 时间 / 空间范围和数据处理
- 基线、对照、误差 / 区间或为什么不适用
- 图注独立可读，说明图展示什么，不替正文夸结论
- 正文在图出现后解释“读到什么、为什么与问题有关、限制是什么”

不使用 3D、截断柱轴、双轴、面积装饰或颜色唯一编码制造差异。图表选择应服从比较任务，不服从“多样化”。

## 5. 摘要数字门槛

摘要中的每个数字必须：

1. 指向正文表图或结果位置
2. 指向具体运行 / 数据
3. 带单位、对象、时间 / 空间范围和比较基准
4. 说明是观测、估计、预测、情景结果还是优化解
5. 不把单次最优运行写成典型性能

缺任何一项时先修证据链，不能靠删脚注把数字变干净。

## 6. 页数预算

先保留评分与论证必需信息，再删重复：

1. 同一个定义只保留首次完整说明，后文用符号与交叉引用
2. 主文保留影响选择和结论的假设、推导与检查；纯机械细节移附录
3. 失败 / 替代模型保留影响选型的证据，不保留长过程日志
4. 图和表不重复表达同一组数字
5. 不删限制、验证或单位给装饰性背景让位

页数短时应压缩表达，不压低证据标准。
