# Modeling Code and Reproducibility Checklist

代码只证明计算机执行了某套指令。要让模型结果可复核，还需要把数学对象、数据、实现、运行与图表连起来。

## 1. 实现前合同

- [ ] 每个函数 / 模块能指向一个 `Q / M / T` 任务，不存在“先写着以后也许有用”的主流程
- [ ] 所有输入变量有含义、单位、允许范围、缺失规则和来源
- [ ] 方程、目标、约束、初始 / 边界条件与假设已经由使用者确认
- [ ] 至少有一个手算小例或已知解
- [ ] 至少有一个不变量：守恒、非负、概率和为 1、容量上限、单调性或问题适合的性质
- [ ] 验收指标、基线和数据分割在看结果之前确定

缺一项时可以搭接口、验证器或测试夹具，但不能把缺失内容偷偷写成实现决定。

## 2. 数据链

- [ ] 原始输入只读；清洗与派生数据另存，不覆盖原件
- [ ] 记录来源、版本 / 截止时间、文件哈希或等价快照标识
- [ ] 字段类型、单位、唯一性、范围、时间顺序、主键与缺失显式校验
- [ ] 单位转换集中在一个可测试入口，内部使用一种标准单位
- [ ] 删除、插补、截断、聚合和异常处理记录数量与规则，不静默执行
- [ ] 训练 / 校准与验证先分割，预处理只在训练侧拟合
- [ ] 输出能追到具体输入快照与处理配置

## 3. 代码结构

按任务裁剪，不要求每个项目都建很多文件：

```text
configuration -> load/validate -> transform -> model/solve
              -> calibrate      -> verify/validate -> sensitivity
              -> export tables/figures + run manifest
```

- 纯计算与文件 I/O 分开，便于用小数组测试
- 参数来自显式配置，不散落 magic numbers
- 模型步骤命名贴近数学符号，但避免单字母在大范围代码中失去含义
- 图表只消费已登记结果，不在绘图函数里重新计算另一套模型
- 错误信息包含变量 / 约束与实际值，不只写 “invalid input”

## 4. 数值与求解

- [ ] 检查 NaN、Inf、除零、溢出、病态矩阵和尺度差异
- [ ] 初值、网格、步长、容差、停止条件和最大迭代显式记录
- [ ] 运行后检查求解器状态、约束残差、最优性差距或积分误差；不只检查进程退出码
- [ ] 多初值 / 多种子判断局部解或随机不稳定
- [ ] 改步长 / 容差检查结果是否收敛，而不是选一组“看起来平滑”的设置
- [ ] 自动修复输入时默认报错或告警，并记录修复；不静默裁剪为可行值

按求解器类型使用 `validation-playbook.md` 的专项验收：ODE / PDE 做加密、观测阶、稳定性、正性与事件检查；
优化区分 primal / dual、整数性、gap 与证书；MCMC 检查多链、R-hat、有效样本量、自相关与 Monte Carlo 误差。

## 5. 任务特定风险

### 统计与机器学习

- 分割符合时间、空间、个体或群组结构
- 特征工程、插补、标准化、选择和调参不看最终验证集
- 候选 / 超参数比较使用开发集或嵌套验证；最终集在模型与报告规则冻结后只看一次
- 预测外生变量在验证时必须与部署时可获得的信息一致，并传播未来协变量的不确定性
- 与简单基线同数据、同指标比较
- 报校准外性能、样本数、波动与适用范围，不只报单次最优值

### 优化

- 数据可行性与模型可行性分开检查
- 每类约束有微型测试和运行后残差检查
- 整数 / 二元变量没有被求解器接口静默放松
- 不可行、无界、超时、有可行解、证明最优是不同状态
- 分开检查 primal / dual 可行性、尺度、变量界、整数性、gap 与可用证书；未闭合 gap 不称已证明最优

### 仿真与随机模型

- 随机数生成器显式传入，种子记录但不在每次函数调用中重置
- 报重复次数、置信 / 误差表达与停止规则
- 先检验单个主体 / 单步，再检验总体统计
- MCMC 另报多链、R-hat、有效样本量、自相关与 Monte Carlo 误差；仿真保留随机流设计

## 6. 验证矩阵

| 层 | 最少一个测试 |
|---|---|
| 输入 | 类型、单位、范围、缺失、键与时间顺序 |
| 公式 | 手算小例 / 已知解 |
| 性质 | 量纲、不变量、边界、极限情形 |
| 数值 | 步长 / 容差 / 初值变化 |
| 数据 | 无泄漏、拆分、基线、校准外验证 |
| 结论 | 灵敏度 / 稳健性是否改变主张 |
| 复现 | 从干净环境按一个命令重建关键表图 |

测试失败时先修根因；不要放宽断言去匹配当前错误输出。

## 7. Run Manifest

```yaml
run_id: R...
status: not-run | failed | passed-with-warnings | passed
code_revision:
entry_command:
environment:
input_snapshots:
configuration:
random_seed:
solver_and_tolerances:

```

不能取得 Git revision、环境锁文件或文件哈希时，记录可用的最低等价信息；不能空着却写“可复现”。

## 8. 完成判据

实现完成不等于“脚本能跑”。至少满足：

1. 验收矩阵中的适用测试已执行并记录状态
2. 结果超过预先基线，或如实说明没有超过
3. 求解 / 估计诊断没有被忽略
4. 输出图表可从登记运行重建
5. 已知限制、未实现项和 AI 辅助范围写清
