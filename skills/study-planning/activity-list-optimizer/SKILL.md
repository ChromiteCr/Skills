# 活动栏压缩 / Activity List Optimizer

把学生写好的活动描述压进 Common App 的字符限额，并保住其中真正有信息量的部分。

两件事必须分清楚：

> **把学生已经写出来的内容压短，是编辑。在空白处替他写，是代写。**
> 这个 skill 做前者，不做后者。

## 何时使用 / When to use

- 学生在填 Common App 活动栏，有内容但超字数
- 学生想知道自己写的这几条在限额上还剩多少空间
- 有一批活动描述要统一过一遍

**不适用于** / Not for：

- 活动经历还没整理过 —— 先用 `activity-profile-builder` 建档
- 想知道这些活动够不够、招生官怎么看 —— 那是 `admissions-reader`
- 写主文书或补充文书 —— 不是本 skill 的范围

## 需要的输入 / Inputs

| 输入 | 必填 | 说明 |
|---|---|---|
| 学生写的原文 | 是 | 职位 / 组织 / 描述三栏中要处理的那些。**没有原文就没有可压缩的东西** |
| 已有长期事项 | 否 | 学生说"就用我系统里那几条"时读出来当原料 |

学生只给了活动名字、没有描述时：**不要替他写第一版。**
让他先用大白话说清楚做了什么，哪怕三百字也行——压缩需要有东西可压。
这是本 skill 唯一必须停下来等的情况，因为缺的不是偏好而是原料。

## 限额 / Limits

| 栏位 | 上限 |
|---|---|
| Position/Leadership description | 50 字符 |
| Organization Name | 100 字符 |
| Please describe this activity | 150 字符 |
| 活动条数 | 10 条 |

**是字符不是词。** 表单按 UTF-16 计（同 HTML 的 `maxlength`），
所以 emoji 一个通常占 2 格——学生肉眼数出来 149，表单可能判 152。
这些都由 `check_activity_limits` 算，不要自己数。

## 流程 / Process

1. **拿原文**：学生贴进来，或从长期事项里读出来。
2. **一次量完**：把**所有**条目一起传给 `check_activity_limits`，看每条超了多少、哪一栏超。
   不要一条一调，也不要量一条改一条再问一句。
3. **直接给出全部压缩版**，按这个优先级砍：
   - **先砍虚词**：`Responsible for`、`Worked to`、`Helped to`、`In charge of` 直接删，动词开头
   - **再砍形容词**：`very`、`successfully`、`significant` 几乎都不承载信息
   - **保住数字**：`18 人`、`从 12 提到 34`、`三所学校` —— 这些是最贵的字符，最后才动
   - **保住具体名词**：技术名、赛事名、职位名

   砍虚词和形容词**不需要问**，直接做，在"砍掉了"那一行写明。
4. **改完重量**：再调一次 `check_activity_limits`。
   **每一版都要重新量。** 你数不准字符数，这不是谨慎是事实。
5. **只有砍到实质内容时才问**：虚词形容词砍完还超，说明装不下的是信息本身。
   这时用 `ask_user` 一次问完（每条一问，最多 4 条一批）：

   > 「机器人社这条砍完虚词还差 22 格，下面哪个可以不要？」
   > 拿奖那句 / 带了几个新人那句 / 具体做的技术那句

   别自己挑一个砍掉再告诉他。这是他的材料，取舍是他的。
6. **（可选）存回去**：学生要求把压缩版写回长期事项时，用 `propose_events` 出确认卡。
   不主动做这一步——活动栏文案和系统里的记录用途不同，多数学生会想分开。

条数超过 10 时，把这件事单独提出来：列出哪几条最弱、为什么，
用 `ask_user` 多选让**学生自己**决定砍哪几条。

## 输出格式 / Output

```markdown
## <活动名>

**描述**（原 <N> 字符 → 现 <M> 字符，限 150）
原文：<原文>
压缩：<压缩版>
砍掉了：<具体砍了什么，一句话>
```

全部处理完给一个总览：几条、几条还超、还差几格。

## 边界 / Boundaries

- **不代写**：空白栏位不替学生填。他没说过的经历、成果、数字，一个字都不能出现。
- **不加料**：压缩过程中不许"顺便润色得更有冲击力"。
  原文里没有的成果不能加，模糊的表述不能替他变确定（"参与"不能改成"主导"）。
- **不凭感觉数字符**：每一版都过 `check_activity_limits`。说"这样应该在限制内了"就是失职。
- **砍内容要经确认**：砍虚词和形容词直接做；砍到实质内容时用 `ask_user` 让他选，不要替他决定。
- **不替学生决定留哪十条**：条数超限时给判断依据，让他自己勾。
- **不承诺效果**：不说"这样写招生官会更喜欢"。没人知道，说了就是编。

## Token 控制 / Token discipline

- 一次把所有要处理的条目传给 `check_activity_limits`，不要一条一调
- 每轮只输出改动的那几条，不重复贴全部原文
- 要问就把多条的取舍攒成一张卡问完；运行时对连续追问有硬上限
- 一条改两三版还压不进去，说明信息量确实超了，交回学生取舍，不要自己反复试
