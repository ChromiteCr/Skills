## 色彩管理决策

1. 显示参照 SDR 输入先归一到 sRGB，再做创意变换；不在未识别的色彩空间上直接套数值。
2. 有 ICC：LittleCMS 相对色度意图，RGB 输出，flags=0。这个选择不是“无损宽色域转换”；超出目标色域的颜色可能被裁切，当前 QA 看不到转换前的色域损失。
3. 无 ICC：要求用户明确确认 sRGB。PNG gamma 与 sRGB 冲突或只有非明确 sRGB 色度声明时拒绝，不私自从几项数字拼 ICC。
4. 拒绝可检测到的 cICP/HDR PNG 信号；没有全面的 JPEG HDR/增益图识别。调用前确认 SDR；8-bit 不能当成充分证明。
5. ICC 转换/解码失败不降级；HDR、RAW、HEIC、高位深和打印交付需要专门流程，不靠改扩展名或重新贴 sRGB 标签解决。

## 确定性像素契约：encoded-srgb-integer-v1

以下是创意参数设计，并非来自 ICC 或 PNG 规范的推荐调色值。
所有处理作用于 EXIF 转正并归一后的 RGB8 像素；对每个像素独立，无随机性。

定义 `R(n,d) = floor((n + floor(d/2))/d)`，d 为正整数。
它是最近整数舍入，恰好半整数时向正无穷方向，包括负数；避免宿主浮点舍入差异。

1. **曲线**：对相邻点 `(x0,y0)` 与 `(x1,y1)`，`t(x)=y0 + R((x-x0)*(y1-y0), x1-x0)`。提前生成 256 项查表。
2. **冷暖偏移**：各通道 `u=t + R(shadow*(255-t)+highlight*t, 255)`，三通道各有自己的偏移。
3. **去/增饱和**：`Y=R(54*r+183*g+19*b,256)`；`v=Y+R((u-Y)*saturation_percent,100)`。
   这里的权重只是编码 sRGB 上的亮度近似，不是线性光亮度，也不承诺保持知觉亮度或色相。
4. **范围处理**：记录 v<0 或 v>255 的通道样本数，再钳位到 0..255。
5. **强度混合**：`out=R(original*(100-strength)+bounded*strength,100)`。
   strength=0 直接返回原像素，既不计算满强度变换，也不制造无效警告。

`neutral` 的曲线恒等、偏移 0、饱和度 100，对任意强度都是恒等；这是数值回归的锚。
手算夹具覆盖纯色、灰阶、曲线节点、负数舍入和一半强度，不能只用实现自身生成“期望值”。

### 数值来源与精度

- sRGB 传递函数使用标准阈值 0.04045、0.0031308，线性段 12.92，指数 2.4，以及 0.055/1.055。
  负坐标采用保留符号的扩展，便于后续统计色域外值；不截成 0。
  可核对来源为 CSS Color 4 的 Sample code for color conversions，
  https://www.w3.org/TR/css-color-4/#color-conversion-code 。
- 线性 sRGB 到 Oklab 使用 Björn Ottosson 于 2021-01-25 更新的两组矩阵，
  https://bottosson.github.io/posts/oklab/ 。代码逐项列出发表的十位小数系数。
  它们是标准颜色空间变换系数，不是拟造的创意配方。逆矩阵由同一组前向矩阵计算，
  避免另外一组舍入后的逆矩阵引入不必要的往返偏差。LMS 用实数立方根，允许负值。
- 这些是供核对的公开来源，本轮未联网重新读取页面。测试的 RGB 原色向量保留八位小数，
  绝对容差 5e-8 用于覆盖参考向量末位舍入。网格往返容差验证的是数值实现，不是摄影色差护栏。
- 所有公开函数返回 float64，不改写输入；输入须为非空、有限的实数。
  色彩坐标最后一轴为 3，传递函数与亮度曲线也支持标量与任意形状。
  RGB 必须先归一到 0..1，函数不会把 255 猜成一个 8-bit 码值。扩展坐标可超出此范围。
  Oklab/OkLCh 转换不钳位 L，亮度曲线单独要求 L 在 0..1。
- OkLCh 用 C=hypot(a,b)，h=atan2(b,a)，角度归一到 [0,360)。恰好 C=0 时记录 h=0；
  近中性仍保留实际坐标，没有虚构肤色键或色度阈值。输入 C<0 拒绝。

### 端点固定亮度曲线

计划给出了部分风格的 contrast 参数，并未规定曲线公式。本轮选择以下可解析验证的工程实现：

`S_c(L) = L^c / (L^c + (1-L)^c)`，c>0；强度混合为 `(1-s)L + s*S_c(L)`，s∈[0,1]。

两端固定在 0 和 1，中点固定在 0.5，中点导数为 c；c=1 恒等，c>1 加反差，0<c<1 降反差。
实现用 log-odds 与稳定 sigmoid，避免直接计算幂导致分子、分母同时下溢。
contrast 与 strength 必须显式传入，没有新增默认配方系数；strength=0 或 contrast=1 返回精确副本。
`contrast_oklab` 只改 L，a/b 不变，后续还须实现计划中的高光色度滚降、肤色保护与色域映射。
不会暗中钳位或量化来伪造可显示结果。

这是重新设计的公式，尚未经 Bill 对真实摄影效果确认，不作为已经批准的六风格配方。
测试使用计划的 1.25、1.02、0.82 检查单调性、端点与方向；contrast=2 只用于手算
S(0.25)=0.1、S(0.75)=0.9 的合成数学例子，不能把它当推荐调色参数。
标准 D65、显示参照 SDR 的线性化也不等于场景辐射恢复、RAW 显影或 HDR 管线。

### 工程曲线的来源

这是本轮新设计的 Hermite 三次插值，来自以下数学约束，没有实验拟合系数：
在肩部起点保留全部色度，在白点满强度时色度为零，两端导数为零。
设归一化肩部位置 t∈[0,1]，色度保留量 f 为三次多项式，则
f(0)=1、f(1)=0、f′(0)=0、f′(1)=0 唯一确定
`f(t)=1-3t²+2t³=(1-t)²(1+2t)`。
系数 1、2、3 来自这四个边界条件，不是计划中未给出的调色配方。

设显式输入起点 q=start，强度 s=strength，输入为 (L,a,b)：

- L≤q 时，返回原坐标。
- L>q 时，`t=(L-q)/(1-q)`，`k=(1-s)+s*f(t)`，返回 `(L,k*a,k*b)`。
- q 必须在 [0,1)，s 必须在 [0,1]；所有输入必须是有限实数，L 在 [0,1]。
- L 不变；非零色度的 hue 不变，色度乘以 k。k 在 [1-s,1] 之间且随 L 非增。
  满强度白点 k=0，此时 hue 未定义，沿用内核 C=0 时记 h=0 的约定。
- s=0 返回独立的精确副本，仍先验证所有输入。s<1 的白点仍可有色度，
  函数不会为“看起来可显示”而偷偷改成全强度或钳位 RGB。

实现采用因式形式，避免在接近白点时用 `1-smoothstep(t)` 相消成零。
只计算 L>q 的像素，即使 q 是小于 1 的最大 float64，也不会对阴影作极小分母除法。
浮点下溢允许趋于零，溢出或非有限值拒绝；没有中间量化、裁切、RGB 色域映射或肤色键。
算法标识为 `oklab-highlight-chroma-hermite-v1`，原色彩转换标识保持不变。

## 分色相调色内核（0.6.0，重新实现）

本增量对应只读计划 3.4 的 OkLCh 分色相调整。现有浮点内核只有颜色转换、亮度曲线
和高光去色，本版补上按环形色相窗口旋转 hue、缩放 chroma 的实际像素变换。
历史 0.4.1 原型未在当前 skill 文件或该路径本地 Git 历史中找到，本函数为重新实现。
不声称找回原型、复现其照片成绩或已经补齐六风格。

### 数学契约与参数来源

输入为非空有限实数数组 (...,3)，每项为 (L,C,h)，L∈[0,1]，C≥0，h 为度数。
center、width、hue_shift、chroma_scale、strength 必须显式传入，无创意默认值。
令窗口中心为 c，支撑半宽为 b∈(0,180]°，转角为 Δ∈[-180,180]°，
色度倍率为 g≥0，强度为 s∈[0,1]。h 和 c 先按 360° 取模后计算最短环形距离
`d=min(abs(h-c),360-abs(h-c))`。C=0 或 d≥b 时原样返回，否则

`t=d/b`，`w(t)=(1-t)²(1+2t)`，`a=s*w(t)`，
`C_out=C*((1-a)+a*g)`，`h_out=(h+a*Δ) mod 360`，`L_out=L`。

w 是满足 w(0)=1、w(1)=0、w′(0)=w′(1)=0 的唯一三次多项式。
1、2、3 的系数由边界条件推导；360、180 来自圆周角定义，均非实验拟合数值。
该窗口、角度线性混合和色度倍率混合是本轮工程设计，未获真实照片视觉确认。
计划给出目标色相但没有这些窗口宽度或偏移的完整组合，本模块不补造六风格配方。
测试中的窗口、转角、色度值、强度、采样网格和容差均为合成数学夹具，
仅用于验证可手算值、连续性和浮点行为，不能当作默认调色建议。

接口返回独立 float64 数组，不改输入，不读写照片或 ICC，不量化、不钳位色域。
只对窗口内的彩色像素计算 d/b，极小合法半宽不会让窗口外的除法溢出。
色度采用凸组合 `(1-a)+a*g`，避免 `1+a*(g-1)` 在满强度时把极小非零倍率相消为零。
超出 float64 范围时报错，下溢可趋零；没有为使测试通过而裁切巨大色度。
极小负角度的浮点取模可能舍入成 360°，将这一圆周端点统一记为 0°，保持输出范围 [0,360)。
算法标识为 `oklch-circular-hue-band-hermite-v1`，旧颜色转换和高光算法标识不变。

强度为零、恒等参数、窗口外/边界和 C=0 的像素精确保留原坐标，包括输入的 hue 表示。
只改 C 时也保留 h 的数值表示；发生旋转的像素 h 归一为 [0,360)。输出 C=0 时 hue 未定义，
其数值可以不为零。恰好中性不会染色，近中性仍按实际色度处理，没有任意阈值。
这一步只按色相选区，所有相同色相的对象都会被处理；它不具备语义或人物识别能力。

### 包络的推导与像素契约

输入为 (...,3) 的有限实数 (L,a,b)，L∈[0,1]，返回独立 float64 数组。
全部创意参数都必须由调用者给出，无默认值：

- shadow_hue、highlight_hue 为各区新增向量的色相角（度，周期为 360）。
- shadow_chroma、highlight_chroma 为各区峰值新增 Oklab 色度，必须非负。
  它们不代表原像素最终应达到的 C，更不是饱和度百分比。
- balance=p∈(0,1) 为不加色的亮度分界。用输入 Oklab L 计算，不取照片分位数、不猜 EV。
- strength=s∈[0,1] 只缩放新增色度，不插值或改动 L。

暗部为 (0,p)，亮部为 (p,1)。设某一区为 (lo,hi)，归一化位置
`t=(L-lo)/(hi-lo)`，`u=(hi-L)/(hi-lo)`。在该区内部添加

`w=16*t²*u²`，`(a_out,b_out)=(a,b)+s*C*w*(cos(h),sin(h))`，`L_out=L`。

L=0、p、1 时完全保留原坐标。s=0 或两个 C 都为零时返回精确独立副本，仍检查输入。
同一区的 C=0 只关闭该区。两个区互不重叠，强度线性缩放新增向量。
色相用向量表示，跨 0°/360° 不进行错误的算术角度平均。

包络属于本轮新设计的工程选择，未获摄影者视觉确认。推导不使用拟合系数：
要求包络在两端的值与一阶导数都为零，最低次数的非零多项式为 k*t²*(1-t)²；
要求中点最大值为 1，得到 k=16。它关于中点对称，区间内先增后减，各区峰值分别在
p/2 和 (1+p)/2。端点固定的理由是避免这一步重新染色中性黑白；p 处零斜率保证两区平滑衔接。
这是一种明确、可验的分离色调实现，并未声称历史原型采用同一包络。

## 减法密度内核（0.8.0，重新实现）

本增量对应只读计划 3.4 的 OkLCh 减法密度。现有函数可以改反差、分色相与分离色调，
本版补上让有色像素随密度变深或变亮的操作，不改旧 CLI 的三份整数配方和安全读写。
当前 skill 文件与该路径本地 Git 历史未找到历史 0.4.1 原型，因此使用新的工程定义。
本节不声称移植原型、得到原型照片评分或恢复其配方。

### 公式、参数与确认状态

输入为 (...,3) 的有限实数 (L,C,h)，L∈[0,1]，C≥0；返回独立 float64 数组。
`density=d` 为有符号有限实数，`strength=s` 为 [0,1]，均必须显式给出。
定义 d 为满强度时每单位色度带来的亮度 log-odds 减量，则

`logit(L_out) = logit(L) - d*s*C`，`logit(L)=ln(L/(1-L))`。

等价形式为 `L_out = L / (L + (1-L)*exp(d*s*C))`。
C 与输入 hue 的数值表示精确保留，不归一或插值 hue。这里用绝对 OkLCh C，不用 C/L
或未知的饱和度估计；因而它不是按人眼饱和度标定过的操作，更不是胶片光学密度模型。
在 0<L<1 且 C>0 时，正 d 压暗、负 d 提亮。固定 C 时仍是单调的亮度变换，输出在 [0,1]。
强度缩放 log-odds 改变量，不在线性亮度上混合；中途没有量化或 RGB 钳位。
黑白端点和 C=0 原样返回；d=0 或 s=0 返回精确副本，仍先验证全部输入。

这个定义是新设计的工程选择，未获 Bill 对摄影效果的确认，没有拟合的隐藏系数。
计划给出的拷贝片 density=0.6 只用于测试方向，不能把同一个数值在新公式中的表现说成原型配方。
粉彩的负密度也没有由本版私定默认值。所有后续创意参数仍须调用者明确提供并按原要求确认。
算法标识为 `oklch-chroma-log-odds-density-v1`，旧算法标识不变。

### 数值稳定性与一次实测修复

直接 logit → sigmoid 在接近白点且 shift 极小时会产生舍入噪声。本轮合成反例中，
L=0.9999999999999999、C=0.5、d=-1e-16、s=1 原应保持或微微变亮，初版却返回
0.9999999999999998。原因是先取对数再指数回算带来一 ULP 的反向变化。
保留失败证据后改为两个等价的数值分支，没有修改期望或放宽测试：

- `abs(k)≤ln(2)`，其中 k=d*s*C，令 `u=expm1(-k)`，计算
  `L_out=L+L*(1-L)*u/(1+L*u)`。直接求变化量，避免恒等附近的对数往返噪声。
  ln(2) 使 exp(-k) 落在 [1/2,2]，分母至少为 1/2；这是数值条件边界，不是调色阈值。
- 更大 shift 用稳定 log-odds 与 sigmoid。靠近白点先算小的补量再从 1 减去，
  靠近黑点直接保留小值。只有 shift 的乘积允许内部达到无穷，其对应的 sigmoid
  必然舍入至有限端点；API 从不返回无穷或 NaN，也没有靠 RGB 裁切实现这一极限。
- d、s、C 先合并二进制尾数和指数，再进行最后缩放，避免极小强度乘巨大参数时
  过早下溢或溢出。数学结果低于 float64 可表示范围时可舍入为零。

## 编码 sRGB 三角抖动与最终量化（0.9.0，重新实现）

不能为调用本函数而直接裁掉前级的超色域值。历史原型未找回，不声称移植或复现其断层成绩。

### 分布、量化与参数来源

输入为非空有限实数数组 (...,3)，每个通道是已编码的 sRGB 值 x∈[0,1]。
A=amplitude_lsb∈[0,1] 为显式峰值幅度，单位是 8-bit 的一个码值，不是 [0,1] RGB 值。
两个独立的均匀随机变量 U,V∈[0,1) 相减，得到 n=A*(U-V)。
理想连续分布在 [-A,A] 为三角形，均值 0、方差 A²/6；代码使用有限精度伪随机数近似采样。
系数 1/6 来自两个独立均匀分布的方差 1/12 相加，255 来自 8-bit 的最大无符号码值。
这些是数学关系，没有来自未知实验的配方系数。A≤1 是本 API 的工程范围，限制单通道抖动
峰值不超过一码；不是摄影质量标准。A 和非负整数 seed 都必须显式提供，不猜默认值。
测试里的 A=1、A=0.5 与种子仅用于合成验证，未经 Bill 确认为六风格或真实照片的设置。

先令 y=255*x+n，只对新增噪声导致的越界饱和至 [0,255]，然后最近整数舍入，恰好半整数向上。
实现用 k=floor(y)，返回 k+I(y-k≥0.5)，避免直接 floor(y+0.5) 把略小于半整数的浮点数误进位。
返回与输入形状相同的独立 uint8 数组，不改输入。A=0 时不创建随机生成器，所有 RGB8
归一值可精确回到原码；恒等路径应明确关闭抖动。非零抖动允许纯黑变为 1、纯白变为 254，
因此不承诺黑白端点恒等，边界饱和也会引入均值偏移。这些行为须由最终管线 QA 明确统计。
输入本身越界时，无论 A 是否为零都拒绝，包括仅差一 ULP 的情况。浮点转换的端点舍入
也应由前级明确处理并报告，量化器不以容差悄悄承担色域映射。该 API 不恢复 8-bit 源片丢失的精度。

先按 C 顺序生成完整 U 数组，再生成完整 V 数组，逐像素逐通道相减；不读系统熵，
不初始化或推进 NumPy 的全局随机状态。底层数组是只读或非连续布局，不影响相同形状下的结果。
算法标识为 `encoded-srgb8-tpdf-pcg64-half-up-v1`。相同环境、输入形状和值、种子及幅度
得到相同像素字节；此结论不包含 PNG/JPEG 容器字节、跨 NumPy 版本或不同分块方式。
将图像分块后分别调用会重启随机流，不能声称与整图一次调用相同。

## 线性 sRGB 色域映射与占比（0.10.0，重新实现）

现有浮点调色会产生色域外数值，最终量化器按契约拒绝它们。本增量补上可独立调用的映射阶段，
不依赖尚未确认的六风格完整配方。历史原型未找回，此方法由几何约束重新实现，尚未经过摄影者
视觉确认；没有借用原型的实验数字，未向真实照片应用新方法。

### 数学定义与来源

输入为非空有限实数 (...,3)，是归一的线性 sRGB D65，不是编码 RGB、Oklab 或文件中的原始码值。
标准相对亮度为 `Y = w_R*R + w_G*G + w_B*B`，使用以下有理数对应的 float64 值：

- w_R = 87098/409605
- w_G = 175762/245763
- w_B = 12673/175545

来源为 W3C CSS Color 4 色彩转换参考代码 `lin_sRGB_to_XYZ` 的 Y 行，
https://www.w3.org/TR/css-color-4/#color-conversion-code 。三项有理数精确求和为 1。
这些系数来自 sRGB 原色与 D65 标准白点，没有来自未知实验的配方系数。本轮未联网抓取该页；
验证采用独立 Fraction 精确有理数计算，不声称进行新的标准测量或网页核验。

若输入像素全部通道位于 [0,1]，返回精确副本。其余像素必须有 Y∈[0,1]，否则整次调用抛出
ValueError，交给上游显式色调处理。不能为获得可输出数值而暗中裁掉亮度。
令中性锚点 `n=(Y,Y,Y)`，沿 `q(t)=n+t*(rgb-n)` 取最大的 t∈[0,1]，使结果首次碰到色域边界：

```text
t = min(1,
        Y/(Y-min(rgb))               when min(rgb) < 0,
        (1-Y)/(max(rgb)-Y)           when max(rgb) > 1)
```

三个通道共用一个 t。Y=0 或 Y=1 时可以收缩到黑或白，不需要猜亮度阈值。
实现用 `(1-t)*n + t*rgb` 的凸组合形式，避免直接计算巨大 rgb-n 后再次放大。
解析结果在精确算术中位于 sRGB 立方体；float64 的边界舍入可能略微越界，最后显式饱和到 [0,1]，
并记录 `roundoff_samples_corrected` 和 `max_roundoff_correction`。该修正只作用于已经完成
解析压缩的结果，原始超色域像素仍全部计入映射比例，不能据此掩盖色域损失。

Y 与线性 RGB 相对中性轴的方向在浮点误差内保持，通常会降低色彩纯度。
它不保证 Oklab 的 L/h 恒定，不实现知觉最小色差优化或肤色保护；不能把这个方法称为历史原型的
映射器或已确认的电影风格。参数由标准及边界求解确定，没有新增创意旋钮或隐含曝光调整。

### API、QA 与数值边界

`gamut_map_linear_srgb` 返回 `(linear_rgb, qa)`。输入不改，输出 float64、形状相同且独立。
Fortran 顺序、转置及只读输入都先取得 C 连续独立工作数组，确保展平写入作用于实际返回数组。
初版在 Fortran 三维输入上展平产生副本，QA 已计数但返回像素仍越界；新增失败测试复现后仅修复
工作数组布局，没有改期望值或缩减支持范围。输入非有限、形状错误或不可保持的亮度均明确拒绝。

每个三通道像素只计一次，包括一 ULP 的越界。QA 的 `mapped_fraction=pixels_mapped/pixels_total`
为 0..1 比例，不是百分数；严格大于 0.1 时有 `gamut_mapped_fraction_above_10_percent` 警告。
实现以 `10*pixels_mapped > pixels_total` 判定，避免恰为 10% 时的浮点比较歧义。
算法标识 `linear-srgb-luminance-ray-cube-v1`；无整体 pass 字段，不替其他护栏宣布成功。
统计只针对本次输入，不包括 ICC 归一之前的宽色域损失，也不等同于高光剪切比例。

以下只展示接口顺序，不执行照片，也不假定任何创意参数已确认：

```python

encoded = color_core.linear_to_srgb(linear_mapped)
rgb8 = color_core.quantize_srgb8(
    encoded, amplitude_lsb=confirmed_dither_amplitude, seed=confirmed_seed)
```

## 显式选区肤色保护（0.11.0，重新实现）

本增量对应计划 3.3、3.5、3.9 的肤色保护。已有分色相与分离色调会改变暖色主体，
当前目录与相关本地历史没有可移植的 0.4.1 代码，本轮补写实际像素限幅，不补造肤色检测数据。

### 数学方法与参数来源

原坐标为 `(L0,C0,h0)`，调后坐标为 `(Lg,Cg,hg)`。布尔选区必须由调用者明确提供，
与像素形状完全一致，不广播、不把概率或整数自动阈值化。所有 L 在 [0,1]，C 非负，坐标有限。
选区外返回调后坐标原值；选区内保持 Lg，并取 `Cout = min(Cg, 1.15*C0)`。
若 C0 和 Cg 都大于零，将 hg-h0 化为最短环形差 δ，再取
`hout = (h0 + clamp(δ,-6°,6°)) mod 360°`。恰好相差 180° 时固定取正向。
不需要限幅的 hue 保留原表示，不为归一角度引入无意义的像素改动。
C0=0 时去掉新增色度；Cg=0 时保留去色结果。零色度的 hue 无物理定义，不据它计算漂移。
不设置近中性色截止值，极小的正色度仍按实际值处理。

6° 与 1.15 来自计划 3.5，没有新增创意系数。逐像素限制是本轮的保守工程选择，
可限制选区内平均变化，但仍须按完整计划在最终成片测量，不能改变原验收定义或省略检查。
硬限幅会改变局部色彩关系，选区边缘的视觉连续性尚待真实照片确认。没有复现历史原型或其评分。

### 数值、收据与集成范围

角度先分别取周期余数再相减，避免巨大有限角度相减溢出。色度上限乘积超过 float64 时，
只在内部比较界限使用正无穷，任何有限调后色度均已满足限制；返回坐标仍全部有限。
极小色度按浮点舍入处理，不能据数学限幅承诺任意亚正常数的精确实数比值。
工作数组连续且独立，Fortran/转置/只读输入均不被修改。无随机数、I/O 或中间量化。

QA 标明 `skin_detection_performed=false` 与 `explicit_mask_before_gamut_and_quantization`。
只统计总像素、选区、原始零色度、可比色相、两类限幅及其并集；无选区发警告，不报通过。
选区可以来自后续检测器或调用者核实的标注，本函数不证明标注正确，也不检测人脸或身份。
后续映射、编码和量化会再改变颜色，需在最终输出重新测量肤色；当前旧 CLI 没有切换。

21 项测试全部是明确标注的合成坐标、布尔选区与数学网格，包含独立三角函数参考和
分离色调→保护→色域映射→编码→量化的实际串接。测试值仅为可验证的夹具，
无真实照片、用户确认配方或新原型实验成绩。完整六风格与摄影效果仍待验收。


## 线性光高光 bloom（0.12.0，重新实现）

本增量推进计划 3.4 的线性光 bloom 与按短边比例计算空间尺度。当前 skill 目录和本路径
Git 历史只有现有整数 CLI 与独立浮点颜色阶段，没有找回 0.4.1 原型或 bloom 实现。
本版重建独立像素 API，不改变现有 render/candidates/compare，不借用历史照片评分。
原型的红色光晕、颗粒和暗角尚未重建；本函数只扩散光源原本的 RGB 颜色。

### 工程定义与数值来源

输入是 H×W×3 的非空有限实数数组，代表已归一、在 [0,1] 内的显示参照线性 sRGB D65。
颜色空间与 SDR 必须在上游明确，不能把编码 RGB8 数字直接传入，不做 ICC 或 gamma 猜测。
相对亮度 Y 使用上节已经列明来源的标准 sRGB Y 系数。四个参数都必须显式给出：

- threshold=q∈[0,1]，选取光源的线性相对亮度起点，既非 Oklab L，也非百分位或曝光 EV。
- sigma_fraction=f∈(0,1]，高斯标准差占当前图像短边的比例，σ=f×min(H,W)。
- truncate=t>0，高斯核支撑的标准差倍数，整数半径 r=max(1,ceil(tσ))。
- strength=s∈[0,1]，新增扩散光的倍率，零为关闭。它不是原图与模糊整图之间的插值权重。

对 Y>q 的像素，提取 E=RGB×(Y−q)/Y；其余 E=0。q=0 时直接复制 RGB 为 E，避免极暗
亚正常数因亮度计算下溢而消失。此时高光计数按任一正 RGB 分量计算，与精确算术的 Y>0 等价。
离散高斯一维核为 k[i]=exp(−(i/σ)²/2)/Σexp(−(j/σ)²/2)，i,j 从 −r 到 r。
用同一核对两轴作可分离卷积，B=k⊗k∗E，返回 RGB_out=RGB+sB。
1/2 来自高斯分布定义；归一化由有限支撑内权重求和得到，没有拟合或缺省摄影系数。

边界采用 OpenCV BORDER_REFLECT_101，端点不重复。长度为 n>1 的轴按周期 2n−2 镜像，
长度为 1 的轴总返回同一像素。不会循环绕到图像另一侧；RGB 通道分别滤波，不进行 BGR 转换。
调用本机已有 OpenCV 的 sepFilter2D，数据和核均为 float64。惰性导入使恒等路径不需要 OpenCV；
需要实际模糊但依赖缺失时明确拒绝，不自动安装或修改 OpenCV 全局线程/优化配置。
本轮实测环境为 NumPy 2.0.2、OpenCV 5.0.0，不读取其安装目录或系统文档。

r 必须不大于图像短边，否则在分配核之前拒绝。这是控制处理成本的工程边界，意味着核宽
最多为短边两倍加一；不是美学标准，不把过大的核静默缩短。所有参数和输入先验证，零强度
也不会掩盖非法参数。极小合法 σ 使核尾部在浮点下溢时趋零，中心保持 1；不裁切图像像素。

这组提取、反射边界和相加方法是本轮工程实现，尚未获得真实照片与摄影者确认。
计划没有完整的阈值、尺度、支撑倍数或倍率配方，接口不给默认值；不能把测试数据当成已确认配方。
它不模拟胶片层间反射、镜头点扩散函数或 HDR 场景辐射，也不以光晕恢复原片剪切的细节。

### 输出、QA 与串接限制

返回独立 float64 图像及仅适用于本阶段的 JSON 字典。零强度、无高光时精确恒等；全黑不凭空
发光。报告参数、σ、支撑半径、反射规则、实际 OpenCV 版本、高光数、变化像素数与超过 1 的
像素数，计数不重复累加 RGB 通道。没有执行模糊时版本为 null，blur_performed=false。
空高光选择给出 no_highlights_above_threshold；不输出整体 pass 或肤色验收结论。

相加可能令高光超过 1，输出原值和 pixels_above_one，并警告必须明确处理亮度。没有直接钳位、
量化或隐藏压缩。下游现有 gamut_map_linear_srgb 会拒绝 Y>1，所以不能把它冒称 bloom 的
自动色调映射器。完整管线仍须实现并确认过亮处理，随后重新统计色域、肤色与最终量化结果。

全尺寸即使半径比例一致，也受采样、支撑取整与边界影响，不能承诺逐字节相同。
同一输入形状/数值、参数与运行环境下可重复，不使用随机数，不改 NumPy 全局随机状态。
