# 形式选择 / Choosing the format

**形式由参与者需要做什么决定，不由带领者擅长什么决定。**
这份表是反过来查的：先说清参与者要做的事，再倒推形式。

## 一、一个问题就能分掉大半

> 这一场结束时，参与者手里应该**多出什么**？

| 多出的东西 | 形式区间 |
|---|---|
| 多出**一段理解** | Lecture / Seminar / Reading Group |
| 多出**一个东西**（作品、方案、数据、决定） | Workshop |
| 多出**一个人**（一个此前不在圈里的人留下了） | 公共活动 |

答不上来这个问题，说明这一场还没想清楚，**形式选了也是白选**。

## 二、形式对照

| 参与者要做的事 | 形式 | 前提 | 办砸的样子 |
|---|---|---|---|
| 接收一套他们目前没有的系统讲解 | `lecture` | 带领者确实有这套东西；听众起点接近 | 讲的人在台上现想，听的人在下面等 |
| 就一份共同材料交换判断 | `seminar` | **所有人提前读过**；存在真分歧 | 没读的人占多数，自动退化成讲解 |
| 一起读、一起停下来记 | `reading-group` | 材料适合当场读；篇幅可控 | 读完了，什么也没留下 |
| 动手做、练习、调查、模拟、产出 | `workshop` | 材料、场地、时长**落实过一次**；有可交付的东西 | 做不完；或者所有人做出来的都一样 |
| 让圈外的人进得来并留下 | `public-program` | 有新人入口、有可复用材料包、有第二个能带的人 | 来了很多人，没有一个再来 |
| 本地自定义形式 | `custom` | 规则**必须由使用者给出**，见 `local-vocabulary.md` | 按字面猜一个定义然后照着办 |

## 三、三条容易踩的

**1. "一半讲一半做"通常两头不着。** 真实结果多半是讲超时、做仓促。
要混就明确切成两段，各自有各自的产出，而不是模糊成一场。

**2. Seminar 的前提是硬的。** "大家应该会读"不是前提。没有把握时降级成
Reading Group（当场读），比办成一场失败的 Seminar 好。

**3. 同一个题目在不同形式下是不同的活动。** "介绍这本书"和"用这本书做一次调查"
不是详略之别，是两件事。不要因为形式换了就沿用同一份材料。

## 四、给出建议时

最多给三个候选，推荐其中一个，并写明判断依据来自哪一行。
**依据必须是"参与者要做什么"，不能是"这样比较好组织"。**
