# 表单骨架 / Artifact templates

七份。**一次只取当前阶段那一份**，不要整份加载。

每份都有必填字段。填不出来的字段写「待确认」并说明它挡住哪一步，
**不要用"待定""视情况而定"填过去**——那和空着一样，但看起来像填了。

---

## 1. 种子卡 / Seed Card

```markdown
- 发起人 / 发起团队：
- 原始兴趣、问题、书或材料：<具体到一本、一篇、一个题目>
- 为什么是现在：
- 目标参与者：<能点名的人，不是"对 X 感兴趣的同学">
- 希望参与者做什么：<对应 format-selection 的三选一：多出理解 / 东西 / 人>
- 已有的兴趣证据：<谁在什么时候说过什么>
- 可用的时间、场地、人、材料：
- 还没定的：
```

## 2. 孵化计划 / Incubation Plan

```markdown
- 这次要验证什么：<一句话，且必须是可能被证伪的>
- 试验对象：<具体几个人>
- 带领者：
- 前置材料 / 阅读：
- 分段与每段产出：<分几段、每段参与者留下什么。不排钟点，几点做什么由带领者自己排>
- 参与者要留下什么：<这一条空着就等于没有产物>
- 怎么观察、怎么记录：<谁记、记在哪>
- 成功标准：
- 停止标准：<什么情况下这次之后就不做了>
```

## 3. 孵化复盘 / Incubation Debrief

**这份是 G2 闸门的证据来源，不能省。**

```markdown
- 日期：
- 到场人数：
- 实际留下了什么：<对照计划里的"参与者要留下什么">
- 出乎意料的一条：<必填。完全符合预期说明没有在观察>
- 参与者提出的、发起人没想到的问题：
- 下一场的题目：<必须能指回本场的某一处，不是原计划表的下一项>
- 结论：继续 / 改了再试 / 停办
```

## 4. 系列图 / Catena Map

```markdown
- 系列总问题：<一个，不是一个主题>
- 外部输入：<不来自本系列任何一场的材料>

每一场：
| id | 子问题 | 形式 | 参与者要做的事 | consumes | produces | 带领者 |

- 整个系列最后形成什么：
```

可交给 `scripts/check_program.py catena` 检查连通性。各栏对应的 JSON 字段见
`references/check-program-input.md`，「外部输入」写进 `external_inputs`。
`consumes` / `produces` 用**同一串字符串**指代同一件产物，脚本靠字面匹配。

## 5. Workshop 计划 / Workshop Plan

```markdown
- 参与者最后获得的能力，或做出的东西：<二选一，写具体>
- 任务说明：<发给参与者的原话>
- 材料与场地：<已落实 / 待确认，逐项>
- 时长与分段：<总时长；分几段、每段参与者产出什么。只写产出，不排钟点，几点做什么由带领者自己排>
- 个人做的部分 / 小组做的部分：
- 带领者什么时候介入：<写触发条件，不写"随时">
- 参与者交付物：
- 反馈与评价方式：
- 安全、资源、无障碍限制：<没有就写"已核对，无">
```

## 6. 公共活动计划 / Public Program Plan

```markdown
- 面向哪类公众：<不是"所有人">
- 新人从哪儿进来：<具体入口>
- 哪些材料可以公开复用：
- 主持人与带领者要求：
- 场地与传播：
- 结束之后怎么保持联系：<没有这一条，来的人不会再来>
- 不在场也能办吗：<G4 的核心问题>
```

## 7. 停办记录 / Discontinued Record

**大多数种子会死。这份是这条链上最有价值、也最没人留的东西。**

```markdown
- 题目：
- 试了几次：
- 每次日期与到场人数：
- 停在哪一步：<对应哪一道闸的哪一条>
- 原因，三选一并说明：
  - [ ] 没人要 —— 该换题目
  - [ ] 没人带 —— 题目可能没问题，该找人
  - [ ] 时间不对 —— 可以原样再来一次
- 留下的可复用材料：
- 给下一次的一句话：
```

三种原因指向完全不同的处理，**不要合并成"效果不佳"**。
