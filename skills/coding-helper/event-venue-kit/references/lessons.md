# 教训 / Lessons：原站修过的错，和没修的坑

这里把六份盘点（身份、素材与印刷、地图、交互、长文报告、界面 CSS）里所有"出过的错"改写成**情境 → 出了什么错 → 规则**，按八个方面分组，最后附上观察到但原站没修的坑。

## 何时使用 / When to use

- **做完一个页面或功能之后**，按相关分组过一遍；这些是 `lint_floor.py` 查不到的。
- **定方案时**：标【地板 Fxx】的对应 `floor.md` 的条目，不随抽牌变化；括号里的 Fxx 是相关的地板条目；其余是做法。

## 怎么读 / How to read

- 规则是**做法**，不是禁令：换一种解法时，要能说清它怎样避免同一个错。
- 【地板】= 无障碍、正确性、隐私，不随抽牌变化。数字是原站数值；"推算"是按原站数值算的，"推断"是从修复反推的原因。
- 编号：I 身份、L 版面、C 颜色、T 字体与中文、M 地图、X 交互、D 数据与素材、O 运维；K 是没修的坑。†= 试跑站（科学节、书市、国际学校开放日、博物馆夜场）踩出、已修进套件的错，规则写现在的做法。

## 一、身份 / Identity

| # | 情境 | 出了什么错 | 规则 |
|---|---|---|---|
| I1 | 早期概念板里混进中文活动名 | 同一活动有两个名字 | brief 写明规范名和禁用字符串，再对成品跑正则 |
| I2 | 强隐喻（校队）招来道具：旗串、针织纹、燕尾旗箭头、滚动校名条 | 气质滑向"球队周边" | 选定后跑一轮减法，只留装置和网格；逐件问"它是装置，还是在模仿隐喻" |
| I3 | 撇号做成帽加长刺（约 45% 字高） | 次级字形抢数字的戏 | 次级字形服从字高线，不超过约 30%（定稿：28 单位的一枚楔形） |
| I4 | 3 的中臂断开留白缝；8 的上孔只剩 5.4 单位；2 与 8 之间纸白缺口像破洞 | 小内孔最先死 | 在 16 px 下压力测试内孔，内孔 ≥ 约 19 单位；缺口填边缘色，不留纸色 |
| I5 | 数字外轮廓相连，围出白色小岛 | 5 m 外读成多出的笔画 | 每个数字独立成章，间距大于轮廓宽（22 单位）；用模糊相关系数测（3 与 8：.68 → .39） |
| I6 | 三层标志缩到 48 px 以下糊成一团 | 小图不可辨 | 每个用途一个光学尺寸版本：≤ 48 px 实心双色，≥ 64 px 才用全层 |
| I7 | 词标字母与数字不是同一种声音，缺活动首字母 | 字标和数字像两家 | 画出来的字母出自同一套字母表：先画主角字形，提参数，程序化生成其余 |
| I8 | 首版是"通用苹果风"（系统宋体、胶囊按钮、半透明栏）；概念里还有中文衬线争主次 | 好看但没性格，三天后整体换成品牌 | UI 词汇从品牌物件推出；"手感层"（按压反馈、弹簧、无障碍偏好）与"皮肤层"分开建，换皮不换手感；每类页面选一个实物隐喻（入口屏、桌牌、门牌）；中文不与展示字体竞争 |
| I9 | 楼梯上下用旗帜三角 | 功能符号不标准 | 功能符号用标准形（90° 箭头），斜向只留给楼梯入口 |
| I10 | 集章卡的格子与章的尺寸不配 | 载体和工具不配套 | 按真实工具定载体尺寸（25 × 18 mm 的章放进 31 × 20 mm 的格） |
| I11 | Gloock 自带短横只有笔画的 6%，"201 204" 读成两个数 | 范围号被读错 | 范围符号自画（0.075em × 0.42em，或 28 × 9 的纸白条） |
| I12 | 设计稿的学校名单和楼层是旧楼数据 | 示意数据被当真 | 身份素材只贡献数字和形状；活数据只有一个事实来源；先核对场地再画；示意图写"示意" |
| I13 | 主办方晚到的 logo 与体系冲突，白底位图在深色模式出现矩形 | 要么重画，要么硬贴 | 贴纸式裁切隔离，体系继续承担身份；母版加脚本让替换变成一条命令 |
| I14† | brief 要"可旋转"，冻结成 `projection=3d`；3d 含 oblique，抽到的牌正是 oblique（拖动 = 平移） | 选完才发现，adjust 成 orbit 又和原站撞两项；重发后无关参数也变 | "能转 / 可旋转"冻结成 `--keep projection=rotate`（orbit 或 exploded，两者拖动都转）；"立体"才用 `3d`；一起写 `lead=zh` 等，不挪别的参数。已选定才发现：`draw.py adjust projection=orbit` 再 `install.py --update`，不手改、不重抽；oblique 的牌提示条不写"旋转"（map-craft §15） |
| I15† | 无照片的使用者：盘点要"能拍照的实物"，又说"不要编" | 全标"假"，又怕滑向品类母题 | 事实写"未知"；实物按活动类型推断、标"假设"并请使用者确认，只定外观、不进页面文字（derive §3.1）；样张用 `--venue`，在前台标签看 |
| I16† | 方向的强调色相只有一个范围（目录卡印台永远是紫） | 同一方向的不同项目强调色一样；活动的物件是红印台时只能事后硬改 | 方向的 `b`（常含 `paper` / `a`）写成 2–4 个色相家族，抽牌先抽家族再取色相；家族是候选，盘点里定了色的物件优先：抽牌前 `--keep b=#hex`，选定后才发现用 `adjust`（derive §5、floor F03） |
| I17† | herbarium 抽给博物馆夜场：叶形标签（品类母题）通过 `--leaf` 写进十几处，盘点里没有植物；方向没标出哪些是可拿掉的道具 | 页面上满是叶子，只能手改配方 CSS；还原要翻十几处 | 方向把品类母题列成 `props`（`--prop-*` + 关闭值 `off`），配方只读 `var(--prop-x, 开的值)`、从不声明；逐项对盘点，有依据才留，其余设成关闭值（derive §8.1、craft-details R08；`specimen.py --props off` 先比一眼） |

## 二、版面与密度 / Layout and density

| # | 情境 | 出了什么错 | 规则 |
|---|---|---|---|
| L1 | 首页照搬入口大屏，手机上太高 | 滚动成本高 | 密度是一等需求：保留可识别区（深蓝窄条），其余收紧，量页面长度（原站手机页缩短约 40%） |
| L2 | 路线弹层在矮手机上盖住地图；`display:none` 藏非当前步 | 812 px 手机只剩约 170 px 地图；CSS 编号重置，每步都是"1" | 按视口高度设计；≤ 900 px 高只显示当前步，运行态弹层 ≤ 54dvh；用 `visibility:hidden; height:0` 藏；状态 class 缺失时 `:has()` 兜底 |
| L3 | 深色弹层里输入框与弹层同色（tint == 底） | 输入框消失 | 凡表面等于 tint 的地方，局部重定义 tint |
| L4 | 通用滚动细线与阅读进度线叠在栏下同一位置 | 两条 2 px 线叠加 | 每个位置只有一个所有者；阅读页隐藏通用线 |
| L5 | 宽表在手机上缩小到看不清，或撑破布局 | 表不可用 | 横向滚动 + 首列粘住 + 可聚焦；有色带里重指背景变量，粘性列才不露底 |
| L6 | 粘性章首比视口还高 | 底部被截断 | `max-height: calc(100vh - 110px)` 加 `overflow-y: auto` |
| L7 | 锚点被粘性栏盖住 | 跳转后看不见标题 | 每个锚点目标设 `scroll-margin-top`（70 / 76 / 80 px）（F19） |
| L8 | 报告的"说明"节占用 01–04 编号 | 编号乱 | 说明节用不编号的 intro 类，字更小更灰 |
| L9 | 所有报告套同一个四章模板 | 各组结构不同（3–12 部分），模板放不下 | 结构跟随内容；导航线按数量自适应；小节 chip 仅 ≥ 3 个小节时出现；长内容折叠 |
| L10 | 引用跳转到折叠的来源列表 | 点了没反应 | 跳转前先展开容器；测试所有 `href="#x"` 都有对应 `id`（F21） |
| L11 | 告示页高设成 210 mm | Chrome 每张多出一页空白 | 页高 209.8 mm，渲染后断言 PDF 页数 |
| L12† | 配方给 `.evk-mark` 设 `font-size:0`，em 右边距归零；弹层变高后地图没重算 | 标记贴名字；地图被盖住 | 间距用 rem / px；弹层自身尺寸变了也重算（`fitAbove.watch` 已观察） |
| L13† | 配方给 `.evk-search` 画横格底纹、替换 base 的 `data-fit` 名字字号、用 `.evk-entity-head > p:not(.evk-eyebrow)`；base 的 `.evk-num span` 命中 `<b>` 里的 `.cn` | 横格穿过输入文字；长校名不缩小（EP-2 失效）；首页抬头里每个 `<p>` 变页脚格；中文数值缩成小灰字 | 配方缩放 base 的梯度，不替换：名字只设 `--name-min` / `--name-vw` / `--name-max`，`data-fit` 再按档缩放；抬头里的附加行用明确类名 `.evk-entity-sub`（另一种语言的名字）、`.evk-entity-line`（一句话）、`.evk-entity-code`；数字的单位用 `small` / `.unit`，标签是 `.evk-num > span`；输入框只留一条基线（`border-bottom`），不铺横格底纹 |
| L14† | 起步页 `.sp-tools` 网格被 5 个楼层钮加路线钮撑宽 3 px，4F 钮在屏外；配方给 `.evk-seg` 写 `overflow:hidden`，盖掉 base 的横滑；`.sp-note` 的中英两句行内连成一行；翻页链接带下划线；`.evk-lines` 低于 44 px | 375 px 点不到最后一个楼层钮；放不下的分段被裁掉；中英句子粘连 | 放分段的网格列写 `minmax(0, 1fr)`，分段在自己里面横滑（配方不写 `overflow:hidden`，圆角写 `border-radius`）；两种语言各占一行（块，不是行内）；链接样式取 base；小控件可点区 ≥ 44 × 44，配方改宽度时补 `min-width`；festival-riso、transit-signage、heraldry 里宽泛的 `.evk-entity-head p` 换成 `.evk-entity-sub` / `.evk-entity-line`（ux-contracts MP-8、F19，craft-details BT08） |

## 三、颜色与对比 / Colour and contrast

| # | 情境 | 出了什么错 | 规则 |
|---|---|---|---|
| C1 | 实体品牌色直接当文字色 | 4 / 52 不及格（Caltech 2.60、UCSD 2.61、Princeton 2.78、UNC 2.16，推算） | 【地板 F04】文字用的颜色从实体色派生（向墨色混合到 ≥ 4.6），并对每个实例写测试 |
| C2 | 主题接口只有 3 个变量 | 站点最终要 7 个 | 按**角色**而不是按颜色数设计接口：fill、text、on、soft、line、dk、soft-dk（F04） |
| C3 | 浅色品牌上放白字（Caltech 橙加白 2.6:1） | 不可读 | `on` 在纸和墨之间选对比高者，保留原色作 fill；两者都不行才压暗 fill |
| C4 | 深色品牌落在深藏青上（UChicago `#370404` 对夜色 1.05） | 色块消失 | 深色模式保色相提亮，饱和度封顶 .62；线退回中性（F05） |
| C5 | 红字落在深蓝上 2.47:1 | 字发虚 | 【地板 F02】文字强调色与填充强调色分开 token；深色模式提亮文字用红（`#FF7084`、导航带上 `#FF8A99`）；写出禁用的颜色对 |
| C6 | 路线的楼梯与步行同红 | 两种含义一种颜色 | 第二种含义第二种色相（琥珀），配深色版；与主强调色相差 ≥ 50°（F03、F07） |
| C7 | 选择框箭头是 data-URI | 深色模式跟不上 | 背景图标用 `currentColor` 的 SVG 或 mask，否则手写深色变体（F06） |
| C8 | 全局 `a:hover` 把按钮文字变成红底红字 | 按钮文字消失 | 按钮自己设各状态的颜色（F12） |
| C9 | 触屏上 hover 样式粘住 | 点完仍高亮 | 所有 hover 规则放在 `@media (hover: hover)` 里（F12） |
| C10† | `--m-select` 是整间房的填色，lint 却要它对楼板 ≥ 3:1；`--climb` 只保 3:1 却被拿来写小字 | 规定互相打架；深色小字约 3.1:1 | 拆开：`--m-select` 边线 + `--m-select-fill` 淡染；文字一律 `--climb-text`（≥ 4.5，同色相）（F02、F03） |
| C11† | 深纸牌上，够不到 4.6 的字版直接落到墨色；配方里 `--climb` 用自己重声明 | 绿、紫、蓝成了同一个白；循环引用不生效 | 字版朝墨色一端走，深纸上提亮保色相，L = 0.98 仍不够才落墨色（F04）；换底前先存外层值 |
| C12† | 配方对纸面写 `.evk-k { color: var(--a-text) }`，填色按钮、按下的分段、填色标签里的双语配对也吃到它 | 橙底按钮里浅字压浅底，"全部"那颗按钮整个看不见；lint 只查令牌，漏了 | 【地板 F02】填色面里的配对继承该面的字色（base.css "FILLS"）；分段的选中态 `aria-selected` 与 `aria-pressed` 都要覆盖；十二个配方各渲染主按钮、按下的分段、填色标签，浅深各一，逐一量过 |
| C13† | 悬停把按钮降到 `opacity .88`；淡染行（当前步骤、`.is-on` 的 chip、卡片）上的字沿用纸面字色；深色里实体色别名只设在实体元素内 | 4.6:1 的按钮字掉到约 3.8:1；淡染行字不足 4.5；导航和 chip 的悬停在深色里浅字压浅底 | 悬停用下划线，`--hover-opacity` 是可选旋钮；淡染上的实体字用 `--e-ink-t`；深色别名也设在 `:root`（F12、F04） |

## 四、字体与中文排版 / Type and CJK

| # | 情境 | 出了什么错 | 规则 |
|---|---|---|---|
| T1 | 模板换行在两个汉字之间渲染出空格 | 中文行里有缝 | 构建时去掉 CJK 与 CJK 之间的空白，生成时插入 CJK 与拉丁 / 数字之间的空格；`line-break: strict`（F10） |
| T2 | Zilla 默认旧式数字 | "3 floors" 里的 3 掉到基线下 | 数据数字强制 `lining-nums tabular-nums` |
| T3 | 长中文名断行不当，留两字孤行 | 看着像模板 | 次要文字的断行手控：`.nw` 词块，只在"大学 / 学院"后换行，第二行缩进一字；`keep-all` 只给拉丁名（中文名用 `text-wrap: balance`，keep-all 会留单字孤行） |
| T4 | 居中的宽字距大写 | 尾部字距把整行推偏 | `margin-right: -.22em`（中文 -.12em）补偿 |
| T5 | 中文嵌在大写标签里继承拉丁字距 | 汉字松散 | `.cn` 重置：不转大写，字距 .04–.12em |
| T6 | 混排行用 `center` 对齐 | 汉字偏低 | 混排行用 `align-items: baseline` |
| T7 | Latin 子集不含 →（U+2192） | 箭头回退到别的字体 | 用到的符号逐个对照子集，缺的补进去或改画 SVG |
| T8† | "英文主、中文灰"写死在 `.en` / `.cn` 上；中文行只靠 `<html lang>` | 中文主要改十几个选择器；汉字用拉丁展示字体、负字距 | 层级认位置、排印认语言，`lead` 是滚牌参数（F08，B09）；中文行自带 `lang` 或 `.cn` |
| T9† | 牌上是 Google 字体，套件无字体文件，地板禁运行时第三方 | 不知去哪拿；DESIGN.md 写着牌上的字，页面是回落字 | 先问能不能下载：不能就系统回落并写进 DESIGN.md；能就自托管 + 子集（print-parity §5） |
| T10† | 起步页搜索框的中文例子写成"例如 night"：汉字间留了空格，例子是出现最多的原始标签；specimen 的摘要句"在二层 东回廊" | 违反 F10；中文页里冒出英文标签；人不会敲 `night` | 一切**拼出来**的句子（路线句、搜索例子、样张摘要）最后都过同一个空格规则：汉字间无空格，汉字与拉丁 / 数字之间恰好一个；例子取一两个真实名称（主语言，没有就取房号），从不取标签 id（wayfinding-copy §5、§6.4） |

## 五、地图 / Map

| # | 情境 | 出了什么错 | 规则 |
|---|---|---|---|
| M1 | 预渲染 4 个角度的等轴测 SVG | 看不出"这个楼梯去哪"，不能看墙后 | 空间导航用连续操作（惯性、弹簧、橡皮筋）代替几个固定视角 |
| M2 | 房号画在房间中心 | 人在门口做判断 | 房号站在门口（铭牌），用品牌自己的物件 |
| M3 | 叠层图看不出哪个楼梯连哪一层 | 层间关系缺失 | 用最轻的幽灵（半透明竖井、虚线角）表达 |
| M4 | 两层叠放互相遮挡，上层盖住路线；步行与楼梯同红；步行时其他房间满强度 | 路线看不清 | 路线叠加单独一遍，画在所有楼层之后；叠层间距由视图几何解出；聚焦分级（其余 .26，步进时细节 .16）；提供"全览" |
| M5 | 长墙排序出错，拐角有缺口 | 画家算法出伪影 | 墙切成 ≤ 2.4 m 的小段，端头外延半个墙厚 |
| M6 | 画布抢了页面滚动 | 手机上划不动页面 | `touch-action: pan-y`；单指不倾斜，两指才倾斜；滚轮只在 ctrl 时缩放；`setPointerCapture` 包 try / catch |
| M7 | 松手后出现幽灵惯性或跳动 | 释放速度不对 | 速度取最近 90 ms 的窗口；手指停留 > 80 ms 则速度归零 |
| M8 | 静止时不重绘，网页字体和图片晚到 | 画布文字是旧的 | 每个异步输入都踢一次重绘：`document.fonts.load`、图片 `onload`、深色模式变化（F17） |
| M9 | 窗口缩放时镜头重新缓动 | 抖动 | 布局变化立刻重新取景，不缓动，保留已转的 yaw |
| M10 | 弹层盖住目标 | 看不到要找的房间 | 把弹层"落定处"（不是动画中的位置）作为安全区喂给相机（lift / pad） |

## 九、没修的已知坑 / Known pitfalls

盘点时观察到、原站没修的。别照抄，也别以为它们"本来就这样"。

**身份与常数**

- **K1** 评审排名与最终选择不一致（C 排第 1，D 被建成），没有任何记录说明原因 → 把选择理由写进项目的 `DESIGN.md`。
- **K2** 常数漂移：条纹 32:10:16:10:32 / 30:10:20:10:30 / 12:4:6:4:12；红色 CMYK 两种写法；外缘 4.4 对 7.4；章字高 11 mm 对约 8.4 mm；主章 50 × 35 对 35 × 44.33 mm；红底房号"实心白"对三层；LED 5760 × 1920 对 2880 × 960 → 选一个常数，其余生成，过期的明说。
- **K3** 同一比例规则在一份指南里两种写法（60/30/10 的色块标签对比例条）→ 比例只写一处。
- **K4** 手册 hero 把大红词放在深蓝上（2.47:1），与自己的规则矛盾 → 规则与自家 hero 不矛盾。
- **K5** 调色板在告示脚本、网页 CSS、设计 token 三处各抄一份 → 读同一份 token。

**颜色**

- **K6** 对比度测试只覆盖实体色：当前步骤英文标签 `#B45309` 落在 `#ECE8DF` 上 4.11:1，深色模式强调字 `#FF7084` 落在 `#1E3A66` 上 4.27:1，金色编号 2.94:1（作者接受为装饰）→ 测试覆盖所有"文字 × 表面"组合。
- **K7** 步骤方块用原色而不是深色版 fill：深色模式下 UChicago 1.05、Columbia 1.35，方块消失，只剩数字悬浮（推断，未验证）→ 用有深色版的 fill 变量并实测。
- **K8** 访谈带次要文字靠 `opacity: .82`：叠在 LSE 3.75、Brown 4.30 上不过线（现有访谈带没中招）→ 次要文字用实色 token。
- **K9** 深色模式下 19 个蓝系学校提亮后收敛到相近的中蓝（JHU 与 Duke 都变 `#5888D1`）→ 区分别只靠颜色，留校徽和校名。
- **K10** 条纹用原始深蓝，深色模式下外侧带与底只有 1.16:1 → 条纹各段也走 token。
- **K11** `prefers-contrast: more` 因选择器特异性低，深色模式下被忽略 → 两种模式都测高对比。

**版面与字体**

- **K12** 打印名字 `overflow: hidden` 加行高 .9，切平了 Georgia Tech 的 g → `overflow: clip` 加 `overflow-clip-margin`，或底部留边距。
- **K13** 微标签 8.6–10 px（0.54–0.64 rem），EN ≥ 1.1 × CN 在微型大写里不成立（0.73–1.06）→ 规则写成"英文视觉上为主"，换更窄的字体时先查微标签。
- **K14** 【地板 F12】触控目标：导航链接约 38 px、`.btn-small` 38 px、分部导航按钮 42 px，都低于 44 px。
- **K15** 数字条标签行在相邻格不对齐（带说明的格把标签挤低）→ 标签行用 grid 对齐。
- **K16** 手机上小节 chip 没有"当前"状态（样式只写在 ≥ 980 px 的粘性栏里）→ 状态样式不分断点。
- **K17** `<select>` 选项只有中文，英文在前的规则在这里失效 → 同样的主次。
- **K18** 没有 skip link；`viewport-fit=cover` 却没用左右 safe-area → 两者都做。
- **K19** `srcset` 只有两个候选，视网膜手机取大图；打印徽章 640 px RGBA 共 12 MB（见 `print-parity.md`）。
- **K20** 单个 URL 超长（43 字符）把一个二维码推到版本 4 → 检查整套 URL 的最大长度。
- **K21** 注释、文案与代码不一致（"58 mm 约 280 dpi" 对 34 mm 的盘；404 说不区分大小写而 README 说区分）→ 改代码时同改注释；一种行为一种说法。

**交互与地图**

- **K22** 点击步骤按钮会重建整个列表，焦点丢失 → 重渲染时保留焦点，或只更新变化的节点。
- **K23** `plan()` 为空时静默返回 → 失败也要有可见反馈。
- **K24** 楼层措辞不一致（"上到 2 层"对"二层大堂"），位置行层在前、起点下拉房间在前；导览模式的上一个 / 下一个跳学校，段内只能点行 → 一套词、一个顺序、一个层级（楼层的词现在是 `floors[].short` 与 `name` 两个字段，见 D10†）。
- **K25** 【地板 F14】减弱动效只在加载时读一次，列表不完整（部分颜色 / 透明度过渡仍在）→ 订阅变化，所有过渡一起处理。
- **K26** 非模态弹层没有 `aria-modal`、焦点陷阱，Esc 只在 document 层处理 → 非模态也要写明语义并测。
- **K27** 魔法数字绑定顶栏高度（64、70–84 px），没有 `visualViewport` 处理屏幕键盘 → 从 DOM 读或统一 token；弹层几何用 `visualViewport`。
