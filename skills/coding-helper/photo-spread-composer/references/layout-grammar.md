# 版面语法的来由 / Where the grammar comes from

`SKILL.md` 里的 G1–G10 是结论，这里是它们从哪来、以及带高方程的推导。

## 这份语法从哪来

它归纳自**报纸与刊物摄影版的通行做法**：横带堆叠、带内等高、两端顶齐、图注归组、署名随图。
这套做法在印刷业里存在了一个多世纪，不属于任何一家出版物。

**要借鉴的是语法，不是身份。** 具体某一家刊物的报头、刊名、字体搭配、红黑配色的用法，
是它的识别系统，不能复制。做出来的东西不能让人误以为是某一期某一版。这条写在 SKILL.md 的边界里。

## 带高方程的推导

一带之内所有 item 等高、左右顶到版心两边。设：

- `W` 版心宽 = 页宽 − 2×页边距
- `g` 天沟
- `h` 带高（**待解**）
- 带内 `n` 个 item

三种 item 各自贡献的宽度：

**photo**，长宽比 `a = 宽/高`。等高即高为 `h`，故宽 `w = a·h`。

**stack**（竖向叠放 `m` 张，共用宽度 `w`）。第 j 张的高为 `w/aⱼ`，
加上 `m−1` 条天沟，总高须等于 `h`：

```
w·Σ(1/aⱼ) + (m−1)·g = h
令 S = Σ(1/aⱼ)
⟹ w = (h − (m−1)·g) / S
```

**text**，宽度固定为 `wₖ`，与 `h` 无关。

三者宽度加上 `n−1` 条天沟等于 `W`：

```
Σ aᵢ·h  +  Σ (h − (mⱼ−1)g)/Sⱼ  +  Σ wₖ  +  (n−1)g  =  W
```

把 `h` 提出来：

```
h · [ Σ aᵢ + Σ 1/Sⱼ ]  =  W − (n−1)g − Σ wₖ + Σ (mⱼ−1)g/Sⱼ
```

右边全是已知量，所以 `h` 唯一确定。**这就是"位置不需要写"的原因**——
给定分带与顺序，版面只有一个解。

### 几条由方程直接读出的结论

- **item 越多，带越矮。** 因为分母 `Σaᵢ` 变大。想让某一带成为视觉重点，就让它 item 少
- **竖构图会把带压高。** 竖图 `a < 1`，对分母贡献小，解出的 `h` 就大。
  一带里混一张竖图，整带会明显变高——这是 SKILL.md 里"竖图更适合 stack 或独占一带"的由来
- **文字栏越宽，带越矮。** 它从常数项里直接减掉宽度
- **带内至少要有一个 photo 或 stack。** 全是 text 时分母为 0，方程无解，脚本会报错

## CSS 怎么表达这个解

`flex-basis: 0` 加 `flex-grow: wᵢ`：剩余空间（`W − (n−1)g`）按 grow 比例分配。
因为 `Σwᵢ` 恰好等于剩余空间，每个 item 拿到的正是解出的 `wᵢ`。

**这个写法是尺度无关的**：页面缩放时比例不变，所以同一份 HTML 在屏幕预览和打印下版式一致。

两处需要注意的实现细节：

1. **photo 写 `aspect-ratio`，让高度由宽度推出**，于是一带自然等高，不需要写任何高度值
2. **stack 必须自己带 `aspect-ratio`（由脚本按 `w/h` 填）**。
   否则它的高度不确定，内部 `flex-basis: 0` 的子图会塌成 0 高。
   stack 的子图**不写** `aspect-ratio`——它们的高度由纵向 flex 按 `1/aⱼ` 分配，
   宽度是 stack 的宽度，两者之比正好等于原长宽比（见上面推导）。再写一个 aspect-ratio 会和 flex 争主轴尺寸

第 2 条是实际踩过的坑：初版没给 stack 写 aspect-ratio，渲染出来那一列高 11px。

## 分辨率门槛

```
需要的像素宽 = 显示宽度(mm) ÷ 25.4 × dpi
```

- 印刷惯例 300dpi；报纸类粗网点印刷 200 也可接受；纯屏幕浏览 150 足够
- **不足不放大。** 放大后屏幕上看着还行，打印出来是糊的，而这个差别使用者在交付前看不出来
- 通过的照片会被缩到实际需要的尺寸再内联，所以成品体积由版面尺寸决定，不由原图决定

## 留给判断的部分为什么不给默认值

分带、主次、顺序这些，取决于这一组照片本身：哪张有决定性瞬间、哪张的留白能接住图注、
哪两张放一起会互相抵消。给一个默认值，等于对所有照片组给同一个答案，
那个答案对绝大多数组都是错的。

所以 SKILL.md 里那张"留给判断的"表格是**故意留白**的，不是没写完。
