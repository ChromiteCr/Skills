# 发布会风格演示 / Keynote Deck Builder

把一段描述、一份演讲稿或一份现有 PPT，做成发布会主题演讲那种片子：一片一个概念，字大，留白多，讲的人是主角。

**必须分两步。** 第一步只产出叙事大纲，第二步才出 HTML。中间等使用者确认。
这种风格的成败几乎全在"哪句话该单独占一张片、哪个数字值得放大"上。一步到位等于把这些判断藏进 HTML，
使用者只能全盘接受或者推倒重来。

取证记录在 `references/stage-style-research.md`，正文每条硬规则都能指回那里。分 A（有依据）/ B（单一来源）/ C（未证实）三档，**C 档不作为规则依据**。

## 何时使用 / When to use

- 有一个产品、项目或功能要做发布式的演示
- 手上有演讲稿，要配一套片子
- 现有的 PPT 太密，要改成这种大字少字的风格
- 要一份能直接投屏或导成 PDF 的演示

**不适用于** / Not for：

- 只要一张总结图，不要整套片 → 用 `launch-summary-panel`
- 要做数据密集的汇报、周报、教学讲义 → 这套风格靠删信息取胜，塞不进详细内容，硬套会两头不讨好
- 要给项目定一整套视觉语言 → 用 `ui-design-system-builder`
- 要一份逐字讲稿 → 这个技能做片子，讲稿只当输入

## 输入 / Inputs

三种入口，先判断使用者在哪一种，**不要三种都按第一种处理**：

| 使用者给的 | 从哪开始 | 关键动作 |
|---|---|---|
| 一句话或一堆产品材料 | 走完整流程 | 缺叙事骨架，要先问清"现状的问题是什么" |
| **一份演讲稿** | 直接切分拍点 | **把句子切成拍点，片上只放碎片、数字或图，绝不贴整句** |
| 一份现有 `.pptx` | 先读出来再重构 | 用 `scripts/read_pptx.py` 提取，一张密片通常要拆成三到五张 |

只有两件事需要问，其余从材料里读：

1. **现状的问题是什么** —— 这套结构里问题必须先于产品出场，没有问题就没有张力（A 档）
2. 有没有必须出现的内容，或必须回避的说法

材料不足时说清缺什么。**不要用常识补齐产品参数。**

### 拿到演讲稿时怎么切

这是最容易做错的一步。演讲稿的句子**不是**片上的文字。

```
讲稿：  「我们发现用户平均要点七次才能完成一笔转账，这个流程从 2019 年就没变过。」
错的做法：把这句话整句放到片上
对的做法：片上只有一个字号极大的「7 次」，下面一行小字「完成一笔转账」
```

理由：片是覆在讲话之上的一层，不是承载信息的主体。讲的人重复片上文字会让听众同时读和听，造成认知过载（A 档）。Jobs 有过五分钟只对着 33 个字讲的段落。

所以每个拍点产出的是**片上文字 + 讲稿留给人说的部分**两栏，大纲里要分开写。

## 阶段一：deck-outline.md

用 `templates/deck-outline.md` 起草。这一步不写任何 HTML。

### 叙事拍点

按这条主线排，缺哪拍就明说缺哪拍，不要凑：

```
现状与问题 → 让人感到这个问题 → 揭示 → 展开（三点）→ 演示 → 数字 → 价格与可得 → 收束
```

依据是 Duarte 的"现状 / 可能"来回摆荡与 Gallo 拆的九拍（A/B 档）。两条可直接用的：

- **问题先于产品**，用人话讲问题，不用技术约束讲
- **展开用三点**。三是工作记忆的容量，也是这套演讲反复出现的计数习惯（A 档）

### 逐片清单

每片一行，必须有这几栏：

| 栏 | 要求 |
|---|---|
| 序号 | 连续 |
| 拍点 | 属于上面哪一拍 |
| 片型 | 从下面十四类里选 |
| 片上文字 | **实际会印在片上的字**，按字数上限写 |
| 讲的人说什么 | 一句话概括，**不能与片上文字重复** |
| 数字出处 | 有数字就标来源；材料里没有的写 **【未确认】** |

片型十八类：标题卡、单句大字、大数字、产品主图、功能名、bento 网格、规格密排、双列对比、图表、logo 墙、章节分隔、价格与上市、one more thing、环保、**引语**、**流程条**、**双栏人物**、**全黑过场**。

后四类是实际做片子时补的，研究里的十四类不够用：

- **引语**：用户原话、评审意见、调研摘录。**出处必须写在引语下面**；没有出处就不要做成引语片，那是把编的话当证据用
- **流程条**：有先后顺序的步骤。这是项目符号最常见的替代品，五步以内一张片，超过五步拆开
- **双栏人物**：分工、团队、职责。职责连成一句写，不要拆成项目符号塞回去
- **全黑过场**：现场切视频或实机演示时停在这一张。**不要放「演示视频播放位」这类占位框**——
  占位框是给做片子的人看的，投出来观众只会看到一个空框

### 当这不是发布会

答辩、课程汇报、路演、立项评审都能用这套视觉，但**拍点要改，而且有些片不能删**。

| 场合 | 拍点怎么改 |
|---|---|
| 答辩 / 课程汇报 | 「价格与可得」换成「这一阶段做到了什么」，收束前加分工。评委看的是工程量，三处攻关各给一张双列对比比笼统说"性能提升"有用 |
| 路演 | 「展开三点」后面加市场与商业模式，数字那一拍分成产品指标与经营指标两段 |
| 立项评审 | 「揭示」之后先给可行性，再给三点 |

**课程或评分表要求的页面不能自作主张删掉。** 目录页、分工页、工具使用说明页在这套风格里都没有位置，
但它们可能是评分项。处理办法是**问，不是删**：在大纲的舍弃项里单独列出来，写清楚"这几页按这套风格
去掉了，如果评分表要求必须有，我加回来"。

**要看密度的场合要提醒使用者。** 这套风格靠删信息取胜，而答辩评委有时候恰恰要看你到底做了多少。
可行的办法是把原始材料当讲义发，这份当投影用。**这一句要主动说，不要等使用者发现片子太空。**

### 片量

按讲的时长估，**宁少勿多**。一片一个概念意味着片数由概念数决定，不由时长决定。
公开资料里查不到"每分钟几张片"的可靠实测（C 档），所以**不要给使用者一个每分钟片数的公式**，
按概念数报数，并说明这是按概念算的。

### 舍弃项

哪些内容没上片，为什么。这一块不能省——使用者最常见的反馈就是"某某怎么没了"，
写清楚比等他问一遍再解释省事。

写完停下等确认。**不要在同一轮里顺手把 HTML 也生成了。**

## 阶段二：deck.html

确认之后用 `templates/deck.html` 填充。

### 技术要求

- 单文件，CSS 与 JS 全部内联，**不引任何外部资源**（字体、图标、CDN 一律不引），离线打开必须一致
- 每片固定 1920×1080，一屏一片，`scroll-snap` 翻页，方向键与空格也能翻
- 字体只走 `system-ui, -apple-system` 系统栈。**不要在 CSS 里写 `"SF Pro Display"`**——
  本机字体文件名是 `SFNS.ttf`，按那个名字引不可靠；而且 SF Pro 的 EULA 只允许做 Apple 系统界面的
  mockup，不允许随文件分发（A 档）
- 深色为默认，浅色可切；切换按钮放在舞台外，投屏和截图里不出现

### 字号阶梯

**下限 40px。** 来源有两条互不相关的依据：Apple 内部"字号不低于 30pt"（30pt = 40px，A 档），
以及按视角几何独立推的结果——40px 在视距等于 8 个屏高处是 15.9 弧分，正好卡在舒适阈值上
（推导见 references 第 9 节）。这条规则的作用是逼着删内容，所以**塞不下就删字，不是缩字号**。

**深礼堂要提到 48px。** 视距超过 10 个屏高时 40px 掉到 12.7 弧分，低于舒适阈值。
问清楚是会议室还是礼堂，礼堂就整体上调一档。

**字重不低于 400。** Thin 与 Light 在投影上笔画会糊掉或直接消失（A 档）。

| 用途 | 字号 | 字数上限 |
|---|---|---|
| 大数字 | 320px | 数字加单位，不带句子 |
| 单句大字 | 180px | 中文 12 字 / 英文 8 词 |
| 功能名 | 120px | 中文 8 字 |
| 片标题 | 96px | 中文 16 字 |
| 说明小字 | 44px | 中文 24 字 |
| bento 格标签 | 40px | 中文 6 字 |

超了就是没想清楚。长段落一律拆片或删掉。

### 中文排版

产出的几乎都是中文片子，但这套风格的公开资料全是拉丁文字的。下面几条是中文特有的坑。

模板里已经写好了，**改模板时不要删掉**：

```css
font-synthesis: none;      /* 苹方 700/800/900 渲染相同，上限是 Semibold。
                              禁掉伪粗体，让它退到真有的那一档 */
line-break: strict;        /* 避头尾禁则：句号逗号不落行首 */
text-autospace: normal;    /* 中西文之间自动插 1/4 em，「30 天」不用手工调 */
font-optical-sizing: auto; /* SF Pro 是可变字体，20pt 以上切 Display */
```

- **字重别声明 700 以上**，中文拿不到，声明了也是原地踏步。要更重的观感靠字号不靠字重
- **行高比拉丁紧**：CJK 字身框没有升降部余量。100px 以上取 1.0 到 1.15
- **字距用 0 或轻微负值**，正值不要超过 0.15em，中文的字距容忍度远小于拉丁
- **`line-break: strict` 只阻止坏断行，不会替你挑好断点**。大字标题断在哪要手写 `<br>`，
  按语义断，不要让它自己折
- **中文标题 8 到 15 字**。中文单字信息密度高于拉丁单词，同样一张片**字数更少而信息更多**，
  所以不要按英文的词数直接换算
- 字体栈必须写全后备：苹方是 macOS 独占，Windows 落到微软雅黑

### 视觉规则

- **底色不用纯黑**，用近黑的多层渐变，模拟舞台幕布上的光晕；浅色主题用近白不用纯白，纯白投影刺眼（B 档）
- **重点色一支为主**，最多两支，且只用在数字、图表、需要区分的分类上。**不做装饰性用色**（A 档）
- 不写死 `#007AFF` 这类"系统蓝"。那是社区取样值不是官方规格（A 档），要用就让使用者给主色
- **不放装饰件**：正片不要页码、页眉页脚、边框、卡片容器；logo 只允许出现在首尾片（B 档）
- **bento 一张片 8 到 12 格封顶**，超过 12 格构图就垮；锚点格面积约为支撑格的两倍；
  格子里放数字不放标题（B 档）
- **bento 不是默认解**。它 2024 年之后已经用滥，设计圈批评其同质化。
  信息本身没有主次差别时，用规格密排或流程条比硬套 bento 好
- **对比度**：正文 4.5:1、大字 3:1 是底线（WCAG）。投影有环境光会吃掉对比度，
  500 lux 下标称 1000:1 的投影机实际掉到 50:1 以下，所以目标定 7:1。模板里的
  `--muted` / `--faint` 透明度是量过的，**改配色后要重新量，不要凭眼睛调**
- **深底还是浅底没有普适答案**，对比度比色相重要。暗房用深色主题，亮房间切浅色，
  浅色底用近白不用纯白
- 内容离边留 10–15%（1920 宽对应 192–288px）（B 档）
- 产品位放**占位图**，居中浮着，留白占四到五成，图不出血不压边（B 档）
- 数字加 `font-variant-numeric: tabular-nums`
- 转场只用溶解与位移，**不要写具体时长当"苹果的参数"**——流传的那些是 Keynote 应用的默认值，
  不是对真实发布会的实测（C 档）

### 图表：唯一不能照抄参考对象的地方

整个 skill 都在借鉴发布会的做法，**图表这一处要反着来**。苹果自己的图表被公开批评过：
iPhone 累计销量图整个纵轴刻度缺失，iPad 那张低估实际销量约三成（A 档）。

- **柱状图基线必须从零起**。Correll 等（CHI 2020）与 Pandey 等（2015）都实测到截断纵轴
  造成系统性误读，效应量为"大"；他们还专门检验了"折线图可以豁免"这个流行说法，**不能**；
  **加断轴标记也不能缓解**
- **折线图可以不带零轴，但要标出来**。数据接近零就带上零轴，远离零（如 90 到 200 的区间）
  可以不带，此时必须写明"基线非零"
- **禁双纵轴**。两个量纲不同就画两张并排的图，共用横轴。双轴靠调两侧量程能造出任意相关性
- **禁 3D、禁饼图、禁面积或半径编码**。人对面积的感知指数约 0.7，会系统性低估；
  3D 透视让前景柱看起来比等值的背景柱大
- **纵轴要有单位**。写"营收（万元）"不是光给数字
- **用直接标注，不用图例**。投影距离下图例基本读不到，而且迫使观众在图与图例之间来回
- **颜色不能是唯一的区分手段**，要配文字或形状（WCAG 1.4.1）。多系列时用 Okabe-Ito 色板，
  红绿色觉障碍影响约 8% 的男性
- **时间区间被截取过就写清楚**。写"2025 年 1 至 6 月"，不要写"2025 年"

### 禁止项目符号

顺序性内容拆成多张片，并列性内容改成图形或 bento 格。项目符号在这套风格里被明确称作"瘟疫"（A 档）。
模板里没有 `<ul>`，**不要加回来**。

## 阶段三（可选）：导出

- **PDF**：`scripts/export_pdf.sh deck.html` 走本机 Chrome 的 headless 打印，零依赖
- **可编辑的 .pptx**：把大纲的逐片清单转成一份片单 JSON（格式见脚本头部的说明），
  再跑 `scripts/outline_to_pptx.py deck.json`。
  **要如实告诉使用者这条路会丢什么**：python-pptx 完全不支持动画与转场（A 档），
  底色只能是纯色，做不到 HTML 那个层次。它的价值是可以在 Keynote 或 PowerPoint 里继续改

  脚本认十一种片型，HTML 里多出来的按这张表降级，**不要指望脚本自己猜**：

  | HTML 片型 | pptx 片型 | 降级掉什么 |
  |---|---|---|
  | bento 网格 / 规格密排 | `specs` | 大小分层没了，变成等宽三列 |
  | 产品主图 | `feature` | 占位图没了，只剩标题 |
  | 双栏人物 | `specs` | 两栏变成标签值对 |
  | 图表 / logo 墙 | 不做 | 这两类在 pptx 里手工摆更快 |
  | 全黑过场 | `section`，标题留空 | — |
- **.key**：做不到。格式私有，没有任何库能写入；AppleScript 只能控制 Keynote 不能建片（A 档）。
  唯一通路是生成 pptx 再由 Keynote 导入。**不要承诺能直接产出 .key**

## 事实校验 / Fact checking

这一节优先于所有视觉要求。这套风格把数字放到 320px，错一个数字的代价被放大了同样的倍数。

下面几条的依据是美国商业广告的举证与披露标准（FTC、AAPOR，见 references 第 7 节）。
**使用者多数在做答辩与项目演示而不是广告**，所以这里按"什么样的数字算诚实"来用，
不是法律建议；但判断一个数字放上去会不会误导人，这套标准比凭感觉好用。

1. **每个数字都要能指回材料**。指不回去的标 **【未确认】** 或者不放
2. **不做换算、不做推算、不做四舍五入**。材料写 4K120 就写 4K120
3. **限定条件跟着数字走**。"最长 22 小时视频播放"里的"视频播放"不能丢，丢了就是夸大
4. **对比性说法要有对比对象、版本和测试时间**。"快 3 倍"要写清比什么、哪个版本、什么时候测的。
   拿过时的对照物比也不合格
5. **"最高可达"要能代表典型情况**。写"最高可达 X"时，要能说明**典型使用下就能达到**，
   而不是个别最优案例；依赖特定配置的，条件写在数字旁边，不写在脚注里
6. **调研数字要给方法，不只给样本量**。样本量、抽样方式、误差范围，缺一样就在片上标出来。
   "87% 的用户满意"没有 n 值和口径，是不专业而不是有力
7. **未确认项在片上要可见**，用小字标注，不要只写在大纲里自己知道
8. 材料互相矛盾时两个数都列进大纲让使用者定
9. **从现有材料重构时，把散在别处的注脚拉回数字身边**。源文件里样本量、测试条件、统计口径
   常常和数字不在同一页——原文件那样排问题不大，因为字都一样小；但这套风格要把数字放到 320px，
   注脚留在三页之前就等于没有。**放大了多少倍，注脚就要跟得多紧。**
   一张片上出现"满意度 4.2 分"，"样本 30 份"就必须在同一张片上。

   这条第一版是我从实操里总结的，后来发现它对应 FTC 的"接近性"要求：限定条件必须清晰醒目
   且紧邻主张，**光打一个星号指向别处的脚注不满足标准**。苹果自己也不在数字旁打星号，
   用的是页首统概免责加分区详列测试条件（A 档）

## 反"发布会腔" / Against the register

这套视觉语言天生鼓励空洞的最高级。Jobs 用"革命性"的时候，下面垫着多点触控、一千首歌、从信封里抽出来的厚度。
**词是垫出来的，不是贴上去的。**

- 形容词要么有一个能指回材料的数字或事实垫着，要么删掉
- 少用这几个词，用之前先问自己垫着什么：革命性、颠覆、重新定义、魔法般、无与伦比、极致、这改变了一切
- 类比要落到熟悉的实物上（"一千首歌装进口袋"），不要落到另一个抽象词上（"体验的重塑"）

## 边界 / Boundaries

- **不使用任何厂商的资产**：商标、logo、产品渲染图、官方摄影、活动视觉、专有字体一律不用。
  借鉴的是信息层级、字号关系和叙事结构这些通用做法，不是任何一家的素材
- **不做 Liquid Glass**。那是 WWDC 2025 发布的系统 UI 专有材质，而且**根本不出现在
  发布会的片子里**，只在软件演示录像中。使用者要求"再像一点"时，往这个方向加是错的，
  它上线后本身就因为可读性被批评（A/B 档）
- **不加产品倒影和厚投影**。拟物化在 iOS 7（2013）就被整体废除，至今十三年，
  现在再用一眼就是旧年份的味道（A 档）
- **不为了像 AI 产品而加流光描边**。那类效果的具体参数是厂商资产；更重要的是，
  这套风格里重点色要承担语义，装饰性动效与它冲突
- **不做到冒充的程度**。产出物不能让人误以为是某家公司的官方发布物料。
  使用者要求加某家的 logo 或做成看起来像官方发布会截图时，拒绝并说明可行的做法
- **不编造产品参数**，包括看起来很合理的补全
- **不替使用者写讲稿**。这个技能做片子；讲的人说什么由使用者定，大纲里那一栏是提示不是成稿
- **不贴项目符号，不塞长段落**
- **不引外部资源**
- **不在阶段一就生成 HTML**
- **不承诺做不到的产出**（.key、带转场的 pptx）

## 输出格式 / Output

阶段一：

```markdown
先按你的材料排了一版叙事拍点和逐片清单：

<deck-outline.md 全文>

**我拿不准的：**
- <标注>

确认之后我出 deck.html。
```

阶段二：

```markdown
片子已生成：<文件路径>

- 片数：<n> 张，按概念数算的
- 叙事：<各拍分别是第几到第几片>
- 未确认项：<在哪几片、怎么标的>
- 需要你替换的：<占位图位置>
- 翻页：方向键 / 空格 / 滚动
- 导 PDF：`scripts/export_pdf.sh <文件>`
```

## Token 控制 / Token discipline

- 长材料和长讲稿先摘要成大纲，不要把全文带进阶段二
- 阶段二只读大纲和模板，不重读原始材料
- 改某几片就改那几片对应的 `<section>`，不重生成整个文件
- `references/stage-style-research.md` 只在需要查依据时读，不默认加载

## 参考资料 / References

- `references/stage-style-research.md` —— 取证记录与 A/B/C 分档。要判断某条做法有没有依据时读它
